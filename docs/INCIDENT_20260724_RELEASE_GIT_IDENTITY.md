# 2026-07-24 不可变镜像 Git 身份兼容故障

## 结论

2026-07-24 首次以隔离镜像 C 运行真实日周期时，日增量和次日开盘对账均 PASS，但影子信号在完整
哨兵计算结束处失败。独立在同一镜像内复跑得到确定性根因：镜像按安全设计不含 `.git`，而
`shaiwei.sentinel` 仍调用 `git rev-parse HEAD`，命令退出 128，外层记录为 `ForwardQlibError`，
scheduler 进入 `degraded` 并完成飞书告警。

这不是行情、规则、内存或数据质量失败；它是从“开发工作树运行”迁移到“不可变发布镜像”时遗漏的
运行身份兼容项。重新挂载 `.git` 会重新引入开发耦合，因此被明确禁止。

## 影响与证据

- `20260724` daily PASS：5 个市场批次、15,613 行；连同 3 个 `stock_basic` 批次共 8 个新批次、
  21,148 行，逐文件行数与 SHA-256 一致，`.BJ=0`；
- `20260723 → 20260724` 次日开盘对账 PASS，30 个观察目标，0 交易腿，平均绝对开盘偏差
  1.8210%；
- 首次影子运行以 `ForwardQlibError` FAIL，没有生成哨兵报告、信号或模拟仓账户日；
- 同镜像独立复跑在 `git_head()` 抛出 `CalledProcessError`，命令为 `git rev-parse HEAD`、退出码 128；
- 容器未 OOM，根文件系统只读和挂载白名单均保持有效。

失败尝试、告警和恢复记录均保留；没有删除账本、覆盖产物或人工修数。

## 最小修复

修复提交 `2ea5343`：

1. 构建时将干净工作树提交号写入 OCI `org.opencontainers.image.revision`；
2. 同一值通过 `SHAIWEI_RELEASE_GIT_HEAD` 固化进镜像环境；
3. `git_head()` 在发布镜像中读取并校验 40/64 位十六进制提交号，开发环境继续使用真实 Git；
4. 发布工具从一次性只读容器和最终运行容器同时复核代码快照与提交身份；
5. 不复制、不挂载 `.git`，不放宽任何代码、数据或模拟仓门禁。

回归测试提交 `ecda815` 增加镜像标签与运行时双身份不一致时 fail closed。全仓 196 项测试 PASS。
