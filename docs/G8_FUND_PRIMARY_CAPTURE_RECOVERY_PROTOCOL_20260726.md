# G8-1R 监管主源采集恢复协议（2026-07-26）

> 协议：`g8-fund-primary-capture-recovery-v1`
>
> 状态：`RESULT_BEFORE_EXECUTION_FROZEN`
>
> 只改变量：执行环境

## 1. 为什么不能继续原执行

G8-1 首个净值逻辑请求的两次官方响应均为空体 `502`，采集器按冻结协议写入一条
`QUARANTINED_HTTP_STATUS` 后立即停止，没有请求其余 53 个逻辑请求。同一镜像分别用 Docker
默认网络和 host 网络只读探测官方首页，仍均为空体 `502`；宿主直连在 G8-0 已取得 `200`。
因此当前阻断是 Docker Desktop 出口而非已冻结的请求字段或选行规则。

同时，首次构建命令由操作层手工传入了错误的完整 Git SHA：镜像声称
`1a974d2c6ea63c61d73d581f6036644163929c52`，但仓库真实提交为
`1a974d24726bc452a111e8dea0df57b350a16e29`。两者短前缀相同不代表身份相同。尽管镜像内容快照
`b91148c4...9f4d` 已通过自验，该运行仍不能被升级为有效采集。

## 2. 原失败证据不可改写

- 失败 evidence ID：`d169e0b5...ce46f`；
- 证据包 SHA-256：`736637e2...67bf7`；
- 账本追加后 SHA-256：`15934f08...3f64`；
- 两次状态：`502/502`，两个原文哈希均为空字节 SHA-256；
- G8 状态仍为 `NOT_READY`，生产授权仍为 `none`。

不删除失败证据包，不修改旧账本行，不把恢复结果回写成原执行 PASS。恢复使用新协议 ID、新请求
身份和同一追加账本，验收只计新协议的 54 条，同时强制核验旧失败行仍存在。

## 3. 恢复时只改一个变量

净值/分红路径、参数顺序、六只产品、日期窗口、双取、限速、选行、证据包、账本和全部失败门
与 `g8-fund-primary-capture-v1` 逐项相同。唯一改动是：

- 从无 `.env` 的一次性 Docker 容器出网，改为宿主项目 `.venv` 的一次性 `env -i` 进程；
- 进程环境只保留 `HOME/PATH`，不读 `.env`，HTTP 客户端仍 `trust_env=False`、零自动重试；
- 仍只写项目 `data/g8/fund_evidence` 和 `ledger/g8_fund_evidence.csv`；
- 两遍宿主双取完成后，使用同一真实 Git 提交构建的 Docker 镜像断网独立重算账本、证据包和
  验收计数。

这是一次性无密钥数据采集恢复，不是裸机常驻服务；未改变用户已冻结的“服务部署使用 Docker”原则。

## 4. 身份与验收

恢复实现必须先提交并推送；执行时的完整 Git SHA 只能由 `git rev-parse HEAD` 实时读取，禁止再手工
补全短 SHA。两遍采集的证据包必须只含一个代码快照和一个真实 Git SHA。

新协议必须独立得到 6 条净值区间证据、48 条分红备注证据、48 条唯一 A 类记录；首遍追加 54、
次遍追加 0，再由断网 Docker 验证通过。网络/结构/双取/修订/哈希任一异常均存证停止。

全部通过也只能进入 `GO_G8_2_CROSSCHECK_AND_FEE_LINEAGE_ONLY`；官方主源仍是 HTTP，所以状态上限仍是
`PRIMARY_CAPTURED_UNAUTHENTICATED`，不得计算 G8。
