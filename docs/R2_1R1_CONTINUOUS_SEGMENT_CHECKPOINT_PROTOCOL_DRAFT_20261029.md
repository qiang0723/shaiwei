## 3. 拟冻结规则（与 v1 相同的部分只列要点）

1. **live-dual 日**：沿用 v1 九条日谓词。
   - 两账户 PASS、FORWARD、operator `docker-scheduler`；
   - `started_at` 的上海日期等于执行日；
   - 策略 SHA 等于冻结身份；
   - 信号/执行日/signal/对账/数据快照/代码快照两账户一致；
   - 每账户每日恰一行；
   - 重放、会计恒等、新鲜度、`.BJ`=0。
2. **区段**：截至评估日的最大连续 SSE 开市日序列，每日均为 live-dual；任何开市日不满足即为缺口并重置（另按 D1）。旧缺口与重置次数全部披露，不删除、不改名。
3. **自然调仓**：区段内 `rebalance_due=true` 且两账户当日完整 PASS；订单数为 0 也如实报告。
4. **锚点**：两账户在区段首日前最后一个共同 PASS 状态；其证据层（live-dual 或受控追赶）常驻披露，不计入观察。
5. **门**：区段 ≥20 个 live-dual 日，且区段内 ≥2 次自然调仓。
6. **终态**：

   | 终态 | 含义 |
   |---|---|
   | `NOT_DUE` | 当前区段未达门 |
   | `BLOCKED_EVIDENCE` | 合同性失败，例如身份不一致、日历未覆盖评估日、重放失败 |
   | `OBSERVED_WITH_EXECUTION_WARN` | 达门，但有不改变核心状态的执行/通知警告 |
   | `CHECKPOINT_OBSERVED` | 达门 |

   缺口本身不再是 `BLOCKED`，只重置。
7. **描述输出**：同 v1 §6 的固定指标与配对差。
8. **禁止输出**：同 v1：胜负、有效性、生产切换、年化、Sharpe、IR、p 值；合并受控追赶与主序列；静默丢日；改模型/TopK/调仓/成本/资金。
9. **下游**：锁存的 `CHECKPOINT_OBSERVED` / `OBSERVED_WITH_EXECUTION_WARN` 满足 RF-1 / TP-F 正式批的 R2-1 门。用户须先看到描述报告；是否继续观察或另立单变量研究，由用户另行裁决。
10. **施工边界**：只读账本与不可变产物，不改 scheduler、账户、信号或 Web。冻结后另经工程、合成测试、单独授权才运行评估器。
