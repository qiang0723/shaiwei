# TS v3 策略整理、信号交付与 Web 反馈闭环方案

日期：2026-08-12（UTC+8）

状态：`DESIGN_GO_QUANTIFICATION_PENDING_NOT_EXECUTION_AUTHORIZED`

## 1. 结果目标

把“从热点板块选择热点股，再寻找右侧买卖点”的想法整理成一条可复现、可证伪、可在 Web 解释的
独立策略。最终每天只回答五件事：

1. 当前是否允许做多，哪些板块正在走强；
2. 哪些具体股票达到观察或交易条件；
3. 第一批何时、什么价格范围、买多少；
4. 第二批满足什么条件才能增加，止损、止盈和最晚退出在哪里；
5. 计划、实际订单、成交、持仓、退出和用户反馈分别有什么证据。

TS不替换中证800 Alpha158生产主策略，使用独立策略版本、数据身份、候选、账户、账本和效果结论。
任何历史或前瞻结果不理想，都不得影响主策略运行。

## 2. 唯一策略漏斗

```text
主要市场安全门
  → 唯一PIT板块映射
  → 热点板块强度门
  → 市值/流动性股票资格
  → 月线强势结构
  → 三周右侧结构
  → 波动与过热门
  → 日线回调后恢复
  → 第一批计划/成交
  → 盈利后第二批确认
  → 止损/止盈/时间退出
  → 独立复核与反馈
```

任何一层失败只记录原因并停止向下，不为凑足3只而放宽门槛。

## 3. 已确认的策略规则

### 3.1 市场、板块和股票方向

- 大盘、创业板、科创板等主要市场至少保持稳定且不继续创新低；
- 股票必须绑定一个当时可得的主要板块/行业基准，板块相对市场走强后才允许选择股票；
- 总市值不低于200亿元；上一完整交易周成交金额不低于50亿元；
- 单日成交额达到30亿元暂作放量加分，不作为首版硬门；
- 至少三根完整月K线支持最近连续两个月高点提高，并检查低点没有明显恶化；
- 最近三根完整周K线低点不下移，最新完整周不能以明显弱势收盘；
- 连续两周需要足够波动，但具体20%口径须由不读收益的数据画像后冻结。

### 3.2 入场和组合

- 日线只能在周线右侧结构成立后寻找“回调后重新转强”，精确触发和高开取消线待TS-1A量化；
- 第一批最多账户权益5%；第一批盈利且再次确认后，第二批最多5%；
- 第二批成交价不得低于第一批，禁止下跌补仓和第三批；
- 单票合计不超过10%，正常持有3—7只，硬上限7只，总名义仓位不超过70%；
- 每票两批合计计划风险不超过账户权益0.5%，组合计划风险不超过3%；风险门可使实际仓位低于5%/10%；
- 信号不足允许0—2只或完全空仓，不为提高资金利用率降低条件。

### 3.3 退出

- 初始结构止损暂定为买入时冻结的上一完整周低点下浮2%；
- 新一完整周形成后，结构止损只能上移，绝不能下移；
- 止损距离过远时缩小仓位，若最小一手仍越过单票风险门则不买；
- T+1、停牌、跌停、容量不足和跳空均按真实可成交价格处理，不把止损线伪造成成交价；
- 最长持有15个官方交易日暂时继承；精确盈利退出须在TS-1A后冻结唯一口径，不能同时回测固定百分比、
  ATR、风险倍数和跟踪止盈再择优。

## 4. TS-1A必须解决的七个口径

TS-1A只读取字段、身份、分布、覆盖和事件数量，不读取任何入场后的收益、MAE/MFE或策略效果：

| 待冻结项 | 必须形成的唯一答案 | 失败状态 |
|---|---|---|
| 市场安全门 | 使用哪些主要指数、何种完整周“不创新低”定义 | `BLOCKED_MARKET_RULE` |
| PIT板块映射 | 每只股票在每个历史日绑定哪个唯一行业/板块指数 | `BLOCKED_SECTOR_LINEAGE` |
| 热点板块 | 相对市场的趋势、相对强度、成交活跃度及排名规则 | `BLOCKED_SECTOR_RULE` |
| 两周波动 | 周振幅、真实波动或年化波动的唯一定义与上下限 | `BLOCKED_VOLATILITY_RULE` |
| 放量 | 日/周成交额相对自身历史的比较方式，30亿元如何只作加分 | `BLOCKED_VOLUME_RULE` |
| 日线买点 | 回调区、恢复确认、下一开盘合法区间和高开取消线 | `BLOCKED_ENTRY_RULE` |
| 盈利退出 | 单一止盈/跟踪规则、15日时间退出和优先顺序 | `BLOCKED_EXIT_RULE` |

同时逐层输出剩余板块数、股票数、事件数、候选日覆盖、最多连续空仓期和容量拒绝数。若漏斗过窄，
只能在读取效果前基于数据可用性裁决继续或停止，不能先看收益再放宽条件。

## 5. Alpha158与新因子

- 首版只把当时真正可得的严格OOS Alpha158分数用于合格候选排序，不让它决定市场、板块或买点；
- TS-1A核验事件日覆盖、分数成熟时间，以及原约10日标签作为最长15日TS排序器的适配声明；
- Alpha158足以启动，但不代表覆盖TS特有的月/周路径、回撤、恢复和板块状态；
- 核心v3先作为一个整体接受裁决。通过后，缩量和10日过热按一次一个机制优先做增量；每个机制最多
  三个低复杂度候选，须先通过语义、公式和暴露去重，再证明相对Alpha158有OOS扣成本增量；
- 核心失败时不得混入新因子救回同一v3身份，须另立版本并计入尝试预算。

## 6. 后台权威输出合同

Web不得扫描Parquet、拼账本或自行计算买卖点。后台必须先生成同一`strategy_version + as_of +
data_snapshot`下的原子TS快照。

### 6.1 候选层

每个具体股票至少包含：

- 候选ID、证券代码、PIT中文简称、信号日期和策略版本；
- 上市板块、唯一行业/热点板块及对应指数；
- 市场门、板块门、市值、周成交额、月线、三周低点、波动、放量和Alpha158排序状态；
- `INELIGIBLE / WATCHING / ENTRY_READY / BATCH_1_FILLED / ADD_READY / HOLDING / EXIT_PENDING /
  CLOSED / CANCELLED`之一；
- 所有未通过原因及源数据截至时间。

### 6.2 交易计划层

只有达到对应状态才允许显示数值，至少包括：

- 第一批触发条件、允许买入价格下限/上限、计划权重/股数、唯一有效执行日；
- 第二批确认条件、允许价格范围、剩余风险和最大增加权重；
- 冻结初始止损、当前只升不降的结构止损；
- 盈利退出价格或状态、最晚退出日期和退出优先级；
- `PLAN`、`ORDER`、`FILL`、`HOLDING`和`EXIT`严格分层，计划价格不得冒充成交价格。

### 6.3 证据层

- 成员/行业PIT、行情、复权、交易日历、规则、Alpha158分数、策略代码和快照哈希；
- T+1、涨跌停、停牌、容量、现金、风险与`.BJ=0`门；
- 生成时间、数据新鲜度、失效时间、取消原因和独立重放状态。

没有合格股票时，权威输出应为`NO_ELIGIBLE_CANDIDATE / HOLD_CASH`，不能返回备用推荐。

## 7. Web页面方案

Web增加独立的“TS波段策略”只读入口，不混入生产信号，不在前端计算任何业务规则。

### 7.1 默认页第一屏

1. 当前结论：可交易、仅观察、继续空仓、证据阻断四选一；
2. 市场/强板块：哪些指数稳定、哪些板块通过、数据截至何时；
3. 今日行动：准备买入、等待加仓、持有、准备退出的股票和数量；
4. 组合风险：实际持仓数、计划仓位、实际仓位、现金、计划风险和最大允许值。

### 7.2 具体股票表

主表直接展示：中文简称/代码、热点板块、当前状态、入选原因、第一批买点、第二批条件、当前止损、
盈利退出/最晚退出、计划仓位、下一动作和证据状态。默认按“需要行动→接近触发→继续观察→取消”排序，
不按预期收益或Alpha158分数制造排行榜。

### 7.3 单票详情

- 月K、周K、日K使用三个清晰时间层；周K/日K标出观察线、两批计划/实际成交、止损和退出点；
- “为什么选它”逐项展示市场、板块、流动性、月线、周线、波动、放量和排序证据；
- “为什么还不能买/为什么取消”同样完整展示，不隐藏坏消息；
- 技术哈希默认收进证据抽屉，主视图使用中文结论和具体日期/价格。

只有后台产生合法`ENTRY_READY/ADD_READY/EXIT_PENDING`计划时才展示具体计划买卖点。`WATCHING`只能
显示观察条件，数据不全显示`NOT_READY`，历史效果未通过不得把候选写成“推荐”或“确定性机会”。

## 8. 用户反馈闭环

每个候选/计划生成稳定`feedback_reference`。首版Web保持只读，提供“复制反馈模板”：

```text
反馈编号：
判断：同意观察 / 买点偏高 / 买点偏低 / 止损过宽 / 板块判断有误 / 继续等待 / 其他
理由：
希望补充的证据：
```

反馈进入追加式研究反馈记录，必须绑定当时策略版本、候选快照和时间，不能覆盖历史计划。反馈只能形成
`OBSERVE/PROPOSE`，由下一版协议复核后才可改变规则；不得直接改当天价格、重算旧信号或作为收益标签。

后续若在Web直接填写反馈，必须另立ADR：本机认证、CSRF/限流、追加式写入、审计、备份和只允许反馈
字段的窄接口。该写入服务与只读Web查询、生产scheduler和交易执行完全隔离。

## 9. 分阶段交付

| 阶段 | 产出 | 不允许 |
|---|---|---|
| TS-1A | 结果盲量化、数据门、漏斗与唯一口径建议 | 收益、训练、回测 |
| TS-1B | 完整无冲突v3协议、快照身份和尝试预算 | 效果读取 |
| TS-2 | 状态机、规则纯函数、原子快照和synthetic验收 | 真实效果 |
| TS-3 | 唯一历史效果、重放和独立审计 | 调参救回 |
| TS-4 | 核心通过后单机制新因子增量 | 多因子混入择优 |
| TS-5 | 独立50万元模拟账户与自然前瞻 | 覆盖生产主策略 |
| TS-6 | TS只读Web、具体计划点、证据和反馈模板 | 前端重算、页面交易 |

TS-6可提前完成视觉/查询合同草案，但只有TS-2产生稳定后台快照后才接真实数据；只有TS-3历史门通过
后才将候选升级为独立模拟计划。任何阶段无合格候选都允许空态，不以页面交付倒逼策略放宽。
