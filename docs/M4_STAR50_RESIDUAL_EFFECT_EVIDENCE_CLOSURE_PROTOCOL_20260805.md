# M4-1R2 科创50残差因子证据发布闭环协议（2026-08-05）

## 目标与非目标

本目标只把 M4-1R 已经生成且封存的效果报告与十个确定性产物补齐为可审计证据链，不重新进行任何
研究计算。M4-1R2 不是新的因子尝试，不增加多重检验次数，不改变候选、公式、方向、窗口、标签、
中性化、Alpha158 混合、组合、执行、成本、压力期或门槛。

机器真身为 `config/m4_star50_residual_effect_evidence_closure_v1.yaml`。协议在实现和再次调用入口前
提交推送；后续执行 release 还须再次绑定实现提交与代码束。

## 封存输入

- 效果报告固定为 `effect_report.json`，SHA-256 为 `627f304a...656b`；
- 首遍与确定性复跑各五个 Parquet，共十个，逐路径和 SHA-256 全部写入机器协议；
- 两遍同名文件物理哈希相等，但闭环仍必须重新核物理哈希与报告内 canonical 哈希；
- 运行账本与决策账本当前均为 0 数据行，运行 manifest 当前不存在；
- 报告的协议、恢复 release、实现、代码束、输入快照及隔离字段必须与机器协议逐项相等。

闭环独立审计通过前，不读取、不输出、不解释候选 RankIC、收益、回撤、持仓或报告裁决。

## 唯一实现变量

原 `append_once` 使用 CSV 的同目录 sibling `.lock`；Docker 虽只给两个 CSV 文件可写，但父目录只读，
因而无法创建锁文件。M4-1R2 固定改为直接对预创建的目标 CSV 文件本身加 `flock`，在同一文件句柄内
读取、比较、追加、flush 和 `fsync`。这维持并发互斥与追加式语义，同时无需放宽 `ledger/` 目录或
新增可写文件。

必须新增回归测试证明：

1. 首次追加、相同身份复用和冲突失败关闭均保持；
2. 不创建 sibling lock；
3. 闭环入口在报告缺失、报告哈希变化、任一 Parquet 变化、账本初态变化或 manifest 提前存在时失败；
4. 闭环调用只能进入 `effect_report.json` 已存在的复用分支；
5. 第二次相同调用不增加账本行、manifest 或产物，不改变任何封存哈希。

## 执行与裁决顺序

1. 实现、测试、提交并推送；
2. 冻结并推送新的闭环执行 release；
3. 构建独立断网、非 root、只读根镜像，结果根只允许 manifest 的既有窄写根，账本只允许两个 CSV；
4. 闭环入口先核 11 个封存文件与账本初态，再调用报告复用分支；
5. 独立审计重算十个 Parquet 的物理/canonical 哈希，核报告、manifest 和 1+3 条账本；
6. 审计通过后才读取和公布报告裁决；
7. 再次调用同一闭环入口，证明零新增、零改写。

如果闭环前任何封存哈希漂移，或者执行路径试图进入特征/标签/RankIC/组合计算，立即失败且不得清理、
重算或重建旧结果。

## 权威边界

即使闭环后科创50专属适配效果门通过，正式 G1-v1 仍因 2019—2024 窗口域不匹配保持
`NOT_RUN_UNIVERSE_WINDOW_DOMAIN_MISMATCH`，正式因子库插入始终为 0，生产授权始终为 `none`。
