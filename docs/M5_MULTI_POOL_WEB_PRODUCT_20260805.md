# M5 多股票池策略工厂 Web 产品方案

> 日期：2026-08-05（Asia/Shanghai）
>
> 文档性质：产品与信息展示专项提案，不是施工授权或后台协议
>
> 首版定位：源数据驱动的策略工厂工作台
>
> 当前真实边界：P3 Web 仍为本机、只读、`GET/HEAD-only`

## 1. 产品结论

多股票池研究应从一次次专项施工升级为平台固定能力，但 Web 的角色必须准确：它负责选择合法研究对象、
生成受控草案、呈现审批条件、跟踪任务与解释权威结果；真正的数据读取、协议冻结、研究计算、审计和证据
发布仍由后台受控流程完成。

首版产品不做“输入一句话立即回测”，而做以下闭环：

```text
权威股票池状态
  → 选择可研究的股票池和已批准模板
  → 形成不产生结果的 Web 草案
  → 后台预检并生成规范研究协议预览
  → 人工明确批准冻结和执行
  → 独立研究 Worker 串行执行
  → 不可变结果、账本和独立审计
  → Web 展示当前权威结论与完整失败历史
```

“股票池可用”“因子有效”“模型有效”“前瞻有效”“生产可用”是五个不同结论。页面不得用进度条、综合分
或绿色视觉把它们合并。

## 2. 设计依据与当前事实

### 2.1 继承的上位边界

- 继承 Web 1.0 的单用户、本机、证据优先定位以及 Web 1.1 的“结论 → 影响 → 原因 → 明细 → 证据”层级。
- 继承 M1-0 的股票池注册身份和跨池评价键：同一因子可跨池复用定义，但每个股票池独立评价、独立准入。
- 继承结果前冻结、追加式账本、不可变产物、失败关闭、`.BJ=0`、研究尝试数不重置和旧裁决不覆盖纪律。
- 继承现有 P3 查询隔离：浏览器不读 Parquet、账本、研究目录或任意 SQL，只消费限字段、哈希绑定投影。

### 2.2 当前必须如实显示的事实

- 中证800是唯一既有生产主策略；多股票池功能不改变生产地位。
- 科创50的官方 PIT 数据和工程路径可用，但 P2-2C 基线和 M4-1 固定残差候选均已权威拒绝；这不是股票池失败。
- 科创100、科创200的公开历史成员谱系仍有阻断；策略保持 `NOT_EVALUATED`，不得提供“开始挖掘”入口。
- 三类自建科创板规则池已有 PIT 数据与规则证据，但必须常驻 `CUSTOM_RULE_BASED`，不得冒充官方指数。
- 正式因子库当前仍为 0；拒绝、停止、失效和只有发现层的记录是平台资产，不得用空白或“敬请期待”替代。

### 2.3 一个需要后台先解决的来源冲突

`m1-multi-universe-foundation-v1` 是基础注册快照，随后 M2/M3/M4 又产生了新的数据门与研究裁决。Web
不能只读旧 YAML 后把科创200继续显示为“尚未做数据门”，也不能通过扫描验收文档自行推断最新状态。

建议新增一次性、write-once 的 `strategy_factory_snapshot`：以冻结注册表为身份底座，以追加式权威状态
overlay 更新当前数据门、规则门、研究阶段和裁决；每条 overlay 必须绑定协议、manifest、账本记录和
authority。文档只作说明链接，不能成为机器状态真身。

## 3. 信息架构

### 3.1 导航调整

桌面端在“研究证据”下新增一个一级入口“策略工厂”，其内部固定五个页面：

1. 研究地图；
2. 策略实验室；
3. 票池 × 因子；
4. 任务中心；
5. 准入与淘汰。

现有“因子工厂”和“模型/回测”保留为证据详情页，由上述页面下钻进入，不复制一套 tear sheet 或实验
适配器。若后续导航过长，可把原两个入口降为“策略工厂”的二级详情，不在首版同时保留三套研究首页。

推荐路由：

```text
/research-factory/map
/research-factory/lab
/research-factory/matrix
/research-factory/tasks
/research-factory/decisions
/factors/:factor_id?version=...        # 复用现有详情
/experiments/:kind/:experiment_id     # 复用现有详情
```

移动端底部“因子”升级为“研究”，默认进入研究地图；五个子页使用页面内紧凑标签/列表导航，不增加第五个
底部入口。390/320px 不使用横向滑动卡片轮播来隐藏状态。

### 3.2 页面间关系

```text
研究地图 ──选择合法股票池──→ 策略实验室 ──形成草案/待审批──→ 任务中心
    │                              │                         │
    ├──查看已有评价──────────────→ 票池 × 因子 ←─────────────┤
    │                                                        │
    └──查看当前/历史裁决─────────→ 准入与淘汰 ──下钻────────→ 因子/实验详情
```

## 4. 页面规格

## 4.1 股票池研究地图

### 默认回答

“哪些股票池当前具备合法研究条件，分别卡在哪里，今天最值得推进的是哪项工作？”

### 首屏层级

1. 决策句：`2 个官方池可研究，2 个官方池因历史谱系阻断，3 个规则池可研究（示例，实际由快照返回）`；
2. 需关注：数据门阻断、证据过期、运行失败或待人工审批；无异常时不显示空异常卡；
3. 研究覆盖事实：已登记股票池数、当前可发起数、阻断数、运行中任务数、正式准入数；
4. 票池明细；
5. 技术证据。

### 桌面主表

| 列 | 含义 |
|---|---|
| 股票池 | 中文名 + `OFFICIAL_INDEX` / `CUSTOM_RULE_BASED`，技术 ID 放详情 |
| 数据与 PIT | 当前权威数据门，不用旧注册基线替代最新 overlay |
| 可研究范围 | 仅数据、因子发现、历史验证、前瞻、既有生产等后台返回权限 |
| 当前研究结论 | `NOT_EVALUATED / DISCOVERY_ONLY / STOP / REJECT / ADMITTED`，与数据状态分列 |
| 正式因子 | 当前权威准入数；0 就显示 0 |
| 研究尝试 | 生成尝试 N 与跨池评价单元数分列，禁止相加成“模型数” |
| 当前工作 | 最近任务、阻断原因或下一合法动作 |
| 截止时点 | authority 生效时间、投影生成时间和新鲜度 |

默认排序固定为：需人工处理 → 数据/证据阻断 → 运行中 → 可发起 → 无动作；不得按收益、RankIC或“成功
率”排序。点击整行进入股票池详情抽屉；只有后台返回 `allowed_action=CREATE_RESEARCH_DRAFT` 时显示
“建立研究草案”。

### 股票池详情抽屉

- 身份：官方代码或自建规则身份、基准、PIT状态、有效区间、排除市场；
- 证据链：基础注册 → 数据/规则门 → 工程门 → 各研究家族 → 当前 authority；
- 当前可做/禁止事项；
- 历史因子和策略裁决摘要；
- 完整技术 ID、哈希和 source refs 只在二级“技术证据”展开。

### 空态和坏消息

- 没有可研究股票池：显示全部阻断原因和恢复条件，不提供绕过按钮；
- 数据可采但 PIT 不可构造：显示“源数据可用，历史研究不可用”，不能简写为“数据失败”；
- 股票池有多个 REJECT：显示“股票池数据可用，当前已评策略均未通过”，不能把池涂红或标“无效”；
- `.BJ` 非 0、身份冲突或 authority overlay 断链：整页 `FAIL`，不丢弃问题行后继续。

## 4.2 策略实验室

### 默认回答

“能否以当前证据合法地发起本项研究；如果能，研究对象、唯一变量、预算、门槛和停止条件是什么？”

### 它不是自由回测器

首版只允许从后台版本化模板创建草案，不开放任意 Python、SQL、文件路径、指标门槛、模型参数或生产
配置输入。LLM 研究只能选择已批准的候选生成模板；提示、知识摘要、响应数、费用上限和外发字段由后台
协议给出，页面不能用自由文本偷偷扩展载荷。

### 五步向导

1. **选择股票池**：只列 `CREATE_RESEARCH_DRAFT`；阻断池可查看原因但不能选择。
2. **选择研究机制**：量价、基本面、资金流、残差/特异风险或未来登记家族；必须显示已有相关尝试 N 和
   最近失败，避免“换名字重开”。
3. **选择验证模板**：标签、horizon、中性化、窗口、成本、容量、压力期、裁判版本全部来自只读模板；
   不支持页面改阈值。
4. **预算与外部能力**：候选数、评价单元数、最大运行资源、DeepSeek响应数/费用上限（如适用）分列；
   `provider_authorization=NOT_GRANTED` 时只能保存草案，不能提交执行。
5. **审阅**：显示唯一变化、全部冻结字段、禁止事项、数据快照、预计产物和规范哈希；用户确认的是这个
   具体版本，不是泛化的“同意运行”。

### 草案主指标

- 股票池/PIT readiness；
- 研究模板版本和唯一改变变量；
- 全球生成尝试增量与跨池评价单元增量；
- 数据读取范围与封存区；
- 预计资源/费用上限；
- 需要的人类批准项；
- 生产授权固定为 `none`。

### 两层提交语义

当前 P3 是 `GET/HEAD-only`，因此首版设计必须把按钮按交付阶段分开：

- **Web 草案能力**：创建、编辑、校验本地研究草案；不会读结果、不会冻结协议、不会排队或调用 API。
- **真正提交执行**：只有未来独立 `research-control` 服务、认证、追加审计、Worker隔离和审批门全部验收后
  才能开放；必须先“提交复核”，再由用户对规范哈希明确“批准冻结”，最后单独“批准执行”。

在控制面尚未施工时，策略实验室只能显示只读模板和本地未提交表单，所有“提交/执行”入口固定为
`NOT_AVAILABLE · 控制面未授权`。不得以调用现有 GET 接口或浏览器本地状态假装任务已创建。

## 4.3 票池 × 因子矩阵

### 默认回答

“同一精确定义的因子在哪些股票池被评价过，各自处于什么证据层和权威结论？”

### 视觉模型

- 行：全局稳定 `factor_id` 的人类名称/机制；
- 列：股票池；官方与自建池用表头文字和图标区分；
- 单元格：只显示证据层和当前裁决，不用 RankIC/收益热力色；
- 单元格状态候选：`未评价 / 数据阻断 / 发现层 / 审查停止 / 历史拒绝 / 已准入 / 已失效 / 前瞻观察`；
- 右侧固定“相关生成尝试 N”，不把多个池的评价单元当成独立生成次数。

单元格点击后打开比较抽屉，展示：

- 精确评价 fingerprint：股票池、基准、标签、horizon、中性化、窗口、成本、裁判版本；
- authority 与记录结论；
- 通过/失败门和证据等级；
- 若口径可比，链接现有 factor compare；不可比返回 `CONFLICT` 并说明差异，不由前端换算；
- 当前与历史版本，失效/被替代记录不删除。

### 筛选

只允许研究机制、因子生命周期、股票池类型、证据层和权威状态。禁止按收益、RankIC、回撤、失败门数量
或“覆盖股票池最多”排序，避免结果后挑选。

### 移动端

390/320px 不渲染超宽矩阵。先选因子，随后用紧凑纵向列表显示每个股票池的状态和下一动作；仍提供“查看
二维矩阵”局部横滚区，页面本身不横滚。移动列表与桌面矩阵必须来自同一响应，不创建简化口径。

## 4.4 研究任务中心

### 默认回答

“现在有哪些研究正在等待、运行、等待裁决或已经失败；需要我做什么？”

### 四轴状态

每个任务必须分列：

1. 业务生命周期：草案、待复核、已冻结、排队、运行、等待审计、终态；
2. 执行状态：未执行、运行中、PASS、FAIL、STOP、BLOCKED；
3. 证据状态：未形成、部分形成、已封存、审计PASS、证据失配；
4. 通知状态：未到期、PASS、WARN、FAIL。

恢复后的 PASS 不覆盖失败尝试；工程失败不自动产生策略 REJECT；研究 STOP 不等于候选经济失败；数据门
NO-GO 不得显示成策略失败。

### 目录字段

| 字段 | 展示要求 |
|---|---|
| 任务 | 人类编号 + 研究家族，机器 `task_id` 入技术详情 |
| 股票池 | 名称和身份类型 |
| 当前阶段 | 上述业务生命周期 |
| 当前结论 | 只显示后台 authority 允许的结论 |
| 进度事实 | 完成/计划响应、候选、评价单元或产物；不显示虚构百分比 |
| 资源 | 运行时长、Worker版本、预算使用；无可靠估计时不显示ETA |
| 需行动 | 复核、批准、补输入、查看失败或无动作 |
| 最近事件 | 失败/恢复链的最新一项及发生时间 |

详情页按“当前判断 → 唯一变量 → 阶段时间线 → 失败与恢复 → 产物/账本 → 技术证据”排序。运行日志不直接
输出；只展示结构化、脱敏事件。任务完成后链接现有因子或实验详情。

### 任务操作边界

- 不提供删除、覆盖旧任务、强制成功、跳过门禁、改结果或重跑同一任务按钮；
- 已冻结任务不可编辑；需要变化时派生新版本并保留父任务；
- 首版不提供“停止正在运行的容器”。未来若提供，只能追加 `STOP_REQUESTED`，由 Worker安全点处理并保留
  已形成证据；
- 幂等刷新不得重复提交、重复计 N 或重复产生外部费用。

## 4.5 准入与淘汰历史

### 默认回答

“哪些因子/策略当前具有权威资格，哪些被拒绝、停止、失效或替代，原因和证据是什么？”

### 首屏

- 正式因子库：当前真实数量（现为0）；
- 当前准入：按股票池分列，不能跨池合并；
- 当前权威 REJECT / STOP / INVALIDATED 数；
- 最近一次 authority 变化和原因；
- 没有准入时的空态：“暂无因子通过正式准入；已有失败研究可供复核”，并提供失败证据入口。

### 追加式时间线

一条记录最少显示：对象、股票池、研究家族、记录结论、authority、规则版本、失败门、研究尝试 N、
记录时间、替代/失效关系和证据状态。当前权威记录置顶，但历史记录不折叠为“已过期”而隐藏。

不展示“成功率”“平均收益”“Top 10因子”或星级。若未来存在 ADMITTED，也必须紧邻适用股票池、窗口、
成本、前瞻状态和生产授权，不能单独使用绿色“可用”标签。

## 5. 指标模型

## 5.1 Hero指标

| 页面 | Hero事实 | 解释 |
|---|---|---|
| 研究地图 | 可合法发起股票池 / 总登记股票池 | 分母明确；阻断仍保留在下方 |
| 策略实验室 | 草案预检状态 | 不是运行或策略结论 |
| 票池×因子 | 已评价单元 / 预登记单元 | 不等于生成尝试数或有效因子数 |
| 任务中心 | 需人工行动任务数 | 运行中、失败、待审批分列 |
| 准入历史 | 当前正式准入数 | 现为0；不以历史GO填充 |

## 5.2 诊断与护栏

- `registered_universe_count`：当前投影登记的股票池数；
- `research_eligible_universe_count`：后台明确允许建立研究草案的股票池数；
- `blocked_universe_count`：按数据/PIT、规则、证据、权限原因分组；
- `global_generation_attempt_n`：相关研究域全部生成尝试，失败/重复/语义拒绝均计入；
- `evaluation_unit_count`：候选 × 预登记股票池的评价单元；与生成尝试分列；
- `admitted_factor_count_by_universe`：按股票池独立当前准入数；
- `authoritative_reject_count`、`stop_count`、`invalidated_count`：按 authority 去重后的当前数量；
- `active_task_count`、`human_action_required_count`、`failed_task_count`；
- `snapshot_freshness_status`、`authority_overlay_status`、`bse_count`；
- 外部调用任务另显示 `authorized_response_count / completed_response_count / budget_cap / spent_estimate /
  billing_uncertain_count`，不得只显示“进度百分比”。

禁止新增单一“策略得分”“股票池得分”“研究效率分”或混合 PASS/REJECT/WARN 的总分。

```json
}
```

同一页面涉及多个响应时必须核对 `snapshot_id + universe_registry_sha256 + authority_overlay_sha256`；更优
方案是为研究地图提供原子响应，避免前端并发拼“最新”。

### 6.2 只读查询

| 端点提案 | 用途 | 核心字段 |
|---|---|---|
| `GET /api/v1/research-factory/overview` | 研究地图原子快照 | counters、attention_items、universes、allowed_actions |
| `GET /api/v1/research-factory/universes/{id}` | 股票池详情 | identity、PIT/规则/工程门、authority链、禁止项、source refs |
| `GET /api/v1/research-factory/templates` | 实验室模板 | template_id/version、eligible_universes、frozen fields、budget schema |
| `GET /api/v1/research-factory/matrix` | 跨池矩阵 | factor identities、universe columns、evaluation cells、fingerprints |
| `GET /api/v1/research-factory/tasks` | 任务目录 | 四轴状态、需行动、最近事件、有界分页 |
| `GET /api/v1/research-factory/tasks/{id}` | 任务详情 | protocol identity、阶段事件、attempt、artifact和authority refs |
| `GET /api/v1/research-factory/decisions` | 准入/淘汰历史 | current authority + append-only records、replacement links |

所有目录固定稳定排序和有界分页；允许按身份、状态和证据层筛选，不允许表现排序。股票池详情与任务详情
的机器 ID、完整哈希和 source refs 进入技术证据折叠区。

### 6.3 未来受控写契约

真正的写能力不能加入现有 `web-query`；必须是独立 `research-control` 服务并经新安全协议验收。建议
最小端点：

| 端点提案 | 边界 |
|---|---|
| `POST /api/v1/research-control/drafts` | 仅创建草案；强制 `Idempotency-Key`，不排队、不读结果 |
| `PATCH /api/v1/research-control/drafts/{id}` | 只允许 `DRAFT` 且使用 `If-Match`；字段严格白名单 |
| `POST /api/v1/research-control/drafts/{id}/validate` | 后台预检并返回错误，不改变研究状态 |
| `POST /api/v1/research-control/drafts/{id}/submit-review` | 追加 `REVIEW_PENDING`，生成规范预览和hash |
| `POST /api/v1/research-control/reviews/{id}/approve-freeze` | 用户再次认证并确认精确hash；冻结后不可改 |
| `POST /api/v1/research-control/tasks/{id}/approve-dispatch` | 与冻结分开批准；外部API/费用授权仍需显式存在 |

不得提供 `DELETE`、任意重跑、通用执行、任意路径/SQL/代码、修改门槛、生产发布或券商相关端点。

## 7. Web草案、提交和执行的安全边界

### 7.1 当前首版可立即交付的部分

- 五页只读工作台；
- 研究模板与合法动作只读预览；
- 浏览器内临时草案，刷新即丢失或明确标“未保存”；
- 查看当前任务与证据；
- 不改变 P3 的 `GET/HEAD-only` 事实。

### 7.2 控制面开放的前置条件

1. 独立 `research-control`，不继承 `web-query` 的服务身份；
2. 本机认证、同源、CSRF、Origin检查、短期会话和高风险动作再次认证；
3. 追加式 draft/review/approval/task 审计，所有请求幂等并绑定用户、规范hash和代码快照；
4. 不加载生产 `.env`，不返回secret存在值之外的任何凭据内容；
5. Web与控制服务均无Docker socket；只能向严格类型化队列提交允许的任务类型；
6. Worker使用不可变镜像、非root、只读根、最小输入/输出挂载、资源/费用上限和网络策略；
7. 外部API请求另有冻结payload bundle与专项授权，不能由普通“执行”批准推导；
8. 控制任务与生产scheduler隔离，生产授权永远为独立状态；
9. 失败恢复、重复请求和计费不确定性对抗测试通过；
10. 先以synthetic fixture验证全链，再允许真实数据任务。

控制面未满足其中任一项时，页面不得显示可用的提交/执行按钮。

### 7.3 数据外发与LLM

- 任何 LLM 任务必须在审阅页明确展示：模型、响应数、最坏费用、发送字段类别、禁止字段和授权是否到期；
- 不发送行情原始数据、证券清单、封存结果、持仓或其他凭据；
- 用户自由文本不自动拼进提示；如未来允许，必须先脱敏、限长、结构化并在冻结payload中逐字可见；
- `BILLING_UNCERTAIN` 时不重发，页面显示人工处理，不提供“再试一次”。

## 8. 空态、错误态与坏消息规则

| 场景 | 页面文案/行为 |
|---|---|
| 正式库 0 | “暂无正式准入因子；已有拒绝与停止证据可复核” |
| 股票池数据门阻断 | 显示源可采/PIT不可构造等精确分层；禁用研究草案 |
| 尚未评价 | `NOT_EVALUATED`，不显示0收益或灰色失败 |
| 审查合同 STOP | “审查合同违约，未形成候选裁决”，不显示候选REJECT |
| 工程失败 | 显示工程尝试及是否产生结果；未产生结果不得升级为经济裁决 |
| 方法失效 | `INVALIDATED_METHOD`常驻并链接纠错/替代记录 |
| 结果 REJECT | 显示适用股票池、候选、失败门、authority和停止边界 |
| 快照冲突/哈希断链 | 整页阻断，不显示旧数据冒充当前 |
| 查询过期 | 保留原生成时点并标STALE；不静默回退最新/历史 |
| 未授权写控制面 | 显示“仅可预览草案，暂不能提交执行” |

任何页面都不允许通过默认筛选隐藏全部 REJECT/STOP/INVALIDATED；坏消息必须在首屏统计或“需关注”区域
可见。

## 9. 响应式与无障碍

- 强制视口：1440、1024、768、390、320 CSS px；320用于400% reflow。
- 研究地图桌面使用紧凑表，移动使用每池不超过三行的目录项：名称/身份、数据状态、当前结论/下一动作。
- 实验室移动端每一步一屏内完成主判断；底部按钮不能遮挡错误和费用上限。
- 矩阵移动端默认“一个因子 × 多股票池”列表；二维视图只在局部可聚焦横滚容器内。
- 任务中心移动端显示人类任务编号、阶段、结论、需行动；机器ID和资源细节进入抽屉。
- 准入历史移动端保持紧凑时间线，不把每条变成高卡片；历史记录可折叠分组，但当前负面authority不可折叠。
- 状态始终有文字与图标；表格/矩阵有等价列表；焦点顺序与阅读顺序一致；抽屉Esc关闭并归还焦点。
- 阻断错误用`role=alert`，运行进度只在实质阶段变化时用`role=status`，不播报轮询心跳。

## 10. 首版验收标准

### 10.1 数据与口径

- 研究地图从统一投影显示全部登记池；M1基础注册与后续M2/M3/M4 authority overlay可对账。
- 科创50显示“数据/工程可用 + 当前策略研究REJECT”，不能显示成股票池失败。
- 科创100/200显示精确数据门阻断，研究草案动作不可用；三规则池显示 `CUSTOM_RULE_BASED`。
- 正式因子库0、各类REJECT/STOP/INVALIDATED均与现有权威记录一致。
- 生成尝试N与跨池评价单元数分列；任何目录都不把记录数称为有效策略/模型数。
- `.BJ`、未知enum、authority断链或fingerprint冲突全部fail closed。

### 10.2 页面与交互

- 五页在无筛选条件下5秒可指出当前结论、需行动事项和数据时点，15秒可进入原因与证据。
- 地图 → 草案、任务 → 结果、矩阵 → 因子详情、历史 → 实验详情四条路线可键盘完成并保持同一`as_of`。
- 默认排序不依赖收益/RankIC/回撤；不出现综合分、排行榜、一键最佳或自由调参。
- 空态解释原因、含义和下一合法动作；坏消息无需特殊筛选即可发现。
- 1440/1024/768/390/320无页面级横向溢出；矩阵与宽表只在容器内横滚；axe serious/critical为0。

### 10.3 查询与隔离

- 正式页面只消费类型化HTTP契约和write-once投影，不扫描Parquet、账本、文档或研究目录。
- 同页响应共享完整快照身份；SNAPSHOT_CHANGED/EVIDENCE_MISMATCH不降级展示。
- Web容器仍为本机、非root、只读根、无`.env`、无Docker socket；scheduler身份、镜像和运行周期不变。
- 日志、绝对路径、secret、Webhook、token、原始LLM载荷和敏感证券明细不进入页面。

### 10.4 草案与执行

- 只读阶段只能预览模板和浏览器临时草案，网络记录证明无POST/PUT/PATCH/DELETE。
- 控制面阶段必须证明“草案 → 复核 → 批准冻结 → 独立批准执行”四步分离，冻结后不可编辑。
- 同一幂等键重复提交不新增任务、不重复计N、不产生二次外部调用或费用。
- 未授权股票池、未冻结协议、无外部API批准、超费用、证据不完整或生产权限请求全部在排队前拒绝。
- Worker的结果、账本、manifest和独立审计可重放；页面只在审计通过后提升authority。

## 11. 建议施工顺序

1. **M5-W0 状态投影**：冻结 `strategy_factory_snapshot` 来源、authority overlay和七类状态轴；只读双跑同hash。
2. **M5-W1 只读后端**：实现地图、股票池详情、矩阵、任务和决策查询；暂不提供控制端点。
3. **M5-W2 五页前端**：完成信息层级、空态、坏消息、移动端和浏览器验收；P3继续GET/HEAD-only。
4. **M5-C0 控制面协议**：独立评审认证、审计、幂等、审批、队列、Worker、费用与外发边界。
5. **M5-C1 草案能力**：先开真实持久化草案和校验，不开放执行。
6. **M5-C2 冻结与执行**：只对一个synthetic任务模板打通；通过后再逐个开放真实研究模板。
7. **M5-C3 真实首批**：选择一个PIT READY且具有独立经济机制的股票池/因子家族，另立结果前协议，不以
   平台功能上线替代研究裁决。

这样可以尽快把现有多股票池证据变成可读、可追踪的日常工作台，同时把“页面可用”和“研究可执行”放在
两个独立安全门之后，避免为了自动化而削弱筛微最有价值的审计纪律。
