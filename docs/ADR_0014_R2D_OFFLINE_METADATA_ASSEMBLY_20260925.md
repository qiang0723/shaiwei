# ADR 0014：R3N 白名单元数据与日期权威离线装配

日期：2026-09-25。状态：OFFLINE_ONLY / NOT_FOR_PRODUCTION。

## 目标、事实与范围

用户在 R3N 九文件 d426238d7994bc1298544328264280e872624f6d 已推送并同步后要求继续。
本步把 R3N 手填日期/计数的测试端口推进为固定文件白名单投影，复用 daily.build_plan，
并提供同时装配现有阶段库、元数据和合成业务端口的离线调用入口。
只读工程源码；新合成快照与数据库只在项目 .test-tmp 专用目录内读写。
不读真实 data/ledger/logs/.release、.env 或环境变量，不联网、Docker、构建或生产操作。
R3L/R3M/R3N核心、现有 scheduler/CLI、配置和生产存储均不修改。

源码核验发现 release_metadata.load_plan 虽接收 project_root，底层 catalog 最终调用
ledger.resolve_artifact_path，不能仅传一个夹具根就声称整个读取链被重新定位。
因此本步不调用该加载器，也不扫描或解析真实账本/行情；这不是线上漏洞复核结论。

## 选择与代价

1. 继续手填 FirstDayObservation：拒绝，无法证明日期与尝试数来自独立输入。
2. 单个严格版本化合成快照 + 内存文件适配 + 既有 build_plan：选择。固定文件名，
   单次读取字节后校验全部字段；无任意路径、无分文件时间竞态、无新增日期算法。
3. 立即改生产入口并连接真实 ledger/config：不在本步范围，依赖生产后端与全writer证明。

新增的仅是外层离线资源适配与装配，不把文件/配置读取引入纯领域核心。
build_plan 的惰性导入会带入原 daily 的依赖，但不调用 config.load、run_once、市场探测、
通知或 client 工厂。测试显式阻断这些能力并使用原生产文件读写/网络保护器。

## 输入、输出与失败关闭

元数据规格 r2d-fixture-metadata-spec-v1 绑定 CandidatePlan SHA 和显式规划参数。
快照 r2d-fixture-metadata-v1、模式 OFFLINE_FIXTURE_ONLY，绑定规格 SHA，包含：
采集时间、运行身份/隔离合成证明、五份严格CSV白名单、独立阶段回执与最终验收布尔。
CSV仅含日历日期/开市位、bootstrap API/参数、daily日期/状态、shadow日期/状态/代码身份、
paper日期/状态/代码身份/账户；额外字段、重复列、缺列、坏日期、错误身份都拒绝。
日历原始CSV字节SHA须与计划绑定一致；日历连续覆盖bootstrap到首日，不以自然日+1推算。
既有 build_plan 是 eligible/pending/watermark 唯一权威；向它传入已校验、只读的内存文件，
不让它打开磁盘默认路径。规划时刻必须aware，ready时分须等于计划首日派发时分。
尝试数按目标日所有行计数，不过滤失败后假装未尝试；失败/重复账户/异身份明确阻断。
claim只取阶段库claimed，不从其END制造独立回执；完整验收必须有独立快照证明。

快照只能从项目 .test-tmp 下专用目录的 r3n-metadata.json 读取，拒绝路径穿越、软/硬链接；
读取前后核对文件身份/大小/修改时间，并限制字节数。异常只返回稳定错误码，不泄漏原文。
这不是针对恶意管理员或并发目录替换的OS安全证明，也不是快照签名/真实性认证。
离线装配入口先拒绝独立/未知路由，再打开已有阶段库与快照；不隐式创建或修复数据库。
停放不claim、不构造业务端口。业务仍只由R3N BEGIN持久化后的注入工厂调用。

## 验收、迁移与退出

用真实测试目录文件/SQLite和合成业务证明停放、首日全阶段、等待续接、关闭后不重跑；
覆盖白名单/哈希/日期/时间/身份/次数/独立证据不符和路径逃逸，异常原文不得外泄。
运行受保护R2D回归、架构、Ruff、diff与静态脱敏；全仓真实业务/密钥检查不执行、不标PASS。
本轮受限验证交付需独立确认，不沿用上一提交的豁免；精确推送另批。

无生产迁移或回滚动作。新模块可不被调用，旧入口保持原样；失败夹具与账本增量保留。
后继还须真实候选入口接线、生产持久化后端、独立元数据采集/验证、全writer隔离、Docker
fixture、新镜像及发布谱系CAS；这些未证明前不得start。R2D仍开放，不提前进入G1。

## 实施后的边界事件

前述禁止真实账本读取是本步预定边界，不代表实施全程无偏离。收尾曾执行未限定路径的
git diff --check，Git也检查了账本改动并输出CRLF提示；未输出账本内容/效果、未写或暂存
账本。发现后暂停并告知用户，用户仅确认继续工程复核和记录，提交/推送仍另批。
之后检查严格使用工程文件白名单，不读取账本内容补证；详见本步交付协议的事件记录。
