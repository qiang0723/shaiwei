# ADR 0011：R2D 收尾后宽窗口合同（2026-09-18）

状态：CONTRACT_ENGINEERING_ONLY；真实适配、候选构建、fixture和生产均未授权。

## 问题、事实和结果目标

用户时间不固定，要求从单次定时/短窗口改为可提前安排的宽时间范围。R3K已按独立授权推送，
HEAD与本地origin/main均ca550e9c0e43afd99140c31aac9828588ac7f069；其9月18日19:00窗口已过期。
本轮仅读取工程源码，不重新读取生产证据。最近真实观察仍是9月17日，不能声称今晚系统空闲。

源码事实：r2d_authorized_start绑定同一target_trade_date的时间窗、prior-day noop及目标日零尝试；
daily_early_release_guard要求唯一新数据日期；release.release_start_readiness拒绝没有更新交易日的
跨代码启动。pipeline.scheduler对daily NOOP仍运行shadow、paper、verify和acceptance。
因此不能通过延长19:00截止或把最新PASS视为空闲证明，安全实现收尾后跨版本启动。
health=noop只是一次观察，不阻止下一轮或其他入口写入。旧生产的锁权威不是已验证named-volume后端；
宿主轮询两次不变、Docker healthy、restart=0或账本计数均不能证明无在途写入。

结果目标：先冻结独立post-close合同和纯输入合成测试，使准备工作不再随每天日期复制整套代码；
未来用户可提前批准一个明确起止的宽窗口，在窗口内由代理执行检查和一次动作，不要求卡点回复。
本阶段不承诺无人值守上线，也不把只读/工程批准解释为未来生产批准。

## 三个方案与选择

1. 仅改旧窗终点：拒绝；旧日期、零尝试与跨版本readiness仍不成立。
2. 直接绕过readiness并启动现有候选：拒绝；没有防旧日重跑或排空证明。
3. 新增POST_CLOSE_PARKED合同：采用，仅完成纯合同。关闭日、操作窗口、候选首日分离；
   候选在首个合法新交易日到达前必须保持业务停放态，不重跑已完成日。

新窗口使用带时区的绝对起止时间，左闭右开，一次最长24小时，可跨午夜；
不能跨过绑定的下一交易日首次可能派发时刻。该时刻必须来自冻结调度/日历语义，不硬编码猜测。
周末/节假日按已核验日历的下一交易日绑定，不假设自然日+1，不滚动续期，不循环消耗scope。
24小时是本新合同显式上限，不改变旧R3K窗口或心跳3600秒上限。部署前须经独立审批接受新合同。

## 权威与模块边界

新增r2d_post_close_contract仅使用内存类型化输入，不读文件、时钟、环境或Docker，不导入生产编排。
合同区分release/Git/容器/日历/控制器身份绑定、双账户最新FORWARD锚、闭环元数据和窗口。
调用者未来必须先验证证据字节/哈希链/来源，不能把自填PASS、任意64位哈希当作真实证明。
评估仅返回CONTRACT_VALID_NOT_FOR_EXECUTION，production_authorized恒false，无CLI/start适配器。
现有13组件、候选、R3K及更早scope/receipt和所有策略门保持字节不变；不改变账本Schema。

未来真实适配至少需要：

- daily/shadow与双账户完整闭环，独立重放和通知验收元数据，不能只以纸面计数1/1/2代替；
- 全部旧写入入口的可靠fence与排空，生命周期覆盖最终变更，不能把快照观察冒充锁；
- 与候选准确身份绑定的“已完成日不重跑/下一合法日才解锁”fixture；
- 重新定义parked readiness，禁止把它伪装成旧CROSS_SNAPSHOT_WITH_NEW_DATA；
- 下一首日无任何尝试、无积压日期，所有身份一致、心跳及观察非未来且新鲜；
- 完整复用精确scope批准、单次claim、派发前复验、MAY_HAVE_WRITTEN及派发后禁止自动回滚。

现有候选无上述已证明能力，因此本新合同不直接接入release.start_current，不能获得START_READY。
若必须加入scheduler启动下界/握手，需新不可变候选、新release身份及独立fixture授权；
不能修改旧候选字节、重用旧fixture或擅自重复已完成Phase A。现有current/previous不在本轮改动范围。
后继设计必须先决定新候选/发布谱系如何迁移，再申请任何真实动作。

## 迁移、回滚与权限

新合同与旧r2d-execution-scope-v1分离，不把新字段塞进旧scope，不改写旧批准文本。
未来真实适配须版本化，并绑定新控制器、候选能力证明和最终元数据；旧scope不可用于新路径。
本轮无常驻任务、Docker、外网、密钥、真实效果、生产读取或写入。仅项目内工程文件和隔离测试。
撤销本轮只停用未接线合同，不涉及生产回滚；实际派发后未知状态必须人工处置，不自动旧版恢复。

## 验收、风险和退出条件

以纯合成输入验证跨午夜/周末窗口、精确端点、24小时上限、日历首日、派发截止、新鲜度、
完成日与首日分离、账户重复/缺失/错哈希/BACKFILL/错误代码、缺失证明、写入未排空、首日已有尝试、
身份漂移和额外字段。另回归原R2D与原跨版本readiness拒绝行为，证明没有暗中放宽旧门。
架构、Ruff、格式/静态脱敏检查；不读取真实业务/密钥做全仓检查，不宣称全仓通过。
纯合同PASS不代表排空、停放、真实部署、首日验收或策略有效性PASS。
唯一后继为post-close停放/排空适配工程方案，不回到每日复制协议追窗口，不提前开G1。
