# 筛微代码与架构宪法

- 版本：`architecture-constitution-v1`
- 生效日期：2026-08-05
- 状态：`ACTIVE`
- 机器规则：`config/architecture_constitution_v1.yaml`

## 1. 目的与适用范围

本宪法约束筛微仓库内的生产、研究、数据、模拟组合和 Web 施工。目标不是追求新技术、更多模块或
更漂亮的抽象，而是持续拿到可信结果，同时让系统在股票池、因子家族、模型和交付方式扩展后仍可
验证、可维护、可回滚。

安全、数据不可变、结果前冻结和既有研究门禁的具体规则优先于本宪法；本宪法负责约束实现结构，
不能被用来放宽任何冻结协议。任务文档与实现若冲突，先停止施工并形成显式裁决，不静默选边。

## 2. 不可协商原则

1. **结果优先，证据裁决。** “先进”只在提高正确性、研究吞吐、可解释性或恢复能力时有价值。
2. **一份事实，一个权威计算。** 领域指标只在后台权威实现中计算；查询层只读投影，前端不复制
   业务公式，不扫描生产文件，不拼第二套口径。
3. **合同先于实现。** 新公共能力先定义输入、输出、版本、失败语义和权限边界，再写适配器与页面。
4. **依赖向内，资源在外。** 领域计算不依赖 HTTP、Docker、页面、通知、`.env` 或常驻运行配置；
   文件、网络、数据库和模型服务通过窄适配层进入，编排层负责组合，不把 I/O 混入纯裁决。
5. **失败关闭。** 缺数据、身份不一致、口径未知、权限越界或证据不完整时返回明确的
   `NOT_READY` / `NOT_EVALUATED` / `BLOCKED`，不猜测、不补造、不降级成看似成功。
6. **生产、研究、Web 隔离。** 研究和页面施工不得改变 scheduler 身份；生产只运行可回滚的不可变
   镜像，Web 默认本机只读，外部调用必须单独授权并有预算、次数和数据边界。
7. **继承稳定内核，扩展差异。** 新股票池、因子或模型必须先复用注册表、PIT、成本、门禁、账本、
   证据和查询合同；池特有规则通过配置或窄插件表达，不复制整条研究流水线。
8. **复杂度必须付租金。** 新依赖、新服务、新抽象或缓存必须说明它消除的具体风险或重复；只有一个
   实现且没有稳定变化轴时，不提前建设通用框架。
9. **变化可归因、可迁移、可回滚。** 一次只改变一个可解释变量；公共合同变更必须显式版本化，
   给出兼容期、迁移路径、回滚点和旧版本退出条件。
10. **坏消息不可隐藏。** 失败尝试、拒绝、数据缺口、恢复路径和通知异常进入同一证据链，页面可以
    降噪，但不能删除或改写权威状态。

## 3. 目标架构与依赖方向

```text
不可变数据 / 外部证据
        ↓
窄适配层（ingest、provider、notify、storage）
        ↓
领域与研究内核（PIT、因子、组合、门禁、裁决）
        ↓
应用编排（pipeline、一次性研究入口、release）
        ↓
只读查询 / 证据投影
        ↓
Web / CLI / 告警展示
```

箭头表示业务数据流，不表示底层可以反向依赖上层。领域内核不得导入 Web；查询投影不得反向调用
生产编排、通知或运行时 secret 配置。跨层需求优先新增窄端口或内容寻址投影，不能用方便为由直接
导入上层实现。

### 多股票池策略工厂的继承边界

所有股票池共享：宇宙注册、成员谱系与 PIT 门、行情/基本面身份、候选合同、尝试计数、成本与执行
语义、G1/压力门、不可变产物、账本、authority overlay、查询与审计。池特有内容仅包括成员规则、
合法历史域、基准、候选经济机制和预冻结参数。若新增股票池需要复制评价器、账本或 Web 口径，默认
判定为架构问题，必须先解释为什么现有扩展点不能安全承载。

## 4. 模块与函数预算

- 新生产模块以 `<=400` 行为常态；`401—600` 行必须在评审中说明单一职责、拆分判断和独立测试；
  `>600` 行禁止新增。
- 生效日前已经超过 600 行的文件进入机器可读热点清单，冻结各自最高行数。它们可以缩小，不能增长；
  新需求只允许薄编排或外置模块。移出清单必须靠实际拆分，不得调高阈值规避。
- 单函数以 `<=60` 个逻辑行为常态；`61—100` 行须说明职责和异常路径；不得新增超过 100 行且同时
  混合 I/O、领域计算和裁决的函数。函数语义仍由人工评审，不为过行数检查制造无意义转发层。
- 禁止新增无边界的 `utils`、`helpers`、`common` 或万能 service。共享代码必须以明确领域能力命名，
  有稳定输入输出和直接测试。
- 自动门只检查稳定、低误报的模块上限和依赖方向；语义职责、重复逻辑、函数复杂度和抽象价值仍是
  必查的人工作业，不能因为机器 PASS 就视为架构 PASS。

## 5. 开工门

影响生产代码、公共合同、数据源、策略臂、页面能力或部署方式的任务，编码前必须回答：

1. 期望拿到什么结果，用户或下游据此做什么决定？
2. 权威事实、冻结输入和不可触碰边界是什么？
3. 现有能力中哪些直接复用、哪些扩展、哪些确实缺失？
4. 新职责属于哪一层，依赖方向是否向内，是否会把重依赖带入常驻服务？
5. 输入/输出 Schema、版本、错误码、`as_of`、authority 和失败关闭行为是什么？
6. 如何独立测试、审计、观测资源、证明幂等并避免口径复制？
7. 如何迁移、回滚、停用旧能力；失败后哪些证据必须保留？
8. 是否新增 secret、外部数据、网络、写接口或用户授权需求？

局部实现且不改变公共合同可在任务协议中回答。以下任一变化必须先写架构决策记录（ADR）：新增常驻
服务或外部依赖；改变跨层依赖；新增写 API；变更账本/公共 Schema；替换权威计算；改变部署/权限
边界；进行跨模块重构；或引入未来多个策略臂共同依赖的新扩展点。

ADR 至少包含：问题与结果目标、现状证据、三个以内候选方案、选择及代价、影响边界、合同与数据
迁移、失败关闭、回滚、验收指标、退出/复审触发器。ADR 只记录有长期影响的裁决，不为普通函数改名
制造文书。

## 6. 交付门

完成定义同时包括：

- 行为测试、失败路径、幂等/确定性和必要的真实部署验证通过；
- `make architecture-check`、全量或相称范围测试、Ruff、`git diff --check` 与脱敏检查通过；
- 未出现新的重复口径、反向依赖、热点增长、隐藏写入或未登记外部资源；
- 公共合同有兼容说明，重大变更有 ADR、迁移与回滚证据；
- `STATE.md` 记录真实完成度，区分工程 GO、数据 GO、策略有效和生产授权；
- 只提交本次范围文件，生产 scheduler 与其他项目边界未被越权改变。

## 7. 例外、债务与宪法变更

例外必须显式记录路径、原因、风险、冻结上限、退出触发器和验证人；“时间紧”不能成为无限期例外。
历史热点采用棘轮治理：不为整齐而大拆重写，也不允许继续堆职责。触碰热点时，至少保持行数不增长、
依赖不恶化、行为有回归；能安全抽离时小步拆分。

修改本宪法或机器阈值必须单独说明被解决的问题、兼容影响和门禁变化。不得在功能提交中静默放宽
上限、扩大排除范围或把违规文件加入热点清单；新增例外须经过明确复核，并保留退出条件。
