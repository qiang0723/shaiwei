# G8-1 监管主源不可覆盖采集协议（2026-07-26）

> 协议：`g8-fund-primary-capture-v1`
>
> 状态：`RESULT_BEFORE_EXECUTION_FROZEN`
>
> 本阶段上限：`PRIMARY_CAPTURED_UNAUTHENTICATED`

## 1. 目标与边界

G8-1 只回答：冻结日起的六只产品法定净值公告原文及其分红备注，能否按可迁移、不可覆盖、
可重放、可检出修订的方式固定在项目内。它不构造总收益，不解析费率，不读策略结果，不运行
G8，不接 scheduler，也不改生产镜像、模型、信号、门禁或 Web。

G8-0 结论已经确认监管集中披露入口覆盖六只产品，但稳定机器入口是 HTTP。因此本阶段即使
全部 PASS，也只能进入 `GO_G8_2_CROSSCHECK_AND_FEE_LINEAGE_ONLY`；基金管理人 HTTPS 交叉源和费率有效期
谱系完成前，G8 保持 `NOT_READY`。

## 2. 首次真实采集冻结

- 日期窗口固定 `2026-07-15~2026-07-24`，不因源站在执行时发布更新日期而漂移；
- 产品和顺序与冻结 G8 篮子完全一致；
- 每只产品一个净值区间请求，共 6 个；每个可用 A 类净值公告再派生一个分红备注请求，
  预期 48 个；
- 每个逻辑请求恰好两次串行观察，共 54 个逻辑请求、108 次 HTTP 观察；
- 不使用环境代理、自动重试、凭据或聚合站。单次超时、非 200、双取不一致或结构漂移均留证后
  fail closed，不用第三次请求“投票”。

## 3. 净值选择门

`GET /fund/disclose/getPublicFundJZInfoMore.do` 的 `aoData` 顺序、固定字段和页长已写入机器协议。
每只产品必须恰好产生 8 条分类 `2030-1010` 的 A 类记录，代码、A 类名称、`fund_id`、估值日、
单位/累计净值和 `uploadDetailId` 全部必须有效；代码×估值日唯一。

每个估值日允许恰好一条分类 `2030-1030` 且单位/累计净值均为空的母级记录被显式忽略。其他分类、
非空未选行、丢日、重日、页长溢出或身份漂移都不能静默容忍。

## 4. 分红备注门

每条可用净值记录的 `uploadInfoDetail.idStr` 是分红备注的父身份。
`POST /fund/disclose/getDividendInfo.do` 必须返回和请求完全一致的产品代码与 A 类名称，并且
包含场内/场外除息日、分红金额、备注和特别说明五个字段。全部为空是合法的“源站空事件证据”，
但不能被解释为历史或未来永不分红；禁止从净值跳变反推分红。

## 5. 证据包与账本

每个逻辑请求生成唯一请求哈希；两次响应的原始字节以 base64 放入项目内的不可覆盖证据包，
同时保留接收时刻、HTTP 状态和安全响应头。`Set-Cookie`、授权头、代理认证头等不得写入证据。

解析行与原文同包保留，Git 忽略该数据目录。受控追加账本只记录请求身份、两个原文哈希、证据包相对路径/
哈希、记录数和状态，不记净值、金额、备注原文、绝对路径或凭据。

相同请求与内容复跑时必须重验证据包并零追加。相同请求出现新内容时，新旧版本均保留，新行标记
`QUARANTINED_REVISION` 后立即停止；禁止覆盖、删除或自动选“最新”。

## 6. 验收门

终版必须同时满足：

- 6 条净值证据行、48 条分红备注证据行，共 54 行；
- 48 条唯一 A 类净值记录，六只各 8 日；
- 非 200、双取不一致、结构失败、修订冲突、哈希失配和代码×日期重复均为 0；
- 第二遍相同入口必须完成双取后复用已有证据，账本行数和哈希不变；
- Docker 一次性容器不注入 `.env`，不挂 Docker socket，只写项目内 `data/g8` 和指定账本；
- scheduler 容器、镜像、创建时间和健康状态不变。

任一门失败都不得宣称 G8-1 GO；全部通过也只证明监管 HTTP 主源证据已安全固化。
