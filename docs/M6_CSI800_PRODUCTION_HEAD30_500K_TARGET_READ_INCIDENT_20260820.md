# M6-5B 结果盲目标读取事件与恢复裁决

## 结论

M6-5B v1 在结果盲工程阶段发生了一次真实目标数组的意外读取。原协议与提交永久保留，但 v1 不再具备执行资格；后续只能使用显式计入该次尝试的恢复版 release scope。

## 发生了什么

为确认封存 R2 bundle 的字段结构，一次只读命令打印了 W1 第一调仓点的交易日、信号日和 30 个有序目标代码。命令没有读取或输出价格、收益、成本、NAV、回撤、窗口指标、汇总指标或裁决；没有调用 runner、auditor、网络、密钥、模拟仓、Web、scheduler 或生产路径。

冻结协议把首次真实目标、价格或效果读取都定义为消耗一次尝试。因此即使效果仍保持盲态，也不能把这次读取静默归类为零尝试。

## 恢复边界

- v1 协议、提交和事件现场不删除、不改写。
- 已发生的目标读取计为家族第 1 次尝试，未产生正式效果产物。
- M6-5B 后续工程只能使用 synthetic fixture；精确 release scope 以恢复协议为权威。
- 将来如获一次真实回放授权，该运行计为第 2 次家族尝试，并仍只允许一个 runner、完整 first/replay 和一个独立 auditor。
- 所有账户、容量、效果门槛和生产禁区保持不变。

权威恢复协议：`config/m6_csi800_production_head30_500k_target_read_recovery_v1.yaml`。
