## 1. 选择口径（作废父协议 D2 的写法）

**原文**："全部合格候选在发现期计算 g1-v2 `selection_increment_ir`，机械取 Top1/Top2"。这是起草时我的错误，按原文无法计算：

- g1-v2 的 `selection_increment_ir`，是候选与 Alpha158 基线逐日配对 RankIC 差的信息比，只在 W1–W6 的检验窗口里存在。
- 基线的滚动预测要用此前的数据训练，而 qlib 缓存始于 2016 年，所以 2016–2018 发现期没有基线预测，"发现期增量 IR"不存在。

**新规则**：
1. **排序**：按 PIT 中性化后因子在 2016-01-01—2018-12-31 的日 RankIC 均值的绝对值排序，有效日 ≥252，即 RF-1 原口径。同值时规范表达式 sha 小者在前。
2. **方向**：取发现期 RankIC 均值的符号，只冻结一次。
3. **判定范围**：只用样本内数据选择，Top1、Top2 依次进入 g1-v2 判定。
4. **证据范围**：全部保留下来的候选都计算完整的 g1-v2 证据，因为 DSR 需要同家族各尝试的增量 IR 方差；但只判定 Top1/Top2。

## 2. 语义盲评（落实父协议第②层"沿用 RF-1"）

RF-1 只留了 `formal_batch_blind_review` 这个名字，从未实现。现定为：

- **时点**：生成阶段结束后、计算任何因子值之前，由用户盲评全部合格候选（≤3）。
- **盲评包内容**：只含候选编号、规范表达式和经济陈述，不含任何由行情计算出的数字、统计量或方向。
- **否决理由**：仅两类，`NOT_THIS_MECHANISM`（不是这个机制）、`DISGUISED_DUPLICATE`（换皮重复）。
- **记录方式**：裁决由工具逐字转录，绝不代写。
- **计数与后果**：
  - 被否决的仍计入家族 N；
  - 全部否决 → `REJECT_TP_F_AND_CLOSE`；
  - 只剩 1 个 → 照常评估判定，`valid_trial_increment_irs` 门如实失败。
