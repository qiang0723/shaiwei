# ADR 0013：R3N 离线入口集成与持久化阶段记录

日期：2026-09-24。状态：OFFLINE_ONLY；继承 ADR 0012，不是生产接线或部署授权。

## 结果目标与开工边界

把 R3M 的纯模拟推进为可实际保存/重载的单次执行记录，以及接收合成业务端口的入口编排。
回答：等待数据后能否在同一 claim 下续接？任意阶段中断、并发竞争或落盘故障会不会重复派发？
用户同意项目内代码、协议和隔离测试；本轮不读取真实业务/效果/秘密，不联网，不调用 Docker，
不构建镜像，不生成真实 scope/批准/claim，不启动或切换生产。测试记录只能写项目 .test-tmp 下。

权威输入是冻结 R3L/R3M、显式时钟、合成元数据及追加的阶段链；不复制交易日历或策略效果算法。
已有 release_metadata.load_plan 可复用日历权威，但它会读取真实业务，因此本轮只定义可替换端口，
不调用该适配器。原 logical_lock 会读环境/运行配置，本轮不调用或改写，也不伪称覆盖旧 writer。

## 选择及代价

1. 只保留内存状态：拒绝，无法验证重启或写入结果未知。
2. 测试目录内 SQLite 事务 + 追加阶段链 + expected-head 比较：选择。使用 Python 标准库，
   不新增服务，BEGIN IMMEDIATE/CAS 只保证本地同一数据库的竞争，不证明 Docker 挂载锁权威。
3. 新增自制 flock/覆盖式 JSON：拒绝，重复锁实现且双文件部分提交难以判定。

SQLite 实现明确命名 OfflineStageStore，拒绝 .test-tmp 外目录，没有生产默认路径。
不据本 ADR 决定最终生产存储后端；迁移到 named-volume 或另一适配器必须另有真实 fixture 证明。
数据库必须显式一次创建；打开丢失库不自动重建，已有/损坏库不覆盖、不清空。测试失败证据保留。

## 版本化合同与调用边界

新增候选离线协议 r2d-candidate-offline-v1，模式 OFFLINE_FIXTURE_ONLY，绑定完整 R3M 计划哈希、
目标首日与显式的 readiness 检查次数上限。该上限只约束合成调度，不修改 g1-v1 或任何生产门。
新源码按合同/持久化适配/编排拆分，各文件<=400行，不改旧13组件、R3L/R3M或生产 scheduler/CLI。

离线入口集合覆盖 scheduler、daily、shadow、paper、verify、acceptance 六类路由。仅 scheduler
可申请完整编排，其他独立业务入口在此适配器内全部拒绝，且在元数据读取/端口工厂之前拒绝。
正常阶段只能由编排进入，不能把独立 paper 当首日启动。未知入口拒绝。
这不意味着现有裸 CLI 已被拦截：本轮未连接真实 CLI，未证明宿主/旧容器无法绕过。
最终生产装配与全入口隔离是上线前硬缺口，不能以“六类离线入口测试通过”替代。

端口工厂延迟至 BEGIN 记录持久化之后构造，停放/拒绝路径不构造业务端口，不装载 secret。
每个端口返回类型严格的阶段回执，绑定计划、首日、阶段、BEGIN 哈希及非敏感证据 SHA；
错误类型、日期、身份、阶段、token 或结果不符均拒绝。回执只是测试合同，不是实际业务证明。

## 阶段与失败关闭

CLAIM 唯一 → READINESS → DAILY → SHADOW → baseline 执行/verify/acceptance →
top20 执行/verify/acceptance → 双账户 FINAL_ACCEPTANCE。独立最终验收不能被前面的计数代替。
每次调用业务端口前先提交 BEGIN，返回合格回执后再提交 END。两个工作者只能一个取得同一阶段。
追加记录包含序号、前哈希、计划 SHA、时间和回执；逐行重放同时验证链和合法状态迁移。

- READINESS 明确返回 WAITING_SOURCE 且 END 已提交时，本次调用立即返回，不进入任何正式业务。
  下次须独立新鲜元数据证明首日仍合法、业务尝试仍为0、身份/所有权不变，才在同一 claim 下再探测；
  每次入口调用最多探测一次，受冻结上限限制，不内部 sleep/retry，不自动滚到下一交易日。
- CLAIM 后尚无 BEGIN，或某阶段 END 已提交且其证据与独立元数据严格相符，可从下一个阶段续接；
  不重新执行已完成阶段。这是新离线合同的明确续接语义，不改 R3M 对手填 CLAIMED 的保守拒绝。
- BEGIN 已提交但无 END，即 MAY_HAVE_WRITTEN：无论是否真的调用过端口，都禁止自动重跑。
  端口异常、回执错误、提交失败一律停止；不调用 rollback，不根据异常字符串猜测“没写”。
- END 提交后应答丢失，下次只能通过持久化链与独立元数据对账后续接，不重放已完成业务。
- 未知/重复/跳步/未来或倒退时间、损坏链、丢失记录、计划漂移、正式尝试不符均失败关闭。
  无自动修复、无删除证据或补写 PASS。完成首日后只返回离线完成状态，不开放后续常驻运行。

每个阶段开始前都重新读取注入的只读元数据并检查时间/身份/日期/尝试计数/阶段证据；初次 claim
复用原 rehearse_first_day 门。后续阶段按已完成的持久化前缀校验独立尝试计数，不把实际 CLAIMED
改写成 UNCLAIMED，也不把“已经 daily PASS”强行套入初次零尝试门。

## 验收、迁移与退出

合成测试覆盖停放零工厂/零业务调用、独立入口拒绝、真实测试数据库重开、等待数据限次续接、
每阶段前后中断、BEGIN/END 提交故障、两进程抢同一 claim、损坏/缺失记录、身份与计数漂移。
延续受保护R2D回归、架构、Ruff与静态脱敏；不运行会读取真实业务/秘密的全仓检查。
测试 SQLite 的幂等/原子性不等于实际业务 exactly-once，也不证明断电、Docker卷或恶意文件删除安全。
追加哈希链不是数字签名；管理员重写整个库或删除尾部再伪造独立元数据不在此离线适配的证明范围。

本轮无需生产回滚：旧入口字节不变，新模块不接入镜像。未来生产适配必须绑定真实计划/镜像/锁/审批，
核验全部 writer 隔离、日历与源就绪时序、新候选 fixture、发布谱系 CAS 和最终验收产物身份。
任何证明缺失仍不能 start。若离线异常路径仍可能重复调用，停止后继施工，不降低门槛。
