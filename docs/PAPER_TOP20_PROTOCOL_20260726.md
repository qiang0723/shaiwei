## 1. 研究问题

在不改变中证800正式模型、股票池、信号日期和执行规则的前提下，将同一份 Top30 正式信号集中为
Top20，能否在人民币 50 万元的真实交易单位、涨跌停、停牌、费用和现金约束下形成更易理解、可执行的
模拟组合，并与原 Top30 基准账户形成长期同口径比较。

这是一项持仓集中度比较，不是新的选股模型、因子或生产策略。短期净值只用于验证工程与积累
`FORWARD` 证据，不据此宣称 Top20 优于或劣于 Top30。

## 2. 账户身份与隔离

- 新账户：`model_top20`；初始资金固定为 500,000 RMB。
- 执行策略版本：`paper-top20-v1`；基准继续为中证800 `000906.SH`。
- 原账户 `model_baseline`、`paper-v1`、既有产物、事件、运行行和策略哈希必须保持字节不变。
- 两个账户共用追加式账本的 schema，但以 `account_id`、策略哈希、独立状态链和独立产物目录隔离；
  任何跨账户状态、事件或净值混用均 fail closed。
- 新账户只做模拟交易，不连接券商，不产生真实委托，不获得生产选股授权。

## 3. 唯一允许的信号投影

输入只能是已通过影子对账的 `model_baseline` 不可变 Top30 signal manifest。每个输入必须同时满足：

1. manifest 哈希与影子运行、次日对账账本完全一致；
2. 恰有 30 个唯一证券，排名恰为 1—30，目标权重之和为 1；
3. 不含 `.BJ`，信号日和执行日满足原 `paper-v1` 的下一开市日合同。

确定性投影仅执行以下操作：按原排名保留 1—20 名；保留证券、原始分数和原始排名；将每只目标权重
改为 0.05，使总目标权重仍为 1。不得换股、补位、重排、调分、读取未来行情或从未持久化的全量排名
重新选择。投影身份和内容哈希必须写入 Top20 不可变运行产物；原 signal SHA-256 仍作为唯一来源信号
身份，不伪造第二份模型信号。

当前前瞻 manifest 并未实现可独立复算的 `n_drop` 选股状态机，因此本账户明确命名为
`rank_head_equal_weight` 投影，不冒充 `TopK20/n_drop2` 策略。若以后研究 `n_drop2`，必须另立独立协议并
从冻结的完整排名/前态生成信号，不能回写本账户。

## 4. 调仓、成交和会计

- 信号和调仓日期完全跟随正式 Top30 signal manifest；当前冻结节奏为每 10 个交易日调仓。
- 非调仓日只估值和处理公司行为，不为凑足 20 只而下单。
- 成交时点、卖出优先、方向性涨跌停、停牌、主板/创业板 100 股单位、科创板最低 200 股、费用、
  公司行为、陈旧估值和会计容差全部复用 `paper-v1`。
- “Top20”表示目标证券上限为 20，不保证实际持仓恰为 20。无法成交、最小交易单位、现金不足、
  公司行为或已有受阻卖单都必须如实反映在实际持仓、现金和拒单原因中。
- 2026-07-17 至 2026-07-24 的可追溯执行日标为 `BACKFILL`；账户规则在下一个交易日开盘前已冻结，
  因此 2026-07-27 起自然形成的账户日才标为 `FORWARD`。原文曾机械沿用基准账户的 7月23日起点，
  已在任何 Top20 结果生成前由 `docs/PAPER_TOP20_PROTOCOL_ADDENDUM_20260726.md` 显式纠正。回填只
  初始化状态和验证会计，不得并入前瞻业绩结论。

## 5. 证据、幂等和验收

每个账户日必须绑定来源 signal、投影 SHA-256、影子对账、行情批次、数据快照、代码快照、策略哈希和
前态哈希。验收至少包括：

- Top20 投影纯函数的顺序无关性、精确 20 只/5% 权重、重复/缺排名/非30只/`.BJ` 对抗测试；
- 两账户状态、事件、运行和产物的独立重放；共享账本按
  `docs/PAPER_TOP20_PROTOCOL_EVIDENCE_ADDENDUM_20260726.md` 验证“旧字节前缀和 Top30 规范行哈希
  不变、只追加 Top20”，原 Top30 不可变产物整树哈希施工前后不变；
- 同一输入二次运行 `NOOP`，Top20 产物与账本哈希不变；
- `BACKFILL`/`FORWARD` 分层、净资产恒等、实际持仓数、拒单和费用可复算；
- Docker 串行运行、飞书消息带 `account_id`、失败不阻断旧证据、`.BJ=0`；
- 新 scheduler 镜像只有在全量测试、发布快照、只读挂载、回滚和现有 Top30 验收全部通过后才可提升。

Top20 前瞻验收必须显式使用 `paper-top20-v1` 的策略哈希；禁止使用默认 Top30 策略哈希冒充验收。
正式展示只允许走冻结的只读查询。Web 账户切换/对比属于后续只读展示变更，不阻塞核心账户建账，也
不得由前端自行扫描账本或 Parquet。

## 6. 停止条件与结果边界

出现信号投影歧义、账户串账、旧 Top30 哈希变化、代码快照不一致、无法重放、会计恒等失败、`.BJ`、
不完整真实行情或发布隔离退化时立即停止，不人工修数、不覆盖历史。

工程验收通过只说明账户可信运行。Top20 与 Top30 的策略比较至少同时报告相同 `FORWARD` 日期范围、
基准、费用、回撤、换手、现金比例、实际持仓数和不可成交原因；未达到既有 Web 前瞻样本门槛时保持
`OBSERVING/NOT_READY`，不得展示年化、Sharpe 或信息比率。
