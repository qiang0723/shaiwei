## 诊断回答

### 1. 失败首先来自负的费前交易经济性

主点 63 笔闭合交易的费前盈亏为 -3,710.56 元，费用为 1,884.04 元，费后为 -5,594.60 元，
单笔期望为 -88.80 元。费用扩大了亏损，但不是亏损成立的必要条件，因此不能把旧实现解释为“只要
降低成本就能救”。

主点止损组 37 笔、净盈亏 -48,641.00 元；止盈组 19 笔、净盈亏 +41,309.72 元；时间退出组
7 笔、净盈亏 +1,736.68 元。持有 1—5 日和 6—10 日分别贡献 +5,469.72 元、+5,190.83 元，
11—15 日贡献 -16,255.15 元。以上是冻结样本中的亏损集中位置，不是因果证明，也不授权按已见
结果改止损线或持有天数。

### 2. 低参与率是规模瓶颈，不是已证明的亏损根因

主点 727 日中仅 204 日持仓，60 日有新买入；有持仓天数占比 28.06%，全期平均仓位 2.01%，
持仓日平均仓位 7.15%，最大仓位 27.24%。没有容量限制订单。

主点首批 188 个买单成交率 33.51%；105 个因 `ALREADY_HELD_OR_POSITION_CAP` 被拒，20 个因
`BELOW_LIMIT_OR_LOT` 被拒。合并原因不能区分重复信号与真实持仓上限，因此只能确认订单漏斗和低
参与率，不能确认信号稀缺或七只上限是根因。负费前期望未解决前，放大仓位只会放大风险。

### 3. 局部邻点和成本场景没有提供挽救证据

主点、确认邻点、容忍邻点的基础净收益为 -1.12%、-6.15%、-1.90%；费前盈亏为 -3,710.56、
-29,683.82、-7,772.67 元。三个点的基础、双倍成本、额外单边 10bp 场景全部为负。2021 年主点
净盈亏为 +8,668.23 元，2022/2023 为 -8,072.46/-6,190.36 元，阶段稳定性也不足。

因此旧 R3G-2 应保持关闭，不调整门槛、不追加参数点、不打开留出期。下一合法研究只能是另立一个
机制上有实质区别的 TS-v6 结果前假设。

## 工程恢复留痕

本节点没有静默重跑：

1. Compose `tmpfs` 首次解析失败发生在容器创建前，真实输入未挂载；修复后另建镜像。
2. 原 runner CLI 映射失败发生在进入函数前，未读封存输入、输出为空；原入口关闭。
3. 第一 runner 恢复在明细读取前发现父 runner 审计前状态与独立 audit 最终状态被混用；只读聚合
   report/audit，输出只有授权，恢复关闭。
4. R2 runner 使用独立输出根唯一完成，内部 first/replay 一致，之后不再运行。
5. 原 auditor CLI 映射失败发生在进入审计函数前，audit-r2 为空；入口关闭。
6. auditor 入口恢复完成检查后因 `numpy.bool_` 无法写 JSON 而失败，audit-r3 为空；scope 关闭。
7. 序列化恢复只把检查值规范为 Python `bool`，最终 audit-r4 唯一完成。
