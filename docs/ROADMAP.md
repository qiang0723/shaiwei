# 结果导向路线图（2026-07-16 冻结；2026-07-22 加入 P0.5）

> 本路线图记录四项已确认的后续施工，以及一条待评审的长期 LLM 持续因子研究线：模拟组合
> 与前瞻绩效闭环、主力资金流候选、科创50独立策略臂、专业只读 Web、LLM 多源因子研究。
> 领先不是验收标准；只有可复现、扣除成本、通过预注册门槛的增量结果才算完成。

## 依赖顺序

1. 先完成当前锁竞争修复后代码版本连续三次“信号 → 下一交易日开盘对账”的前瞻影子验收。
2. 验收期间不修改中证800生产基线、调仓规则、数据口径或门禁。
3. 三次完整闭环验收和健壮性复核通过后，先施工 P0.5“模拟组合与前瞻绩效闭环”，把信号、真实成交约束和累计结果连接起来；P0.5 不反向改变模型或调仓规则。
4. P0.5 通过后，依次施工“资金流候选验证”和“科创50独立基线”；二者不得同时写入生产基线，确保结果可归因。
5. 后台结果线始终优先。P0 验收期间可旁路优化 Web 和 P0.5 的信息架构、指标草案、查询契约草案和低保真线框，但不写代码、不启动服务、不读取未登记的临时数据。
6. P0.5 首批后台指标、账本和查询契约稳定后，才施工 Web 代码；Web 首版只读，不连接券商、不提供下单或在线改参，且不得阻塞 P1/P2。

截至 2026-07-23，P0 三次闭环和验收后通知健壮性复核均已完成：飞书瞬时网络、HTTP 408/425/429/5xx 与响应解码异常采用最多 3 次的有界退避，同一逻辑消息固定 `message_id`，每次尝试追加留痕；通知仍不改变核心任务退出语义。P0.5 已冻结 500,000 RMB 和 `paper-v1`，工程、Docker 接入、四日 BACKFILL 及首个自然 `FORWARD` 验收全部 PASS；完整证据见 `docs/P05_FORWARD_ACCEPTANCE_20260723.md`。

## R0.5 · 模拟组合与前瞻绩效闭环

### 目标

把不可变信号、真实下一交易日开盘约束和持续组合会计连接起来，回答“正式信号在真实可成交约束和成本后取得了什么结果”，而不是只统计目标权重或单日可成交性。

### 当前边界

- 首版只运行 `model_baseline` 正式模型基准仓；不接券商、不生成真实订单。
- 正式买卖时点固定为信号后下一交易日官方开盘。止盈、止损、限价区间或 LLM 动态择时不进入首版；若后续研究，必须作为独立、预注册的执行策略臂。
- 实际成交、持仓和现金是组合真身；涨跌停、停牌或行情缺失导致未成交时，不得用目标持仓覆盖实际状态，也不得事后追价补成交。
- 未来对话或 LLM 研判只能进入独立 `llm_judgment` 账户，不能污染模型基准仓或生产信号。

### 施工输出

- 版本化执行策略，以及追加式订单、成交、持仓、现金、公司行为和每日净值账本。
- 每笔订单到信号哈希、行情批次、成交判定、费用和持仓变化的完整证据链。
- 扣成本净值、中证800净超额、最大回撤、换手、成交率、开盘偏差、现金拖累和个股贡献。
- `paper_portfolio_snapshot`、`paper_orders_fills`、`paper_nav_series` 三组首批只读查询契约。
- Docker 日任务、重复运行幂等、异常恢复、飞书守护和脱敏后的运行证据。

### 通过条件

- 无未来数据；成交只能使用执行时点已知的信号、交易状态、官方开盘和事前费用规则。
- 每日满足“净资产 = 现金 + 持仓市值”，订单 → 成交 → 持仓 → 现金 → 净值可逐项重算并通过哈希验证。
- 同一输入重复运行产生相同结果且账本不重复追加；`.BJ` 为 0，失败不覆盖旧证据。
- 公司行为、不同板块交易单位、最低费用和无法成交语义均有实测 fixture 与边界测试。
- 首版只读、无券商连接、无在线改参；Web 只能查询已登记结果。

### 禁止事项

- 不把当前目标权重当成已成交持仓，不以复权价格伪造真实现金流。
- 不观察后续行情后补写买卖点、成交价、止盈止损或未成交处理。
- 不混合模型基准仓、未来因子研究仓和 LLM 主观研判仓的资金、成交或业绩。
- 不以绝对盈利替代相对中证800、扣成本、含回撤的结果判断。

## R1 · 每日主力资金流候选

### 目标

判断数据商口径的主力/大中小单资金流，在现有 Alpha158 量价特征之外是否提供稳定、可交易的独立信息；不以“成功采集”或“单因子历史收益为正”作为成果。

### 当前边界

- 当前正式 Alpha158 使用价格、成交量、VWAP 及滚动量价关系，不包含 `moneyflow_ths`/`moneyflow_dc` 等显式主力资金流特征。
- 已有 `amount`、`turnover_rate`、`volume_ratio`、市值等字段属于量价/流动性信息，不等同于数据商定义的“主力净流入”。
- 北向资金继续服从 `DATA_SPEC.md` 冻结口径：2024-08-19 起无连续日度披露，不作因子。

### 施工输出

- Tushare 资金流原始批次、冻结字段 schema、请求参数、内容 SHA-256 和追加式采集账本。
- 发布时点实测报告：明确当日 19:30 是否稳定可用；若不能证明，则统一按下一交易日可用处理。
- 覆盖率、缺失率、重复键、修订、极值、停牌日行为及北交所排除报告。
- 对行业、市值、成交额/换手及现有 Alpha158 暴露残差化后的候选特征和证据。
- 与现有基线同窗口、同成本、同调仓条件下的增量 RankIC/ICIR、净超额、回撤、换手和稳定性报告。

### 通过条件

- PIT/shift、完整性和幂等门禁全部通过；来源不可用或发布时间不确定时失败即停。
- 残差化后仍有跨窗口稳定信息，并使组合扣成本结果相对 Alpha158 基线产生可复现增量。
- 通过冻结的 G1 准入规则后才允许进入正式因子库；普通 REJECT 保留证据，不调整门槛追结果。

### 禁止事项

- 不把数据商的“主力”标签当成交易所统一事实。
- 不因原始相关性、单窗口 IC 或回测收益好看而直接入模。
- 不用回测期内观察到的发布时间为同日可用性背书。

## R3 · 专业只读 Web

### 目标

让使用者更快判断“数据是否可信、策略是否有效、今天是否需要行动”，而不是把上线页面本身当成果。

### 双轨边界（2026-07-19 更新）

- **后台主线**：P0/P0.5/P1/P2 的运行、证据、数据与研究结论优先，Web 不得反向要求修改冻结口径。
- **设计旁路**：近期连续打磨页面任务模型、信息架构、指标定义、查询契约和线框，产物只落文档。
- **代码闸门**：P3-0 查询底座和 P3-1 首批三页已分别结果前冻结并于 2026-07-25 验收 GO；后续页面、查询或部署能力仍须另立目标，且不得改变冻结后台口径。
- **真实性闸门**：线框可使用明确标注的示例值；正式页面的每个数字必须能追溯至账本、不可变产物或哈希证据。

### 参考范式

- Grafana：运行状态、时间序列、告警和下钻。
- MLflow：实验、参数、指标、模型与产物追溯。
- TradingView：K线、指标叠加、缩放和标的比较交互。
- Ant Design：中文企业应用的信息层级、导航、筛选、表格和详情页。

参考其信息架构和交互范式，不复制品牌视觉；整体采用中性、克制、桌面优先且可响应式查看的专业金融风格。

### 页面进度

1. **总览（P3-1 已完成）**：数据截止时间、核心/通知状态、最新信号、FORWARD 观察和证据下钻。
2. **模拟组合（P3-1 已完成）**：BACKFILL/FORWARD 分层、实际持仓、会计事实和账户日证据。
3. **股票池与信号（P3-1 已完成）**：排名、目标/实际权重、计划差、执行证据和哈希身份；当前后台未提供因子贡献时不生成前端解释。
4. **因子工厂（待查询契约）**：因子目录、tear sheet、可比分析和准入/拒绝历史。
5. **模型与回测（待查询契约）**：实验版本、滚动窗口、基准、成本情景、回撤和可复现产物。
6. **数据质量（待查询契约）**：覆盖、缺失、异常、批次、来源、发布时间和哈希链。
7. **系统运行（待查询契约）**：Docker、调度任务、脱敏日志、飞书投递和异常恢复。

### 通过条件

- 先冻结指标字典、状态机、API/查询契约和低保真线框，再写前端代码。
- 首页优先显示结论、异常和数据时点；所有收益同时展示基准、成本与回撤。
- 页面中的数字可下钻到运行、信号、实验或原始批次证据。
- 不显示 token、Webhook、签名或其他秘密；首版不写生产数据、不下单、不在线改参。
