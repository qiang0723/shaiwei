# 结果导向路线图（2026-07-16 冻结）

> 本路线图记录三项已确认的后续工作：主力资金流候选、科创50独立策略臂、专业只读 Web。
> 领先不是验收标准；只有可复现、扣除成本、通过预注册门槛的增量结果才算完成。

## 依赖顺序

1. 先完成当前锁竞争修复后代码版本连续三次“信号 → 下一交易日开盘对账”的前瞻影子验收。
2. 验收期间不修改中证800生产基线、调仓规则、数据口径或门禁。
3. 三次完整闭环验收通过后，依次施工“资金流候选验证”和“科创50独立基线”；二者不得同时写入生产基线，确保结果可归因。
4. 后端指标口径、账本和查询契约稳定后，再施工 Web；Web 首版只读，不连接券商、不提供下单或在线改参。

## R1 · 每日主力资金流候选

### 目标

判断数据商口径的主力/大中小单资金流，在现有 Alpha158 量价特征之外是否提供稳定、可交易的独立信息；不以“成功采集”或“单因子历史收益为正”作为成果。

### 当前边界

- 当前正式 Alpha158 使用价格、成交量、VWAP 及滚动量价关系，不包含 `moneyflow_ths`/`moneyflow_dc` 等显式主力资金流特征。
- 已有 `amount`、`turnover_rate`、`volume_ratio`、市值等字段属于量价/流动性信息，不等同于数据商定义的“主力净流入”。
- 北向资金继续服从 `DATA_SPEC.md` 冻结口径：2024-08-19 起无连续日度披露，不作因子。

### 施工输出

- Tushare 资金流原始批次、冻结字段 schema、请求参数、内容 SHA-256 和追加式采集账本。
- 发布时点实测报告：明确当日 19:30 是否稳定可用；若不能证明，则统一按下一交易日可用处理。
- 覆盖率、缺失率、重复键、修订、极值、停牌日行为及北交所排除报告。
- 对行业、市值、成交额/换手及现有 Alpha158 暴露残差化后的候选特征和证据。
- 与现有基线同窗口、同成本、同调仓条件下的增量 RankIC/ICIR、净超额、回撤、换手和稳定性报告。

### 通过条件

- PIT/shift、完整性和幂等门禁全部通过；来源不可用或发布时间不确定时失败即停。
- 残差化后仍有跨窗口稳定信息，并使组合扣成本结果相对 Alpha158 基线产生可复现增量。
- 通过冻结的 G1 准入规则后才允许进入正式因子库；普通 REJECT 保留证据，不调整门槛追结果。

### 禁止事项

- 不把数据商的“主力”标签当成交易所统一事实。
- 不因原始相关性、单窗口 IC 或回测收益好看而直接入模。
- 不用回测期内观察到的发布时间为同日可用性背书。

## R2 · 科创50独立策略臂

### 目标

验证科创50能否在中证800主策略之外形成经成本和风险约束后仍成立的独立结果；不预设指数名称不同就代表有效分散。

### 当前边界

- 指数代码固定为 `000688.SH`，使用历史成分和权重做 PIT 股票池。
- 当前科创板 20% 涨跌停识别、全市场行情/复权/基本面采集和通用 qlib 构建能力可以复用。
- 中证800仍为主策略池；科创50使用独立配置、数据集标识、基准、模型、信号、实验账本和准入结论。

### 施工输出

- `000688.SH` 的 index_daily、index_weight 历史批次与完整性报告。
- 独立 `star50` qlib instruments；不得覆盖 `csi800` 或阶段0冻结缓存。
- 在首次回测前冻结适合50只股票池的 TopK/n_drop、流动性、行业和单股风险约束；Top10/Top15只能作为事前候选，不能看完结果再选。
- 按科创板真实历史长度重新设计训练/验证/OOS窗口，并显式声明其证据不能与2016年起的中证800六窗口等同。
- 成本、涨跌停、极端波动、持仓集中度及与中证800实际持仓重叠的压力报告。

### 通过条件

- 历史成分 PIT、20%涨跌停、停牌、ST、复权、量纲、北交所排除和幂等门禁通过。
- 多窗口净结果、回撤和稳定性达到事前冻结门槛。
- 与中证800联合配置前，必须证明持仓重叠、行业/风格暴露和风险贡献可接受；未通过时只保留研究结果，不配置资金。

### 禁止事项

- 不照搬中证800 Top30（30/50会显著削弱截面选择强度）。
- 不用2016年以前/科创板成立前的伪历史补足窗口。
- 不把两个股票池混合后再回头解释收益来源。

## R3 · 专业只读 Web

### 目标

让使用者更快判断“数据是否可信、策略是否有效、今天是否需要行动”，而不是把上线页面本身当成果。

### 参考范式

- Grafana：运行状态、时间序列、告警和下钻。
- MLflow：实验、参数、指标、模型与产物追溯。
- TradingView：K线、指标叠加、缩放和标的比较交互。
- Ant Design：中文企业应用的信息层级、导航、筛选、表格和详情页。

参考其信息架构和交互范式，不复制品牌视觉；整体采用中性、克制、桌面优先且可响应式查看的专业金融风格。

### 首版页面

1. **总览**：数据截止时间、任务/门禁状态、最新信号、组合表现、风险和告警。
2. **股票池与信号**：入选/排除原因、排名、因子贡献、流动性和可成交性。
3. **模型与回测**：实验版本、滚动窗口、基准、成本情景、回撤和可复现产物。
4. **数据质量**：覆盖、缺失、异常、批次、来源、发布时间和哈希链。
5. **系统运行**：Docker、调度任务、日志、飞书投递和异常恢复。

### 通过条件

- 先冻结指标字典、状态机、API/查询契约和低保真线框，再写前端代码。
- 首页优先显示结论、异常和数据时点；所有收益同时展示基准、成本与回撤。
- 页面中的数字可下钻到运行、信号、实验或原始批次证据。
- 不显示 token、Webhook、签名或其他秘密；首版不写生产数据、不下单、不在线改参。
