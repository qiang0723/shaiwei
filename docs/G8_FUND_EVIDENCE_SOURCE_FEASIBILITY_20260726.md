`PRIMARY_CAPTURED_UNAUTHENTICATED`；只有完成基金管理人官方 HTTPS 交叉核验、费率有效期谱系和冲突
门后，才可能升为 `VERIFIED`。

## 2. 为什么它是法定主源

证监会《公开募集证券投资基金信息披露管理办法》第十四条要求开放式基金不晚于每个开放日次日
披露份额净值和累计净值，第十五条要求基金合同、招募说明书等载明申购赎回价格计算及费率。
证监会净值公告 XBRL 规则要求基金管理公司向电子数据平台报备，并由基金信息披露网站对外展示；
净值模板同时覆盖分红除息说明。配套规定明确基金电子披露网站为
`http://eid.csrc.gov.cn/fund`。

因此本项目固定：监管电子披露站是主源，基金管理人官网是 HTTPS 交叉源；聚合平台只能用于发现
异常，不能提供权威值、补缺或改判。

## 4. 分红与法定文件入口

净值响应提供 `uploadInfoDetail.idStr`，监管站公开
`POST /fund/disclose/getDividendInfo.do`，返回场内/场外除息日、分红金额、备注和特别说明等固定字段。
本次空事件样本结构 PASS，但不据此声称六只产品历史或未来不会分红；下一阶段每个已捕获净值公告
都必须查询并保留对应分红说明，禁止只从净值下跌推断分红。

六只产品详情页均存在并同时提供产品资料概要、招募说明书、净值日报和基金管理人公告入口。当前
只证明文件可发现；尚未下载、哈希、解析申购/赎回费率，也未建立生效日期谱系。费率在 G8 首尾现金
流中有实质影响，所以缺失时必须保持 `NOT_READY`，不得使用当前费率回填历史。

## 5. 下一阶段唯一允许范围

G8-1 只允许施工监管主源不可覆盖采集器和账本：

1. Docker 内串行、限速请求；保存请求身份、响应原文、接收时间、HTTP 头和 SHA-256，禁止覆盖；
2. 同一请求即时双取一致后才登记，任何结构漂移、修订或冲突进入隔离区；
3. 逐代码、逐估值日抽取唯一 A 类净值行，并为每个公告查询分红说明；
4. 监管 HTTP 主源未完成官方管理人 HTTPS 一致性核验前，只能标
   `PRIMARY_CAPTURED_UNAUTHENTICATED`；
5. 法定文件单独下载和哈希，费率人工/机器抽取必须绑定文档哈希与生效日；
6. 不接 scheduler、不生成总收益、不读策略收益、不运行 `evaluate()`、不写 G8 裁决账本。

聚合站数据、前向填充、累计净值直接当复权净值、从净值跳变猜分红、当前费率覆盖历史或删除冲突
版本全部禁止。
