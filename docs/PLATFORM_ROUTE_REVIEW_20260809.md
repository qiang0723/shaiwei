## 4. 哪些方向继续保留

1. 生产 scheduler、数据增量、哨兵、信号、次日对账、双模拟账户和飞书异常恢复继续自然运行。
2. PIT、结果前冻结、成本、成交约束、不可变证据、独立 audit 和 Docker 隔离继续作为不可降低的底线。
3. 负结果、BLOCKED、NO-GO 与方法失效继续如实展示；不为“平台看起来成功”而改门槛或删失败证据。
4. Web 保持本机只读和权威事实投影；当前没有事实缺口，不做视觉重做、写控制面或新指标拼接。
5. 架构棘轮继续执行；新生产模块不超过冻结边界，但不以删行数量代替结果目标。

## 6. 下一主目标：R2-1 前瞻证据检查点

下一主目标不新增代码，目标是取得真实的20个live-dual账户日和至少2次自然双账户调仓：

1. 仅由现有 scheduler 自然产生证据；不补造、不手工追跑成功、不改模型/TopK/调仓/成本/账户初始资金。
2. 每日只在核心 FAIL、通知越界、账本不追加、代码/数据快照漂移或幂等失败时施工最小修复。
3. 预计2026-08-14核验第一次live-dual调仓；预计2026-08-28同时核验第二次调仓与20日门。实际日期随
   真实交易日和运行状态顺延，不能用计划日期代替证据。
4. 检查点只比较累计净值、相对基准、回撤、换手、费用、现金、可成交性和调仓级差异；继续禁止短样本
   年化、Sharpe、信息比率或生产切换结论。
5. 20 日/2 次调仓只授权形成首份诊断结论，不自动授权更换生产 Top30。若差异仍小或不稳定，继续观察；
   若形成明确可执行信号，再另立单变量协议。

## 7. 下一次研究如何避免重复偏移

R2-1 完成前不选新研究家族。完成后若启动新批，必须同时满足：

- 只使用已有成熟 PIT 数据和已验证 runner/auditor，不先追逐新的外部谱系；
- 一次只改变一个具有经济含义的变量，候选/模型/组合尝试数结果前冻结；
- 真实运行前先做最小 metadata/coverage probe，数据不满足就停止，不先建完整恢复栈；
- 首次基础设施失败最多允许一个有界 successor；第二次仍失败则关闭本批，禁止形成 R1—R5 恢复链；
- 任何公共控制面必须先证明至少三个未来批次会复用，否则保持批内窄实现；
- 先定义“这个结果会改变什么决策”，不能回答就不施工。

## 8. A1 与备份旁路

A1-3A 已建立远端代码 tag 和本地镜像恢复材料，但镜像与真实执行证据没有异机副本。A1-3B 继续阻断；
等用户指定远程服务器或私有 registry 后，再旁路完成异机恢复。该事项不应阻塞 R2-1 的自然前瞻，也
不能成为继续写研究代码的理由。

## 9. 最终裁决

平台没有整体跑偏：它稳定、诚实，并且能够拒绝不可信结果。近期确实局部偏离了“拿到结果”的主道，
表现为恢复分支和历史复算入口增长过快。现在起把成功标准从提交数、代码量和工程 GO，改回可影响决策
的权威证据。

因此本复盘完成后不自动启动新开发。下一有意义节点是2026-08-14的首次live-dual调仓核验，随后是
最早2026-08-28的20日/2次自然调仓检查点；中间没有异常时，保持系统自然运行就是正确施工。
