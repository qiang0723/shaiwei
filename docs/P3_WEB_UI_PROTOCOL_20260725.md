# P3-1 Web 1.0 首批正式界面协议（结果前冻结）

> 冻结日期：2026-07-25（Asia/Shanghai）
>
> 协议：`p3-web-ui-v1`
>
> 状态：`FROZEN_BEFORE_IMPLEMENTATION`

## 1. 本阶段目标

P3-1 只把 P3-0 已冻结的只读 HTTP 契约接成 Web 1.0 首批三个正式页面：

1. `/overview`：总览；
2. `/paper`：模拟组合；
3. `/signals`：股票池/信号；
4. 三页共用的证据抽屉、状态组件、请求错误态和响应式导航。

本阶段不新增或修改研究指标、查询公式、API schema、策略、模型、门禁、生产数据、账本、
scheduler 镜像或发布流程；不实现因子工厂、模型/回测、数据质量、完整系统运行、导出、认证、
远程访问、交易、在线改参、任务重跑或文件浏览。

## 2. 权威输入与一致性

前端只允许消费 P3-0 已登记的同源接口：

- 总览：`GET /api/v1/overview`
- 模拟组合：`GET /api/v1/paper/portfolio`、`paper/nav`、`paper/forward`、`paper/replay`
- 股票池/信号：`GET /api/v1/signals/latest`

总览只使用一个原子 `overview` 响应，禁止并发拼接其他端点形成首页结论。模拟组合的四个响应
必须具有完全相同的 `schema_version/meta.snapshot_id/meta.as_of`；任一不同即显示
`CONFLICT` 并停止渲染组合数字。信号页只使用一个 `latest` 响应；执行证据以该响应返回的
状态和字段为准。

所有请求固定 `cache: no-store`。`as_of` 只能来自 URL 中合法的 `YYYY-MM-DD`；路由切换保留
该值，页面局部筛选不跨页面保留。刷新或切换 `as_of` 时不得把旧数字冒充当前响应。

前端不得扫描文件、账本、Parquet 或 Docker，不得自行查询任意路径，不得计算研究指标。
允许的展示计算仅限格式化、图形坐标映射、同一 `paper/nav` 响应内的最大回撤，以及同一列表
内的计数和排序；这些值不得回写或称为后台裁决。

## 3. 页面冻结结构

### 3.1 总览

阅读顺序固定为：

1. 综合状态、原因、最新完整交易日和查询生成时间；
2. 今日行动：是否调仓、信号日、下一执行日、目标数、计划交易腿和执行证据状态；
3. 唯一第一视觉焦点：FORWARD 锚定后的最新组合净值、基准净值、净值差、回撤和观察数；
4. 组合与运行诊断：净资产、现金比例、实际持仓、重放、核心任务、通知；
5. 证据链、恢复历史和异常原因；
6. 证据抽屉。

首页不从其他接口补时间序列。当前原子响应只有 FORWARD 最新点时，主结果使用清晰的最新值
比较和“前瞻观察仍短”的 `OBSERVING` 说明，不造曲线、不显示年化、Sharpe 或信息比率。

### 3.2 模拟组合

阅读顺序固定为：

1. `model_baseline / paper-v1 / 000906.SH / mode / replay` 身份条；
2. FORWARD 锚定组合与基准净值、净值差和回撤图；
3. 全账户 BACKFILL/FORWARD 分段审计图；
4. 净资产、现金、市值、累计费用、累计分红与账户日；
5. 实际持仓表：证券、数量、价格日期、市值、实际权重、成本基础、已实现/未实现盈亏、陈旧日；
6. 账户日证据抽屉：该点的模式、净值、基准、回撤、换手、现金比例、费用与产物哈希；
7. 重放摘要和完整证据抽屉。

P3-0 没有暴露订单/成交明细 HTTP 端点，本阶段不得绕过 API 读取文件补齐；界面明确标注该下钻
尚未开放，而不是伪造订单或成交。

### 3.3 股票池/信号

阅读顺序固定为：

1. 信号身份、是否调仓、执行证据状态和下一执行日；
2. 目标数、计划交易腿、实际交易腿、`.BJ` 计数；
3. 主表：排名、证券、目标权重、最近实际权重、计划权重差、目标变化、模型分数；
4. 证券详情抽屉：信号事实、实际权重参照日、执行证据状态和相关哈希；
5. 模型/数据/代码/qlib/信号证据抽屉。

`planned_weight_delta` 是计划差，不是订单或成交。`NOT_DUE` 时不得猜测次日停牌、涨跌停、
真实开盘、成交、换手或成本；缺失值显示“待执行证据”，不显示 0。

## 4. 状态与 fail-closed

已知领域状态固定为：`PASS/WARN/FAIL/STALE/NOT_READY/NOT_APPLICABLE/NO_DATA/OBSERVING/NOT_DUE/NOT_EVALUATED`。
未知状态、缺少必需字段、跨快照、无效数字、证据哈希格式错误，或任一证券代码以 `.BJ` 结尾，
必须形成页面级阻断错误；不得删掉异常行后继续给出正常结论。

请求状态固定为 `loading/refreshing/error/ready`：

- loading 使用结构骨架；
- refreshing 保留旧内容但显式显示原 `generated_at` 与“刷新中”；
- error 显示稳定错误码、请求 ID 与重试按钮，不显示栈、路径或秘密；
- 离线或上游不可用不把缓存标成最新。

状态始终使用图标、文字和颜色三种线索。核心任务与通知状态分列；恢复历史不覆盖先前失败。

## 5. 图表、数字和文案

- 策略使用深蓝实线，基准使用中性灰线；BACKFILL 使用灰色虚线和文本标签，FORWARD 使用
  深蓝实线和文本标签；不使用双 Y 轴、渐变、发光或行情大屏装饰。
- 组合与基准使用同一坐标尺度；净值差有零线，回撤从 0 向下。
- 图表常驻显示观察类型、起止日期、基准、费用口径和执行策略版本，并提供等价数据表。
- RMB 两位小数并带千分位；净值四位；百分比两位且保留正负号；极小非零值不能显示为伪 0。
- 哈希默认显示前 12 位，抽屉显示完整值并允许复制；来源引用只展示后端已脱敏字符串。
- 页面不能使用“有效”“优秀”“盈利能力”等超出后台裁决的文案；当前 FORWARD 仅标
  `OBSERVING`。

## 6. 技术栈与静态边界

前端依赖精确冻结于 `config/p3_web_ui_v1.yaml`，采用 React 19、TypeScript、Vite、Ant Design、
Ant Design Charts、TanStack Query 和 React Router；组件测试使用 Vitest/Testing Library，
浏览器验收使用 Playwright/axe。`package-lock.json` 必须锁定完整传递依赖。

前端源码固定在仓库内 `web-ui/`。Docker 使用固定 digest 的 Node 22 构建阶段，最终静态产物
仍由现有非 root Python `web-ui` 容器提供；运行时不保留 Node/npm、源码、测试或开发依赖。
禁止外部 CDN、远程字体、分析脚本、图像服务和内联脚本/样式。

`web-ui` 只允许以下页面与静态路径：`/`、`/overview`、`/paper`、`/signals`、受控
`/assets/*`、`/healthz` 和既有 API allowlist。任意其他路径返回 404。CSP 至少固定为
`default-src 'self'; script-src 'self'; style-src 'self'; connect-src 'self'; img-src 'self' data:`，
不得使用 `unsafe-inline` 或 `unsafe-eval`。

## 7. 响应式与可访问性

冻结验收视口为 1440×900、1024×768、768×1024、390×844，并增加 320 CSS px reflow 与
400% 页面缩放检查：

- 1440：240 px 左导航、12 栏内容；
- 1024：紧凑侧栏、8 栏；
- 768：单栏主图，表格只在自身容器横向滚动；
- 390/320：顶部移动导航、单列、抽屉全屏，关键内容不隐藏；
- 键盘可跳到主内容，Tab 顺序遵守视觉顺序，Esc 关闭抽屉并把焦点返回触发器；
- 后退/前进恢复路由与 `as_of`；焦点可见，交互目标至少 24×24 px；
- 尊重 `prefers-reduced-motion`，动态刷新只用审慎的 `role=status/alert`；
- axe 的 critical/serious 违规必须为 0；图表提供可聚焦摘要与表格替代。

## 8. 性能与资源预算

- Vite 生产构建不得出现未解释的大包告警；路由必须按页拆分，Ant Design Charts 只在组合页加载；
- 首屏 JS+CSS gzip 合计目标不超过 600 KiB，全部已加载路由资源 gzip 合计不超过 2.5 MiB；
- 本机回环冷启动首次内容可见目标 ≤2 秒，API 超时沿用 P3-0 的 5 秒；
- API 请求失败时不无限重试，手动重试必须可见；
- Web 两容器仍各自限制 384 MiB/0.75 CPU/128 PID，若实测越界则本阶段 NO-GO，不上调生产
  scheduler 资源换取通过。
