## 2. 已交付页面

### 2.1 因子目录

- 首屏如实显示正式因子库 0、已研究因子 10、当前权威 REJECT 8、仅历史因子 2；
- 默认目录只发出一个 catalog 请求，生命周期、研究家族和数据类别在同一响应内筛选；没有通过
  N+1 详情请求补名称、假设或结果；
- 固定按后端“研究家族、因子 ID”顺序，不提供收益排序、综合分、星级、排行榜或最佳因子动作；
- `ADMITTED` 空态明确说明正式库仍为 0，同时允许回到全部研究证据；
- 比较选择限制为 2—3 个当前权威版本，并在 UI 先行约束同一研究家族；后端 fingerprint 仍是
  最终裁判。

### 2.2 单因子 tear sheet

- 分列稳定因子 ID、实验版本、记录判决和当前权威状态；冻结公式按纯文本展示；
- 完整展示十五项 G1 门、全部失败门、研究尝试 N、PIT/shift、复杂度和回看边界；
- 六个 OOS 窗 RankIC 与冻结压力期只画聚合图，并提供紧邻的精确数据表；没有伪造逐日 RankIC、
  IC 分布、月度热力图或分位收益时序；
- 组合增量、成本/滑点压力和因子库相关性均直接读取后端聚合证据；
- 覆盖率、分位收益/单调性、因子自相关、候选池相关性固定显示
  `NOT_EVALUATED · recomputed=false`，浏览器没有补算。

### 2.3 严格比较与准入历史

- 比较保留用户选择顺序，固定 `sorted_by_performance=false`；完整 fingerprint 不一致时返回
  `CONFLICT`，页面清空图表但保留选择以便修正；
- 六窗口、压力期、组合与成本同时提供图表和精确表格；不同因子的压力期集合不一致时前端
  fail closed，不用 0 填补缺失证据；
- 准入历史按账本顺序追加展示，旧 REJECT、历史非权威和被替代版本不覆盖、不删除；
- 历史 `as_of` 常驻当前权威覆盖提示，并在浏览器侧阻断只支持最新权威版本的比较请求。

## 8. 结论与后续边界

P3-3C 使 Web 1.0 从五个运行/决策页面扩展为六类正式页面，并第一次把“因子为何失败”以真实、
可复核且不补算的方式接入本机界面。页面 GO 只证明证据展示和只读工程闭环，不改变正式因子库为
0、当前八个权威候选全部 REJECT 的研究结论。

后续模型/回测页必须先冻结并实现 `experiment_catalog`；不得让浏览器扫描账本补列表。远程访问、
认证、导出、写能力、研究重跑、在线改参、交易和生产控制仍须分别另立目标。
