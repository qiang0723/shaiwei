# M4-1R2A 独立审计失败门顺序补正协议（2026-08-05）

M4-1R2 已按协议补齐 1 条运行账本、3 条决策账本和 manifest；报告及十个 Parquet 哈希均未改变。
独立审计除 `candidate_decisions` 外全部通过，因而尚未披露效果裁决。

唯一缺陷是表示顺序：报告写入使用 `sort_keys=true`，重读后的 `gates` 键按字母排序；
`failed_gates` 数组则保留判定器冻结的评估顺序。两个进入效果分支的候选分别有 4 项和 3 项失败门，
独立重建与报告记录的成员集合、数量及最终决策标签全部一致，但列表顺序不同。失败门集合在方法上无
优先级语义，审计不应把 JSON 映射序列化顺序当作研究门槛。

本补正只允许把审计从“列表顺序完全相同”改为“记录项无重复且成员集合完全相同”，最终决策标签仍
须精确相等。报告、Parquet、账本、manifest、候选、公式、方向、阈值和裁决均不得修改。

闭环运行还暴露出一项纯存储风险：两份预创建CSV表头为LF，Linux容器内`csv.DictWriter`追加的数据
行为CRLF；manifest已经绑定这组真实物理字节，而仓库通用`ledger/*.csv text eol=lf`会在Git入库时
规范化它们，使克隆后的物理哈希失真。本补正因此同时允许在`.gitattributes`中只对这两份已封存
M4账本关闭文本规范化。该措施必须保留当前字节，禁止重写、转换换行符或重发manifest；入库前须证明
Git过滤对象哈希与无过滤对象哈希完全相同。其他账本继续沿用LF规范。

机器协议：`config/m4_star50_residual_effect_audit_order_recovery_v1.yaml`。补丁与新执行 release 均须
先提交推送；新镜像只运行独立审计和既有报告复用幂等，不进行任何研究计算。
