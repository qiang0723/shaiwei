> 本阶段上限：`ENGINEERING_GO_ONLY`

> DeepSeek 调用授权：`false`

> 生产授权：`none`

## 1. 目标和停止边界

D1-3A 的 8 份响应虽然通过 JSON/schema，但有 3 份正文建议替换公式、调整窗口或尝试变体，同时结构
字段声明 `formula_change_or_new_candidate_proposed=false`。本目标只补上这类“结构字段与自由文本相互
矛盾”在宣告机器 GO 前的 fail-closed 工程门。

旧批 `d1-llm-review-v1-batch-001` 的权威终态继续是
`STOP_SEMANTIC_CONTRACT_VIOLATION`。本目标不得重写旧报告、账本或响应，不补发 3 份响应，不递补候选，
不调用 DeepSeek，不读取 W1—W6、压力期、G1、前瞻或生产效果。工程通过也只表示未来新批具备重新
预注册的必要基础，不自动授权新批、人工闸、G1 或生产。

## 2. 冻结的语义门

语义门同时读取结构字段与 `summary`、`findings[].category`、`statement`、
`falsification_or_resolution`，只允许对冻结公式做三类结论：保持原式、拒绝原式、未发现阻断。不得在
正文中提出以下动作：

1. 替换公式、算子或聚合方式；
2. 生成新候选、变体或备选表达式；
3. 调整回看窗口、参数或方向；
4. 改用另一估计量、归一化或风险中性化构造；
5. 声称业绩、准入或生产结论。

确定性扫描器按英文输出合同运行。明确建议上述动作返回 `FAIL_SEMANTIC_CONTRACT`；出现非英文、疑似
新 DSL、无法确认是否为建议的模糊表达，返回 `MANUAL_REVIEW_REQUIRED`。两者都必须在人工闸前停止。
正文只是对抗证据，永远不能由机器解释为候选准入。

允许用显式否定句重申禁令，例如 “Do not replace the frozen formula”；否定只作用于紧邻的动作短语，
不能替整段文本洗白。出现与冻结式不同的完整 DSL 表达式，或出现与冻结回看期不同的 `Nd` 字面量，
无论结构布尔值为何都失败。

## 3. 证据与验收

- 测试必须覆盖：合规拒绝、合规无阻断、直接/条件替换、窗口变体、替代估计量、不同 DSL、否定句和
  非英文模糊文本；
- 已知 3 份违约响应必须被新门识别；其余 5 份即使通过，也不能反向恢复旧批 GO；
- 跟踪证据只保存输入哈希、状态、原因码和计数，不保存自由文本、业绩数字、secret 或绝对路径；
- 相同输入双跑输出与哈希一致；Docker 断网只读验证不得访问 provider；
- 全仓测试、Ruff、compileall、依赖、diff、脱敏检查通过，scheduler 容器/镜像/创建时间不变。

## 4. 未来新批边界

只有本工程门 GO 后，用户另行指令并冻结新批协议，才可发起新的结果盲态复核。新协议必须把该门放在
每份响应的 JSON/schema 之后、追加“有效响应”判定之前；`FAIL` 或 `MANUAL_REVIEW_REQUIRED` 都计入
批次总数且不得补发。旧批 STOP、旧费用和旧 N 永久保留，不得借新门回溯挽救。
