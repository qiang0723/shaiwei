# P3-3C 因子工厂页面协议（结果前冻结）

> 冻结日期：2026-07-26（Asia/Shanghai）
>
> 协议：`p3-factor-factory-ui-v1`
>
> 状态：`FROZEN_BEFORE_IMPLEMENTATION`

## 1. 目标与结论边界

P3-3C 只把 P3-3B 已验收的四组因子查询接成本机只读因子工厂，回答“哪些因子值得继续研究，证据
在哪里失败”。四层结构保留可复核 URL：`/factors` 目录、`/factors/{factor_id}?version=...` 单因子
tear sheet、`/factors/compare?version=...` 严格比较、`/factors/{factor_id}/admissions` 追加式准入
历史。

正式因子库当前为 0、十个研究因子中八个当前权威版本均为 REJECT，是页面第一结论，不是待填充的
占位符。页面允许查看 REJECT 的研究价值与失败门，但不把失败候选包装成推荐，不产生策略有效、
可交易或生产授权结论。

本阶段不修改研究证据、权威覆盖、指标公式、G1、实验账本、策略、模型、信号、生产数据、scheduler
或追加式账本；不提供因子编辑、改方向、改门槛、重跑、导出、文件浏览、远程访问或交易能力。

## 2. 唯一数据源与元数据窄修

页面只允许消费：

- `GET /api/v1/factors`
- `GET /api/v1/factors/{factor_id}`
- `GET /api/v1/factors/compare?version=...`
- `GET /api/v1/factors/{factor_id}/admissions`

前端不得扫描投影、Parquet 或账本，不得逐行补请求来拼目录字段，不得从实验详情推导新指标。
因子详情与准入历史只有在 `snapshot_id` 和 `as_of` 相同后才组合显示；不一致即整组 fail closed。

施工前审计发现 P3-3B 研究响应 `meta.as_of=null`，与既有 `web-v1` 前端日期门冲突。P3-3C 只授权
一个传输元数据窄修：显式 `as_of` 返回规范化后的请求日期；未指定时使用研究投影 `generated_at`
换算到 `Asia/Shanghai` 的日期。该修正不得改变响应 `data`、研究切片、权威状态、判决、快照身份或
哈希输入。

页面不复用“业务数据截至”措辞：研究页把 `as_of` 标为“查询截止”，把 `generated_at` 标为“研究
投影生成”。未指定 `as_of` 时的日期只说明当前投影纳入证据的上界，不冒充市场数据日期。

`factor_compare` 没有历史 `as_of` 口径，只比较最新当前权威版本。因此 URL 指定历史 `as_of` 时，
页面必须禁用比较并解释原因；不得把历史目录/详情与最新比较响应拼接。

## 3. 因子目录与首屏

阅读顺序固定为：

1. 第一视觉焦点：正式库 0 与“尚无通过全部 G1 门的因子”；
2. 四个事实：正式库、已研究因子、当前权威 REJECT、仅历史因子；
3. 生命周期、家族、数据类别三个筛选；默认 `ALL`；
4. 因子 ID、家族、数据类别、阶段、权威状态、当前版本、版本数、实验尝试 N、证据状态和操作；
5. 对比选择与证据说明。

目录保持后端固定的“家族、因子 ID”顺序，不提供收益排序、用户自定义排序、Alpha 综合分、星级、
排行榜或“一键最佳因子”。目录查询没有名称和经济假设字段，首表不得通过 N+1 详情请求补齐；经济
含义在点击后的 tear sheet 展示。`ADMITTED` 筛选返回空时显示“正式库仍为 0”，同时保留返回全部
研究证据的动作。

## 4. 单因子 tear sheet

单因子视图只展示后端已有聚合证据，顺序为：

1. 身份、家族、数据类别、版本、权威状态、冻结公式、经济假设和方向；
2. G1 记录判决、15 项门、失败门和实验尝试 N；
3. PIT/shift、复杂度、回看边界；
4. 六个 OOS 窗 RankIC 与三段压力期最大回撤；
5. 基线/候选净超额、净 ICIR、换手以及成本/滑点压力；
6. 因子库最大相关；
7. 当前缺证据的四块；
8. 追加式准入历史、来源引用和完整哈希。

当前没有逐日 RankIC、IC 分布、月度热力图或分位组合序列，页面不得画伪时序。六窗口与压力期可用
小型图帮助比较，但必须紧邻精确表格。覆盖率、分位收益/单调性、自相关、候选池相关性必须原样显示
`NOT_EVALUATED / recomputed=false`，不由浏览器补算。公式按纯文本渲染，不作为 HTML 执行。

## 5. 严格比较

目录只允许勾选有当前权威版本的因子；2—3 个版本方可提交，同一研究家族在 UI 先行约束，完整
fingerprint 仍由后端作最终裁判。跨宇宙、窗口、horizon、中性化、组合、成本、代码、数据或比较
策略不一致时，响应 `CONFLICT`，比较区不保留旧图或部分结果。

比较保持用户选择顺序，禁止按表现重排。默认展示六窗口 RankIC、压力期回撤、组合增量和成本压力；
图表只帮助发现稳定性和差异，必须提供可展开的等价数据表。比较结论不得压缩成单分、最佳因子或
“推荐上线”。

## 6. 准入历史与历史视图

准入历史按账本顺序展示判决时间、版本、记录判决、权威状态、实验 N、失败门、规则版本及报告/
证据哈希。旧 REJECT、被替代工程版本和历史非权威版本不得删除或覆盖。

使用历史 `as_of` 时常驻 `CURRENT_AUTHORITY_APPLIED_TO_HISTORICAL_RECORDS` 解释：事件按日期裁剪，
但当前权威覆盖仍适用于历史行。这是“按当前知识回看历史证据”，不是当时可用权威状态的重演。

## 7. 导航、响应式与无障碍

桌面侧栏把“因子工厂”从待接入提升到“研究”分组；模型/回测继续禁用。移动底栏按 Web 1.0 基线
收敛为“总览 / 因子 / 组合 / 更多”，“更多”打开现有导航抽屉，承载信号、数据质量和系统运行，
避免六项挤压 390 px 宽度。

1440/1024/768/390、320 CSS px 和 400% 缩放必须无页面级横向溢出；宽表只在自身容器滚动。键盘
可完成筛选、选择、进入/返回详情、对比和证据下钻，焦点返回触发点。状态不可只靠颜色；图表有
文本标题、可访问说明和等价表格；axe critical/serious 必须为 0，reduced motion 继续生效。

## 8. 安全、性能与验收硬门

UI 静态 allowlist 只新增 `/factors`、`/factors/compare` 及严格因子 ID 的详情/历史路径；API
allowlist 只新增固定目录/比较路径及严格匹配：

- `/api/v1/factors/[0-9a-f]{64}`
- `/api/v1/factors/[0-9a-f]{64}/admissions`

因子版本只接受十二位小写十六进制，查询参数由 `URLSearchParams` 编码。GET/HEAD、1 MiB 响应限制、
同源 CSP、零外部资源、无 `.env`/Docker socket/宿主 query 端口、非 root、只读根和 127.0.0.1 绑定
保持不变。

通过必须同时满足：

1. 本协议与机器配置提交、推送早于页面、代理和传输元数据窄修；
2. 类型校验覆盖全部必需字段、十五门、四个 `NOT_EVALUATED`、哈希/日期/数字/状态和 `.BJ`；
3. 正式库 0、REJECT、历史非权威和历史 banner 不被隐藏或误判；
4. 详情/历史同快照，历史模式不调用比较，比较冲突清空旧结果；
5. fixture 覆盖加载、筛选、空态、详情、历史、比较、冲突、刷新、错误、键盘和 axe；
6. 真实页面与 P3-3B 投影逐项对账，外部请求、console/page error 和 CSP violation 为 0；
7. TypeScript、Vite、前端测试/浏览器、全仓 Python、Ruff、compileall、依赖、Compose、脱敏与
   `git diff --check` 全部通过；
8. Web 容器资源与隔离不放宽，scheduler 容器、镜像、创建时间和健康状态施工前后不变。

## 9. 停止条件

若实现需要新增研究指标、逐日序列、目录 N+1 补数、跨快照合并、历史/最新混比、读取原始研究目录、
开放任意代理或放宽 Docker 隔离，立即停止并回主控裁决。不得以视觉完整性为理由填补不存在的证据。
