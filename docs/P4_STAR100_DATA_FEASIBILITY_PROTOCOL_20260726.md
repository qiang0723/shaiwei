# P4 科创100官方谱系与数据可行性协议（结果前冻结）

日期：2026-07-26（UTC+8）  
协议：`p4-star100-data-protocol-v1`  
范围：`official_membership_lineage_and_source_data_gate_only`

## 1. 为什么现在启动

中证800生产主线继续由不可变 scheduler 独立运行，科创50具体基线已经权威 REJECT 并停止；Web
也已在隔离 profile 内完成当前版本。因此现在可以增加一条不接生产、不读取策略效果的新研究线，且
不会等待短期 FORWARD 样本才能开展。

本阶段选择上证科创板100指数，而不是自建“科创300”。科创100有官方代码、发布公告、编制方案和
调整公告，研究对象可明确归因；自建股票池应在官方指数研究成熟后另立构造协议，不能混入本阶段。

## 2. 冻结身份与可用起点

- 指数：上证科创板100指数，`000698.SH`。
- 官方发布公告日：2023-07-21；正式发布日：2023-08-07。
- 编制方案基日：2019-12-31，但基日不是当时可交易、可知的成员事实，禁止据此把策略历史前移。
- 本阶段最早可能的研究可用日固定为 2023-08-07，且只有官方首批100只名单完整时才成立。
- 数据截止日：2026-07-26；最后完整交易日：2026-07-24。

## 3. 官方成员与规则谱系

成员真身只认上交所/中证指数官方材料：

1. 2023-07-21发布公告及其首批样本附件；
2. 从发布公告起至截止日的全部定期与临时调整公告；
3. 启动版编制方案；
4. 2025-02-26修订公告及2025-03-17实施的新版方案。

2025年修订把新股纳入时间从上市满6个月调整为超过12个月，并采用新老样本划断。解析器必须记录
规则版本的生效边界，不得用当前12个月规则解释或重写历史成员事件。

每条成员变化必须绑定公告日、生效日、调出、调入、官方URL、原文哈希、抓取时间和解析器版本；
公告日在生效日之后、缺少成对替换、同批重复或成员数不为100都必须失败关闭。公告若在收盘后生效，
统一在下一官方交易日应用；公告明确起始日的，按该交易日开盘前成员集应用。

## 4. Tushare角色

Tushare只承担两个角色：

- `index_daily`：核验2023-08-07至2026-07-24的指数日线完整性；
- `index_weight`：以2023-08至2026-06共35个完整月的月度成员集合，对官方逐日谱系作二级集合对账。

每个请求串行即时双查，内容不一致不落正式批次。`index_weight`的权重数值不得进入未来等权研究，
其快照日期不得冒充官方生效日；接口缺少发布时间、版本号和修订原因，因此不能单独成为PIT真身。

## 5. 数据质量硬门

- 官方首批名单恰好100只、每日成员恰好100只、成员主键重复为0；
- 官方公告扫描必须越过发布日前边界，范围内每个调整公告都被分类；
- 官方逐日成员与35个月度Tushare集合逐月精确一致，缺月和集合差异均为0；
- 指数日线对官方SSE开市日覆盖100%，重复、非日历日、OHLC/涨跌幅异常均为0；
- `.BJ`、当前成分回填、未来公告回填均为0；
- 原始与派生产物均绑定SHA-256，相同入口复跑不得新增请求或改写产物。

## 6. 裁决语义

全部硬门通过，只能得到：

`GO_OFFICIAL_LINEAGE_AND_SOURCE_DATA_ONLY`

它表示科创100的官方PIT成员与源数据足以进入下一工程协议，不表示数据集/qlib完成，更不表示策略
有效。任一硬门失败得到 `NO_GO`，保留全部证据后停止；不得用当前成分、基金持仓、第三方成分库或
人工补表绕过。

## 7. 本阶段禁止事项

本阶段不构建qlib，不计算特征/IC/收益，不训练模型，不产生排名、选股、信号或回测，不选择TopK、
调仓频率或成本参数；不修改中证800、科创50证据、scheduler镜像、生产配置或Web契约。

如果数据门通过，下一阶段须另立P4-1工程协议。科创50的Top10、`n_drop=2`、10日调仓和LightGBM
配置不自动继承，必须在看科创100效果前重新论证并冻结。
