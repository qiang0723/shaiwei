# TS-v5-R2 四响应合同金丝雀协议

日期：2026-08-13（UTC+8）

状态：`AWAITING_EXPLICIT_USER_APPROVAL`

## 1. 本节点目标

R2只验证已通过工程门的响应合同v2能否在真实DeepSeek API上交付完整、非空、严格Schema JSON；不评价
候选收益，不搜索参数，也不恢复首批12响应。当前先完成scope、请求束、费用、隔离和失败关闭的零调用
预执行门，之后停在真实API调用前等待用户按唯一scope哈希批准。

## 2. 四个固定席位

固定四个独立候选，顺序为：波动自适应回调、周结构分位、突破回踩、均线恢复。没有反方改版，不发送
首批响应或reasoning，不使用候选间反馈。四个完成响应均计数；非法响应不递补，候选失败不重发，只允许
传输层在“尚无已知完成响应”时按既有策略有界恢复。达到四个完成响应立即停止，不得出现第五次调用。

## 3. 响应与停止门

请求显式`thinking=disabled`并省略`reasoning_effort`；仍保留`json_object`、1800 token、无工具、非流式、
原候选Schema和原提示。只有`stop + 非空JSON object + 严格Schema`有效；`length`、空content、非法JSON、
未知结束原因和重复候选均失败关闭。四份必须全部完成；合法唯一候选为0则
`STOP_NO_VALID_CANDIDATES`，至少1份才可`GO_CONTRACT_CANARY_ONLY`。后者也只证明合同可用，不证明策略有效。

## 4. 费用与发送边界

按官方价格和每席位最多16000输入、1800输出计算，四席位全cache miss最坏费用为0.034104美元；本批
硬熔断0.10美元。TS-v5总额度5美元不扩大本批，余额不是执行授权，也不得携带到下一批。

仅发送冻结提示、严格Schema、产品/复杂度约束、公开方法摘要、匿名失败记忆与席位身份。禁止证券、行情、
持仓、订单、信号、收益、封存结果、本地路径、任何凭据、首批原始响应或reasoning。

## 5. 架构与隔离

R2新增能力只允许表达“批次计划与预检”；复用v2请求画像、候选验证、DeepSeek传输、成本和不可变证据。
不得复制live runner或扩张`deepseek_client.py`热点。未来若获批，使用独立输出目录、独立账本和独立镜像，
短命非root、只读根、无端口；只注入DeepSeek key，不挂载`.env`。scheduler、Web和首批证据均不改变。

## 6. 当前权限和验收

当前外部调用、secret读取、费用、行情/效果读取均为0。预执行门须证明：scope字节冻结、4份请求确定性、
v2画像精确、发送边界、最坏成本、无第五席位、异常失败关闭、全仓/架构/脱敏检查和无密钥Docker预检。

通过后权威状态最多为`GO_PREEXECUTION_ONLY`，并向用户交付唯一scope SHA-256。只有用户逐字批准该哈希
及“四响应、0.10美元、无行情效果/回测/生产”的边界后，才允许另立执行release；本指令“继续下一节点”
不是付费API授权。
