## 1. 原 v4B 为什么失败

提交 `eec7315`、镜像 `sha256:7a14fc…e560` 的唯一 v4B 画像已经启动，但在第一份 Parquet 写出前，
DuckDB 将同一条 `COPY` 语句中用于筛选的首个日期参数 `20190102` 解释成输出路径，因容器根目录只读而
抛出 `duckdb.IOException`。失败发生时仅创建了专用目录和空的 `duckdb-tmp/`；事件 Parquet、匿名
日报、报告和审计均不存在，终端没有输出任何事件计数、证券、Alpha分数或收益。

原 release 和失败镜像永久保留，原 scope 不重跑。这是序列化入口缺陷，不是数据门、样本门或策略
结果；不得把它记成密度 STOP/GO，更不得根据尚未出现在证据层的内存计算调整参数。

## 2. R1 只允许改什么

唯一修复是把写出拆成两步：先在 DuckDB relation 中只绑定发现期开始/成熟结束两个日期，再调用
`write_parquet` 传入显式文件路径。新产物写入独立目录
`data/research/trend_swing/ts-v4-density-preflight-r1`，原空目录不删除、不复用。

四臂、相邻关系、2019—2021发现期、末尾16信号日purge、状态机、紧邻下一开盘、30事件/20信号日/
每年5事件/Alpha键100%门槛、输入哈希、结果防火墙和Docker隔离全部逐项继承原 release。新增合成
测试必须真实调用写出函数，以防再次只验证SQL计算而漏掉序列化边界。

## 3. 恢复次数和权限

R1只允许运行一次恢复画像和一次独立审计；原失败计一次序列化尝试，但策略效果尝试仍为0，四个参数
尝试仍为4。R1不得读取收益、Alpha158分数、H00906点位、外网、密钥、模型或回测，不得创建模拟仓、
改Web或生产。即使密度通过，也只允许另立效果 release，且仍受H00906谱系门阻断。
