## 1. 恢复原因与已知信息

F1-0 v1 已产生权威 `NO_GO_F1_FUNDAMENTAL_PIT_DATA_FEATURE_GATE`：101,600 个成员形成日记录中，
有 1 行在形成时点可见的三张报表最新年度报告期不一致。六项覆盖、来源完整性、未来信息和 `.BJ`

v1 的协议、manifest、报告、特征面板、哈希和 `NO-GO` 永久保留。本协议不修改 v1，也不通过容差把
`1` 改成可接受；它只把原先含歧义的跨表 PIT 选择顺序明确为新的 v2 语义。

## 2. 唯一允许改变的变量

v1 先分别选 income、balancesheet、cashflow 在形成日可见的最新年度报告，再要求三个 `end_date`
相同。某张表提前披露下一年度时，即使上一年度三表完整可见，也会使该成员形成日整体失效。

v2 固定为：

1. 每张表先按 `ts_code + end_date`、形成日当时可见性和冻结的修订优先级选出该报告期版本；
2. 三张表按 `ts_code + end_date` 做精确交集；
3. 对每个 `formation_date + ts_code`，从交集中选择不晚于形成日、`end_date` 最大的共同年度报告期；
4. 组合可用日取三张表组件可用日最大值，且必须不晚于形成日；
5. 某张表已经出现更新年度、其他表尚未出现时，只增加 `newer_unmatched_statement_rows` 诊断，继续
   使用此前完整共同年报；不得把不同年度拼成特征，也不得用未来版本回填。

除此之外，股票池、日期、形成频率、八类本地源、公告次日可用、版本优先级、六项公式、分母规则、
覆盖阈值和权限边界逐项沿用 v1。特征 ID 升为 `_v2`，避免与 v1 真身混淆。

- 八类当前本地批次仍须逐文件通过行数和 SHA-256，源身份字段冲突为 0；
- 质量期至少 90 个形成日，每期中证800成员 700—900，只，`.BJ=0`；
- 实际构造的跨表混期行为 0，未来可用行为 0；质量期没有共同年度报告期的成员形成日为 0；
- 六项特征总覆盖率各不低于 90%，任一形成日最差覆盖率各不低于 80%；
- 同一冻结输入双跑的新特征、报告和 manifest 必须逐内容同哈希。

`NO_GO_F1_FUNDAMENTAL_PIT_RECOVERY_DATA_FEATURE_GATE`。不得因只差少量记录而改门槛。
