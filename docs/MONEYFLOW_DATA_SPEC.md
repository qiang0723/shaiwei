状态：2026-07-23 冻结为 P1 数据可用性基线；2026-07-24 在全历史回填后新增
`moneyflow-quality-v2` 整日隔离规则。本文只授权隔离研究，不改变生产模型、信号、门禁、调仓规则
或 scheduler。

## 2. 冻结粒度与 schema

主候选唯一键为 `(ts_code, trade_date)`，一行表示数据商对一只证券一个交易日的资金流分类。原始层不做证券代码猜测映射、不截尾、不填补、不残差化。

`tushare.moneyflow` 精确字段顺序：

```text
ts_code, trade_date,
buy_sm_vol, buy_sm_amount, sell_sm_vol, sell_sm_amount,
buy_md_vol, buy_md_amount, sell_md_vol, sell_md_amount,
buy_lg_vol, buy_lg_amount, sell_lg_vol, sell_lg_amount,
buy_elg_vol, buy_elg_amount, sell_elg_vol, sell_elg_amount,
net_mf_vol, net_mf_amount
```

- `*_vol` 单位为手；`*_amount` 单位为万元。
- 基础接口的买/卖字段是双边分桶，八组买卖金额或成交量合计约为官方日成交额/量的 2 倍。
- 官方口径将小/中/大/特大单按订单金额分档；它是数据商基于主动买卖和 L2 订单的定义。
- `net_mf_vol`、`net_mf_amount` 不允许由八个分桶自行重算；官方明确说明其 L2 计算口径不能用分桶简单加减替代。

同花顺接口的实际冻结字段使用 `buy_lg_amount_rate`、`buy_md_amount_rate`、`buy_sm_amount_rate`。这些 `buy_*` 字段表示分档**净流入**，允许为负；不能按基础接口的 gross buy 规则校验。东财的分档金额与占比同样允许有符号。

## 3. PIT 与最早可用时点

冻结策略为 `moneyflow-pit-v1`：

- 当日 19:30 稳定可用性：`UNPROVEN`。
- 最早进入特征的时点：下一官方交易日。
- 研究实现必须按交易日 `shift(1)`；D 日信号最多使用 D-1 及更早的资金流。
- 2026-07-23 22:35（UTC+8）三类接口均能返回当日数据，只证明该晚间时点可用，不能倒推 19:30 已稳定。
- 将来即使积累了多日 19:30 观测，也只能经新版本 PIT 裁决升级；不得静默回改 v1 或重写历史实验。

这一路径遵循路线图的保守条款：无法证明同日发布时间时，统一按下一交易日可用处理，因此当前无需等待才能安全开展隔离实验。

## 4. 采集与修订纪律

- 所有请求按 `trade_date` 单日分区，并显式提交冻结字段列表。
- 每个响应写入新的 Parquet、内容 SHA-256 和 `ledger/ingest_batches.csv`；禁止覆盖旧批次。
- 默认执行按规范化请求参数和完整哈希跳过已提交批次，保证幂等。
- 只有显式 `--refresh` 才允许为同一请求追加新快照；旧、新快照均保留，用于发现历史修订。
- Tushare 单次 6000 行上限在北交所过滤**之前**检查；触顶即失败，防止过滤后低于上限而掩盖截断。
- `.BJ` 在原始入账边界排除；任何已提交批次出现 `.BJ` 均 fail closed。
- 本采集器位于 `tools/p1_moneyflow/`，明确排除在当前生产代码快照之外，不在生产 scheduler 中自动运行。这样新增研究能力不会让既有模拟仓 FORWARD 产物因无关代码变更失效；未来若批准生产集成，必须另立目标并生成新的受控快照与前瞻证据。

默认幂等复核示例：

```bash
.venv/bin/python -m tools.p1_moneyflow.candidate \
  --trade-date 20260723 --api moneyflow \
  --report logs/moneyflow/<new-evidence-name>.json
```

## 5. 主候选质量门

每个交易日同时满足以下条件才为 `PASS`：

1. 精确 schema，无缺列或额外列；交易日与请求一致。
2. `(ts_code, trade_date)` 无空键、无重复键。
3. `.BJ=0`，数值可解析且有限；基础接口 gross 买卖分桶不得为负。
4. 相对 `tushare.daily` 当日代码覆盖率不低于 99.5%。
5. 主源无当日行情的额外代码比例不高于 0.5%。
6. 双边分桶金额与成交量相对日行情的中位比例均在 `[1.9, 2.1]`。
7. 同参数刷新如出现不同内容哈希，标记 `REVISION_OBSERVED` 并暂停后续实验裁决。

`net_mf_*` 相对日成交额/量的极端比例只作结构化 warning，不修改原始数据。截尾、标准化及 winsorization 只能在后续预注册因子实验的派生层实施。

## 6. 代码变化与缺失语义

历史样本存在数据商代码回溯口径差异，例如旧代码与当前代码在 `moneyflow` 和 `daily` 中可能采用不同标识。v1 不凭名称或收益轨迹猜测映射：

- 质量报告分别输出 `source_only` 和 `daily_only`。
- 后续因子表仅在可验证交集上构造；未匹配记录按缺失处理。
- 若未来建立代码别名表，必须来自可审计的权威变更证据，并作为独立版本化数据集，不回写原始批次。

## 7. 授权边界

通过本规范只表示数据层 `GO_DATA_ONLY`，允许下一目标开展独立增量因子实验。它不表示资金流有效、不表示通过 G1，也不授权入生产模型、生成正式信号或展示为已验证因子。

## 8. 全历史缺档与整日隔离（moneyflow-quality-v2）

2026-07-24 在任何资金流收益、RankIC 或 W1—W6 增量结果生成前完成 2016—2026 全历史回填。
2563 个官方交易日中，2517 日通过上述单日质量门，46 日失败；其中 36 日的买卖分桶金额与成交量
相对日行情的市场中位比例同时低于 `[1.9,2.1]`，12 日覆盖率低于 99.5%，1 日额外代码比例高于
0.5%（部分日期同时失败）。对全部 46 日显式刷新后内容哈希均未变化、历史修订为 0，确认是稳定的
供应商历史缺档，不是瞬时网络空响应。

v2 不修改 v1 的任何单日阈值，也不把失败日降为 PASS；处理方式固定为：

- 失败源日整日隔离，六个候选一视同仁；禁止只删异常股票、截尾修补或依据因子表现选择保留日期。
- 隔离日不填 0、不前填、不后填；任何 5/10/20 日滚动窗只要包含隔离日就保持缺失。
- 全期、2016—2018 发现期及每个 W1—W6 的有效源日比例均须不低于 95%；三个冻结压力期分别不低于
  90%；连续隔离日不得超过 10 个交易日。任一条件失败则不生成候选面板。
- 隔离清单、逐日失败原因、刷新证据、代码/数据/规则哈希必须绑定到派生面板；未来源数据修订不得
  回写旧结论，必须创建新质量版本和新实验家族。

该升级只决定“稳定缺档如何作为缺失处理”，不改变 G1、成本、调仓、候选公式或任何收益门槛。
