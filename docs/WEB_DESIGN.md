# 筛微 Web 1.0 初始设计基线

> 状态：v1.0，2026-07-23 经用户确认并完成主控架构复核，冻结为 Web 1.0 初始设计基线。2026-07-25 P3-0 已完成只读查询与隔离 Docker，P3-1 已完成总览、模拟组合和股票池/信号三个正式页面；设计与首版验收均不授权交易、写后台或远程开放。
>
> 设计真身：本文件 + `WEB_METRIC_DICTIONARY.md` + `WEB_QUERY_CONTRACTS.md` + `WEB_WIREFRAMES.md` + `WEB_RESEARCH.md` + `WEB_ARCHITECTURE_RULINGS_20260723.md`。

## 1. 冻结结论

Web 1.0 是单用户、只读、证据优先的专业因子工厂与量化决策台，不是交易终端，也不是通用 BI。它既要交付当前结果，也要完整呈现因子从研究假设到准入、组合和前瞻验证的生命周期。默认页必须在不操作筛选器时回答：

1. 数据与运行证据是否完整、是否新鲜；
2. 策略结果是否具备可解释的有效性证据；
3. 今天是否调仓、有哪些执行风险或异常需要处理。
4. 哪些因子正在研究、为何通过或拒绝、是否真正提供独立增量。

首期实现顺序冻结为：**总览 → 模拟组合 → 股票池/信号**。模型/回测、数据质量、系统运行完成信息架构和契约设计，但只有在相应只读查询落地后才接真实数据。

当前后台事实：

- 既有 Python 查询仍保留；P3-0 已提供原子总览、模拟组合、FORWARD、重放、最新信号和次日对账 HTTP 只读契约，P3-1 已严格复用这些契约形成三个本机正式页面。
- `paper_forward_acceptance` 仍是生产机器验收入口；Web 查询不替代生产裁判，也不核发策略有效性。
- 实验、数据质量、完整系统运行和因子工厂页面查询仍是需求提案，不把它们写成已存在能力；P3-1 的禁用导航只表示规划位置，不表示后台接口已完成。
- 四日 `BACKFILL` 只作工程与账务证据；当前 2 个自然 `FORWARD` 观察日仍为 `OBSERVING`，禁止年化、Sharpe、信息比率或策略有效性结论。

## 2. 产品边界

### 2.1 用户与使用节奏

首版面向项目所有者本人，主要场景是交易日收盘后复核、次日开盘前确认、异常时下钻。默认时区为 `Asia/Shanghai`，显示交易日与生成时间；UTC 只在证据详情中保留。

### 2.2 允许

- 查看已登记信号、模拟账户、回测、门禁、运行和证据摘要；
- 在统一 `as_of` 范围内筛选和下钻；
- 复制证据 ID、哈希和只读来源引用；
- 导出当前视图的脱敏 CSV/JSON，前提是后端另行提供经过授权的只读导出契约。

### 2.3 禁止

- 下单、连接券商、在线改参、重跑任务、修数、修改门禁或确认告警；
- 浏览器直读 Parquet、CSV 账本、生产目录或任意 SQL；
- 把目标权重显示成实际持仓，把 BACKFILL 显示成前瞻业绩，把缺失显示成 0；
- 读取或显示 `.env`、token、Webhook、签名、完整敏感路径；
- 展示或接纳 `.BJ` 证券；若查询返回 `.BJ`，页面必须 fail closed；
- 用 Figma、外部分析工具或前端状态反向定义指标口径。

## 3. 导航与页面任务

桌面端左侧一级导航固定为七页，移动端改为“总览 / 因子 / 组合 / 更多”。首期代码优先级仍维持“总览 → 模拟组合 → 股票池/信号”，因子工厂先冻结页面和查询契约，待后台只读契约落地后接真实数据。

| 顺序 | 页面 | 默认要回答的问题 | 主要下钻 |
|---:|---|---|---|
| 1 | 总览 | 今天可信、有效、要行动吗 | 组合、信号、失败步骤、证据抽屉 |
| 2 | 因子工厂 | 因子为何成立、处于哪一阶段、是否有独立增量 | 因子 → tear sheet → 实验 → 准入记录 |
| 3 | 模拟组合 | 实际成交后账户发生了什么 | 净值点 → 账户日 → 订单 → 成交 → 证据 |
| 4 | 股票池/信号 | 为什么入选，是否需要调仓，能否执行 | 股票 → 排名/目标 → 对账/限制原因 |
| 5 | 模型/回测 | 哪个模型、哪些窗口、什么结论 | 实验 → 窗口 → 指标/参数/产物 |
| 6 | 数据质量 | 数据覆盖和门禁是否可信 | 哨兵 → 异常 → 批次/哈希 |
| 7 | 系统运行 | 哪一步失败，核心任务与通知是否分离 | 周期 → 步骤 → 通知尝试/恢复 |

全局仅保留三个高价值控件：`as_of`、账户（首版锁定 `model_baseline`）、证据抽屉。页面内筛选器不跨页面持久化，避免隐性口径漂移。

### 3.1 视觉设计总原则

Web 1.0 的视觉目标冻结为“专业、安静、清晰、有重点”，不能以信息密度或装饰效果冒充专业感：

1. **好看但不抢内容**：用准确对齐、稳定栅格、字体层级、留白和细节质感建立专业感，不依赖渐变、发光、大面积高饱和色或行情大屏装饰。
2. **信息展示合理**：一屏先结论和行动，再到结果、原因和证据；一个组件只承担一个主要问题，独立指标不塞进同一张卡。
3. **表达科学**：图形、基准、分母、时间范围和空值语义必须正确；相同指标跨页面使用同一名称、精度、颜色和尺度规则。
4. **重点明确**：重点由位置、面积、字级、字重、对比和留白共同建立；颜色只作辅助。每个页面只允许一个第一视觉焦点、最多两个第二焦点。

阅读顺序冻结为左上到右下的 `结论 → 行动 → 结果 → 诊断 → 明细 → 证据`。如果一个模块不能改变判断、解释变化或支持追溯，就不进入默认视图。

## 4. 信息优先级与 KPI 模型

### 4.1 总览层级

首页不固定凑四张 KPI 卡，按决策层级组织：

1. **结论与时点**：综合状态、最新有效交易日、证据生成时间；
2. **行动**：是否调仓、信号状态、计划交易腿、执行证据状态和执行后的实际交易腿；
3. **结果**：以后一个 BACKFILL 账户日为锚的模拟仓 FORWARD 累计净值差，紧邻基准、费用、回撤和观察类型；
4. **诊断**：现金比例、成交率/不适用、换手、数据/任务/通知异常；
5. **证据**：策略版本、代码/数据/信号/产物哈希和重放状态。

### 4.2 主指标、驱动与护栏

| 角色 | 指标 | 决策用途 |
|---|---|---|
| 主结果 | FORWARD 锚定后的扣费净值差 | 判断模拟策略相对中证800的真实前瞻结果；必须以最后一个 BACKFILL 账户日为锚，无 FORWARD 时 `NOT_READY` |
| 主结果 | 最大回撤 | 防止收益脱离风险展示；必须与同一观察范围一致 |
| 行动 | 调仓状态 | 决定是否进入信号与执行检查 |
| 驱动 | 实际成交率 | 解释目标为何没有转化为实际持仓；无交易腿时 `NOT_APPLICABLE` |
| 驱动 | 现金比例/现金拖累 | 解释交易单位、受阻买入对配置结果的影响 |
| 护栏 | 数据/证据新鲜度 | 过期或断链时禁止给出正常结论 |
| 护栏 | 账本重放状态 | 重放非 PASS 时组合数字不可作为可信结果 |
| 护栏 | `.BJ` 计数 | 必须为 0；非 0 直接 FAIL |

完整机器名、公式、粒度、单位、空值和来源见 `WEB_METRIC_DICTIONARY.md`。

## 5. 页面冻结规格

### 5.1 总览

从上到下：

- 状态横幅：综合状态、短原因、`as_of`、生成时间、最近完整证据；
- 今日行动：调仓/非调仓、信号日期、下一执行日、目标数、交易腿；
- 模拟组合结果：审计图可分段展示全账户组合与中证800净值；主结果必须使用最后一个 BACKFILL 账户日锚定的 FORWARD 专属序列，副图为同范围回撤；显著标注 `BACKFILL`/`FORWARD`；
- 执行与风险：实际持仓数、现金比例、成交率/不适用、累计费用、当前回撤；
- 证据链时间线：数据 → 门禁 → qlib → 模型 → 信号 → 对账 → 模拟仓 → 重放；
- 异常清单：只显示需处理或解释的异常，任务状态与通知状态分列。

总览必须来自同一一致性快照。`overview_snapshot` 未落地前，总览只能用明确标注的示例数据做原型，不能由前端并发拼接多个生产查询。

### 5.2 因子工厂

因子工厂使用“目录 → tear sheet → 对比 → 准入历史”四层结构，不用单一分数代替研究判断。

**因子目录**：

- 生命周期分组：`CANDIDATE / TESTING / REJECTED / ADMITTED / RETIRED`；状态必须来自冻结裁判或实验账本，前端不能改；
- 表格主列：因子 ID、名称、研究家族、经济假设、数据类别、表达式/实现版本、样本范围、最新判决、失败门、实验尝试 N、更新时间；
- 默认不按收益排序，优先按状态、更新时间和证据完整性组织；正式因子库为 0 时如实显示空态，并展示当前 REJECT 研究证据入口；
- 筛选只保留生命周期、研究家族、数据类别、判决和版本，避免构造“找最好看结果”的自由筛选器。

**因子 tear sheet** 从上到下固定为：

1. 身份与假设：因子定义、经济含义、输入字段、可用时点、方向、版本和代码/数据哈希；
2. 结论与门禁：G1 总判决、15 项门结果、失败原因、实验总账 N；
3. 数据健康：覆盖率、丢失率、极值、股票数、日期范围、PIT/shift、行业/市值中性化状态；
4. 预测能力：日频 RankIC 时序与滚动均值、IC 分布、月度 IC 热力图；
5. 经济单调性：分位数组合收益、Top-Bottom spread 及置信区间，只使用冻结 forward horizon；
6. 稳定性：六滚动窗口、三段压力期、行业/市值分组结果；
7. 可交易性：因子自相关、Top/Bottom 分位换手、组合换手和成本敏感性；
8. 独立性：与既有库、候选池和基线暴露的相关矩阵及阈值；
9. 增量结果：入库前后组合净 ICIR、净超额、回撤和成本变化；没有正式准入时显示 `NOT_APPLICABLE`；
10. 证据：实验、候选、判决、产物和账本哈希。

**因子对比**最多同时选择 3 个因子。只有宇宙、日期、forward horizon、中性化、成本和版本一致时才能并排；不一致时拒绝比较，不用前端转换制造可比性。

**禁止的展示模式**：

- 不提供单一“Alpha Score”、星级、排行榜或一键最佳因子；
- 不只展示累计收益而隐藏 IC 分布、换手、相关性、压力期和失败门；
- 不隐藏无效候选、失败尝试或实验总账 N；
- 不把 WorldQuant/Alphalens 等平台的指标阈值直接当成筛微 G1；
- 不允许在页面内改表达式、参数、方向或门槛后立即看结果。

本页当前无 Web 查询契约；正式因子库为 0 也是重要事实，不得用示例因子伪装为已准入。

### 5.3 模拟组合

默认视图为 `model_baseline`：

- 身份条：账户、`paper-v1`、基准 `000906.SH`、观察类型、最新账户日、重放状态；
- 结果区：全账户归一化净值与基准同图只作审计；FORWARD 主图以最后一个 BACKFILL 账户日重新锚定，前瞻净值差和回撤使用同一范围；
- 会计区：净资产、现金、市值、累计费用、累计分红、账户恒等状态；
- 持仓表：证券、数量、成本基础、收盘价日期、市值、实际权重、已实现/未实现盈亏（仅有可靠字段时）；
- 执行区：订单数、成交数、成交率、未成交原因、费用；
- 下钻：净值点打开账户日抽屉，按“订单 → 成交 → 公司行为 → 持仓 → 现金 → NAV”展示不可变事件。

目标权重、计划数量和实际持仓必须并列命名；未实现接口提供目标权重前，不在持仓表伪造该列。

### 5.4 股票池/信号

- 信号身份：信号日期、生成时间、模型/数据/代码/信号哈希、是否调仓；
- 结论摘要：目标数、相对上期新增/保留/移除、预计交易腿；
- 主表：排名、证券、目标权重、上期实际权重、权重差、流动性、状态、执行提示；
- 可成交性：停牌、方向性涨跌停、交易单位、缺失行情等必须按来源时点标注；
- 因子贡献：只有确定性、可审计的贡献分解接口存在时展示，否则显示“暂无可审计贡献分解”。

本页查询尚未实现，所有字段均需后端以一个信号身份返回；前端不得自行扫描 manifest、对账账本或行情。

### 5.5 模型/回测

- 先展示判决与实验身份，再展示收益；失败实验不隐藏；
- 六滚动窗口用小倍图或点图展示每窗扣费超额，避免只看合并曲线；
- 策略与基准使用同一归一化起点；回撤单独绘制；成本基准、+50%、+100% 分场景，不混成一条不明曲线；
- 展示训练/验证/OOS 日期、模型参数、数据/代码/模型/产物哈希；
- BACKTEST、SHADOW、PAPER 三类结果在视觉和标签上强制区分。

### 5.6 数据质量

- 首页卡只显示最新交易日、S1-S10 汇总、异常数、`.BJ` 排除数、最新批次和重哈希结果；
- 哨兵矩阵显示状态、覆盖对象、阈值/规则版本、异常数、运行时间；
- 下钻到异常清单和脱敏来源引用；不提供“忽略”“修复”“重跑”按钮；
- 合法空、未适用、无数据和失败必须是不同状态。

### 5.7 系统运行

- 周期时间线按实际执行顺序展示核心任务步骤；
- `task_status` 与 `notification_status` 分列，通知失败不能覆盖核心任务 PASS；
- 通知按 `message_id` 聚合尝试，同时保留每次 attempt、错误类型、retryable、recovered 和重复消息风险；
- 原始日志只在后端脱敏并授权后提供；首版默认展示结构化摘要。

## 6. 状态与错误语义

### 6.1 领域状态

| 状态 | 含义 | 页面行为 |
|---|---|---|
| `FAIL` | 必需步骤失败、哈希不一致、账本断链或禁入数据 | 红色文字+图标；显示首个失败点；禁止正常结论 |
| `STALE` | 已过数据时钟但没有最新完整证据，或估值超过允许陈旧度 | 橙色文字+图标；显示滞后交易日/字段 |
| `WARN` | 主流程可用但有非阻断异常，例如通知失败 | 黄色文字+图标；任务和通道分列 |
| `NOT_READY` | 正式观察期或验收条件未满足 | 中性进度；不得显示为失败或收益结论 |
| `NOT_APPLICABLE` | 当前场景无分母或检查不适用 | 显示“不适用”与原因，不显示 0% |
| `NO_DATA` | 查询范围没有登记证据 | 空态；不补零、不沿用上次值 |
| `PASS` | 同一范围必需证据完整且通过 | 克制的成功状态，始终显示时点和证据入口 |

综合优先级冻结为 `FAIL > STALE > WARN > NOT_READY > PASS`。`NO_DATA` 和 `NOT_APPLICABLE` 是否提升综合状态只能由查询契约返回，前端不得推理。

### 6.2 UI 请求状态

- `loading`：保留结构骨架，不显示旧数字冒充当前请求；
- `empty`：显示查询范围、空值原因和可返回动作；
- `partial`：仅当后端明确返回 `PARTIAL` 与缺失清单时展示；当前契约没有此状态，前端不能自行降级；
- `error`：显示稳定错误码、请求 ID、可重试按钮；不显示堆栈、路径或秘密；
- `offline`：说明无法取得新证据；不把本地缓存标成最新；
- `refreshing`：旧数据可见但加“正在刷新”和原 `generated_at`，刷新失败保留旧数据并明确过期。

## 7. 金融图表规范

1. 策略与基准统一从所选范围首日归一化为 1；不得用双 Y 轴制造相对表现错觉。
2. 净超额使用独立零基线图；回撤以 0 向下绘制并显示峰值、谷底、恢复日（有数据时）。
3. 每张收益图常驻显示：观察类型、起止日期、基准、费用口径、执行策略版本。
4. BACKFILL 使用灰色虚线/淡区间，FORWARD 使用主色实线；颜色之外同时使用线型和文本。
5. 缺口保持缺口，不前填；停牌估值沿用仅在后端已按冻结政策产出时展示，并标 `STALE` 天数。
6. 成交率用分子/分母文本配合条形图；无交易腿时显示 `NOT_APPLICABLE`。
7. 未成交原因用排序条形图，避免饼图；持仓/行业贡献使用正负发散条形图，零线明确。
8. 六窗口稳定性使用小倍图或点图；不只展示合并累计值。
9. K 线只用于单股价格、成交量与信号/成交事件定位；不进入总览。首版若无必要，不引入 Lightweight Charts。
10. Tooltip 同步显示日期、策略、基准、净超额、回撤和模式；键盘用户必须获得等价表格或数据摘要。

## 8. 响应式与可访问性

目标为 WCAG 2.2 AA；图表同时提供可聚焦摘要和可下载/可读表格替代。

- ≥1440 px：固定 240 px 导航，12 栏内容，核心图 8 栏、诊断 4 栏；
- 1024–1439 px：折叠导航，8 栏；两栏卡片；
- 768–1023 px：单栏主图，表格保留关键列并允许容器内横向滚动；
- 320–767 px：单列，顶部四项导航；详情用抽屉全屏；复杂图默认显示摘要和“查看图表”；
- 非二维必要内容在 320 CSS px 宽度可单向滚动；宽表的横向滚动限制在表格容器内；
- 正文/关键数值对比度至少 4.5:1，大字至少 3:1；状态不能只靠颜色；
- 所有操作可键盘完成，焦点清晰；交互目标至少 24×24 CSS px，常用操作目标 36×36 以上；
- 动态刷新用 `role=status`，阻断错误用审慎的 `role=alert`；避免频繁播报；
- 尊重 `prefers-reduced-motion`，数值与曲线刷新不使用连续跳动动画；
- 哈希、证券代码和数值使用等宽数字；中文标签不依赖缩写，图标均有可读名称。

### 8.1 视觉系统候选

- **主题**：首版默认浅色主题；白色内容面配冷灰页面背景，保证日间长时间阅读。暗色主题不进入首期，避免双主题拖慢口径与可访问性验收。
- **栅格**：8 px 基础间距；内容最大宽度 1600 px；12 栏桌面栅格。卡片内部留白不小于 20 px，模块垂直间距不小于 24 px。
- **字体**：中文优先系统无衬线字体；正文 14–16 px，辅助信息 12–13 px；页面标题 24 px；关键结论 28–36 px。金额、比例、日期和哈希启用 tabular numbers。
- **色彩角色**：策略主线使用深蓝，基准使用中性灰，净超额负值/回撤使用克制的橙红；PASS/WARN/FAIL 使用独立状态色并始终伴随文字和图标。证券涨跌不沿用状态色逻辑。
- **表面**：低对比边框和极轻阴影，只用于区分层级；不让每张卡都像可点击按钮。可点击区域必须有悬停、焦点和按下反馈。
- **数字**：关键数字右对齐或按小数点对齐；同组保留一致小数位。金额默认带千分位，百分比明确正负号，极小值不以 `0.00%` 掩盖。
- **文案**：卡片标题直接描述问题或指标，例如“前瞻净超额”“是否需要调仓”，避免“数据概览”“综合分析”等空泛标题。

### 8.2 视觉重点控制

- 顶部状态横幅只突出一个综合结论和一个行动句；哈希、版本等身份信息降为次要层。
- Hero 区最多包含一个主结果图和一组紧密相关的护栏指标；不使用六张等权 KPI 卡制造“每项都重要”。
- 异常存在时，异常取代正常趋势成为第一焦点；正常状态只做克制确认。
- 表格通过列顺序、固定关键列、数值对齐和异常行标记突出重点，不用整行高饱和底色。
- 详情、方法和证据默认收进抽屉或折叠区，但状态原因、基准、费用、时间范围不得折叠。

## 9. 技术栈基线与施工前裁决

### 9.1 前端

- React + TypeScript + Vite；
- Ant Design 作为布局、表格、筛选、状态、抽屉和可访问交互基座；
- Ant Design Charts 作为唯一通用图表层；首版不同时引入 ECharts；
- TanStack Query 管理只读请求、新鲜度和取消；不使用全局状态拼接业务口径；
- Vitest + Testing Library 做组件/状态测试，Playwright + axe 做关键路径、响应式和无障碍验收。

版本号在代码目标启动时基于锁文件单独冻结；本设计不预先声称仓库已安装上述依赖。

### 9.2 只读查询适配层（需求提案）

建议以 Python FastAPI 建独立、无业务计算的只读适配层：只调用冻结查询函数，负责参数校验、统一响应包络、错误码、脱敏、限流和缓存头。它不得读取 `.env` 中与展示无关的秘密，不得开放任意路径或 SQL，不得把多个不一致快照拼成 PASS。

主控已于 2026-07-23 接受此选型，但附加硬边界：查询服务不继承生产 Compose 公共锚点、不加载 `.env`、不挂项目根目录，只挂 allowlist 子路径为只读；根文件系统只读、非 root、移除 capabilities、无 Docker socket、无宿主机查询端口。详细裁决见 `WEB_ARCHITECTURE_RULINGS_20260723.md`。

该适配层尚不存在，须由主控另立后台提案并评审。若主控不接受新增 HTTP 层，则前端施工暂停，不能以浏览器直读文件替代。

### 9.3 Docker 隔离边界

当前 `compose.yaml` 只有 `shaiwei` 与 `scheduler`，Web 设计不得修改或重启它们。后续代码目标建议：

- 新增独立 `web-query` 和 `web-ui` 服务，放入显式 `web` profile，默认 `docker compose up scheduler` 不启动 Web；
- `web-query` 只读挂载经批准的产物/账本路径，应用目录和数据目录均不可写；不得挂 Docker socket；
- `web-ui` 只访问 `web-query`，不访问生产卷；
- 查询服务设置 CPU/内存限制、并发上限、超时和只读健康检查；
- 端口默认仅绑定 `127.0.0.1`；任何局域网或公网暴露需另行授权和认证设计；
- 构建、启动、停止和健康检查均使用独立命令，不影响 scheduler 网络、容器或健康状态。

由于 Compose 启用 profile 时仍会纳入未设置 profile 的服务，Web 启动命令必须显式点名 `web-query web-ui`；禁止使用裸 `docker compose --profile web up`。两个 Web 服务不得继承现有带 `.env` 和整仓可写挂载的 `x-shaiwei-common`。

## 11. 验收清单

- 七页均有默认问题、主指标、下钻路径、空态和错误态；因子工厂具备目录、tear sheet、对比和准入历史四层结构；
- 首页不交互即可辨别 `BACKFILL`/`FORWARD`、数据时点、任务/通知状态和行动结论；
- 所有收益同时出现基准、成本、回撤、范围和观察类型；
- 目标、订单、成交、实际持仓、现金互不混淆；
- 已实现查询与需求提案明确分层，前端不自由拼账本；
- `.BJ` 返回即失败，不进入任何表、图或统计；
- 状态不只靠颜色，键盘、焦点、reflow、状态播报和图表替代满足约束；
- Web profile 默认关闭，未触碰 scheduler 和生产服务；
- 原型、示例数据和设计文件全部在仓库内可审计。
- 5 秒扫视能指出页面结论、是否需行动和最新数据时点；15 秒内能找到主要原因和下钻入口。
- 每页只有一个第一视觉焦点；主图、卡片和表格不存在无业务作用的装饰元素。
- 关键数字的名称、单位、精度、时间范围、基准和状态跨页面一致；图表与明细表可对账。

## 12. 主控架构裁决（2026-07-23）

七项提案已经完成主控裁决，权威全文见 `WEB_ARCHITECTURE_RULINGS_20260723.md`：

1. 接受后台原子 `overview_snapshot`；系统、证据、表现观察和通知状态分列；
2. 接受 FastAPI 只读适配层与独立 `web` profile，但必须与生产秘密、写卷和宿主查询端口隔离；
3. `latest_signal` 只返回信号时点事实和计划交易腿；真实可成交性只能在执行日后由对账契约返回；
4. 接受实际权重和未实现盈亏的查询投影；估值陈旧天数直接复用现有 `stale_trade_days`；
5. FORWARD 主结果以最后一个 BACKFILL 账户日为锚；252 日后才允许年化描述，504 日且至少 40 个调仓周期后才允许展示经序列相关修正的风险调整指标，720 日仍由 G8 独立裁决；
6. 原则接受脱敏只读导出，但首期后置并使用字段/范围/行数 allowlist；
7. 接受四组因子工厂查询设计，正式库为 0 时只做原型，后台契约另行施工。

## 13. 冻结后的受控演进

v1.0 冻结的是可实施基线，不封闭后续调研和优化。联网调研、设计观察和第一版实现后的真实反馈按以下规则处理：

1. **调研可持续**：继续核查专业因子研究、实验追踪、风险归因、金融工作台、无障碍和前端工程的官方资料；每项必须记录来源、借鉴点、不照搬点和对筛微的影响。
2. **专项统一承接**：Web 设计出现明确调研问题时，统一交由“Web 1.0 专项审计”只读核查并回传证据、发现、适用边界和变更提案；主窗口负责裁决与施工，不重复扩散调研。没有明确决策问题时不定时巡游、不频繁启动专项。
3. **冻结口径不静默变化**：专项发现先记入 `WEB_RESEARCH.md` 的观察区或独立变更提案，不直接修改生产代码、后台契约、指标公式、状态语义或页面主任务。
4. **优先完成可用版本**：不会因持续追逐竞品功能而阻塞已裁定版本；与当前决策无关的先进能力进入 v1.1 候选池。
5. **实现后用证据优化**：第一版 Web 完成后，依据任务完成时间、误读点、下钻深度、空态/错误态、真实数据密度、渲染性能、响应式和无障碍测试进行复盘。
6. **改版需可归因**：每轮只解决明确问题，记录“问题 → 证据 → 设计变化 → 验证结果”；不以主观“更高级”或截图相似度作为升级依据。
7. **版本边界**：不改变数据/指标/契约的视觉微调可进入 v1.0.x；改变页面任务、指标、状态机或查询契约的设计进入 v1.1 评审；生产边界变化另立目标。

第一版实现后的最低复盘问题：

- 用户能否在 5 秒内识别结论、行动和时点；
- 是否有人把 BACKFILL 当成 FORWARD、把目标当成持仓或把通知失败当成任务失败；
- 因子 tear sheet 是否能在不查看原始产物时解释通过/拒绝及独立增量；
- 图表与表格是否对账，筛选后是否仍保留范围、基准、成本和版本；
- 1440/1024/768/390 px 与 400% 缩放下是否保留关键内容；
- 查询、首屏渲染和大表交互是否达到代码目标另行冻结的性能预算。
