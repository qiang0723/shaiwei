# 筛微专业只读 Web 设计草案

> 状态：v0.2，2026-07-20。当前只做设计，不写 Web/后端代码、不启动服务、不改变生产口径。

## 1. 产品任务

Web 首版不追求“展示很多数据”，而是让使用者依次回答三个问题：

1. **数据可信吗**：最新有效交易日、采集状态、门禁、异常、覆盖与证据链是否完整。
2. **策略有效吗**：相对基准、扣除成本后的收益、回撤、稳定性和当前模型版本是否成立。
3. **今天要行动吗**：是否调仓、最新信号、可成交性、风险与告警是什么。

## 2. 信息架构

### 总览

- 顶部结论条：系统状态、数据截止日、最新成功任务、当前告警数量。
- 今日行动卡：是否调仓、信号生成时间、目标持仓数量、次日执行提示。
- 组合结果：策略与基准净值、扣费超额、回撤、换手；收益不得脱离基准和成本单独展示。
- 证据摘要：当前代码/数据/模型/信号哈希与验收进度，可进入对应详情。

### 股票池与信号

- 当前股票池、入选/排除原因、排名、目标权重、当前权重和预计换手。
- 流动性、停牌、涨跌停、ST、上市状态及可成交性提示。
- 因子贡献仅展示已有确定性归因；无法可靠归因时明确显示“暂无可审计贡献分解”。

### 模型与回测

- 实验版本、数据窗口、训练/验证/OOS 划分、参数、模型与产物哈希。
- 策略/基准净值、成本情景、年度结果、最大回撤、换手及多窗口稳定性。
- PASS/REJECT/NOT_READY 结论与失败原因，不隐藏失败实验。

### 数据质量

- 数据源、最新批次、覆盖率、缺失、重复键、异常、发布时间和 `.BJ` 排除状态。
- 从门禁结果下钻到批次、账本行、文件路径和 SHA-256；页面只读，不提供修数入口。

### 系统运行

- Docker 服务、scheduler 最近运行、日增量/影子步骤、飞书投递和异常恢复记录。
- 日志默认结构化摘要；原始日志按需下钻，并对密钥、token、Webhook 和签名做硬脱敏。

## 3. 首批指标草案

| 决策区 | 指标 | 必须同时展示 | 证据来源候选 |
|---|---|---|---|
| 数据可信 | 最新有效交易日 | 任务状态、门禁状态、数据快照哈希 | 日运行账本、哨兵报告 |
| 数据可信 | 原始批次数/行数 | `.BJ` 行数、重哈希结果 | ingest ledger、原始批次 |
| 策略有效 | 扣成本净超额 | 基准、成本、最大回撤、窗口 | 实验账本、回测产物 |
| 策略有效 | 当前模型状态 | 代码/数据/模型哈希、生成时间 | 影子运行账本、manifest |
| 今日行动 | 是否调仓 | 上次/下次调仓日、目标持仓数 | 信号 manifest |
| 今日行动 | 次日可成交率 | 换手、开盘偏差、预计成本 | 对账账本 |
| 系统运行 | 最近一次完整周期 | 开始/完成、耗时、失败步骤 | 日运行账本、通知记录 |

所有指标在代码施工前还须补齐：机器名、业务定义、时间口径、单位、空值语义、状态枚举、来源字段和下钻主键。

### 真实证据核对后的口径约束

2026-07-20 首次用真实非调仓日对账复核页面口径，冻结以下设计约束：

- **正式验收进度不能直接显示 `forward_report.json` 的 `reconciled_trade_days` 或 `trial_ready`**。汇总包含不同代码快照的先导证据；页面必须以 `signal_sha256` 关联影子运行与对账账本，再按受控 `code_snapshot_sha256` 和预定交易日对过滤。
- **次日可成交率的分母只包含 `delta_weight != 0` 的实际交易腿**。非调仓日 `trade_count=0` 时显示 `NOT_APPLICABLE`，不得把行级行情可观察或历史累计比率显示为“当日 100% 可成交”。
- 非调仓日仍展示目标持仓的平均绝对开盘偏差，并紧邻展示定义 `official_next_open / signal_day_close - 1`；换手和预计成本正确显示为 0。
- “整日任务批次”和“当日新增原始批次”分开命名。前者只统计市场补采计划，后者还可能包含 `stock_basic` 刷新，禁止用同一个“批次数”标签混用。
- 首页状态只能来自完整证据连接：日运行 PASS → 同数据/代码快照门禁 → qlib/模型/信号哈希 → 次日对账；任一连接缺失都不能显示整体 PASS。

### 状态机草案

| 状态 | 机器含义 | 首页表现 | 是否需要行动 |
|---|---|---|---|
| `FAIL` | 必需步骤失败、哈希不一致或证据损坏 | 红色结论条并显示首个失败步骤 | 是 |
| `STALE` | 已过数据时钟截止但没有最新完整快照 | 橙色结论条，显示滞后交易日 | 是 |
| `WARN` | 主流程可用但存在非阻断异常或通知失败 | 黄色提示，主结论保留具体限定 | 视情况 |
| `NOT_READY` | 观察期、窗口或正式验收次数未满 | 中性进度状态，不冒充失败 | 否 |
| `NOT_APPLICABLE` | 当前场景没有分母或该检查不适用 | 显示“不适用”及原因 | 否 |
| `NO_DATA` | 查询范围没有登记证据 | 显示空状态，禁止补零 | 视数据时钟 |
| `PASS` | 同一快照的全部必需证据完整且通过 | 绿色但克制，展示截止时间和哈希入口 | 否 |

状态优先级为 `FAIL > STALE > WARN > NOT_READY > PASS`；单项 `NOT_APPLICABLE`/`NO_DATA` 是否影响整体状态，由该指标是否属于当前场景的必需项决定，不能由前端自行推断。

## 4. 查询契约草案

首版只读接口按页面任务拆分，不让前端直接扫描 Parquet 或自由拼接生产 SQL：

- `overview_snapshot`：指定 `as_of` 的首页一致性快照。
- `latest_signal`：最新信号、调仓状态和持仓明细引用。
- `shadow_reconciliation`：信号对应的次日成交与成本对账。
- `experiment_summary`：指定实验的版本、窗口、指标、判决和产物引用。
- `data_quality_summary`：指定交易日的批次、覆盖、异常和门禁。
- `system_run_summary`：任务、步骤、通知和恢复记录。

每个响应都应携带 `as_of`、`generated_at`、`source_refs`、`evidence_hashes` 和 `freshness_status`；若来源之间不一致，接口失败或显式返回不一致状态，不静默拼成一个数字。

`overview_snapshot` 还必须携带 `controlled_code_snapshot` 和 `acceptance_scope`；`shadow_reconciliation` 必须同时返回 `trade_count`、可成交率分子/分母及 `metric_status`，不能只返回一个容易误读的百分比。

## 5. 总览低保真线框

```text
┌ 系统结论：PASS / STALE / FAIL ─ 数据截至：YYYY-MM-DD HH:mm ─ 告警：N ┐
├ 今日行动 ───────────┬ 当前验收 ───────────┬ 证据身份 ─────────────┤
│ 是否调仓 / 目标数量 │ 当前版本 1/3 / 下一节点 │ 代码·数据·模型·信号哈希 │
├ 策略 vs 基准（含成本）──────────────────┬ 风险与回撤 ──────────┤
│ 净值、净超额、成本情景、时间范围          │ 最大回撤、换手、集中度 │
├ 最新信号与次日对账 ─────────────────────┴──────────────────────┤
│ 信号时间｜调仓状态｜交易腿｜可成交率/不适用｜开盘偏差｜预计成本 │
├ 数据质量与运行时间线 ─────────────────────────────────────────┤
│ 批次/行数/.BJ/门禁 → qlib → 模型 → 信号 → 飞书 → 次日对账       │
└ 每张卡均可下钻到账本主键、不可变产物与 SHA-256 ───────────────┘
```

## 6. 视觉与交互原则

- 桌面优先、响应式查看；中性克制的专业金融风格。
- 首页先结论、异常和数据时点，再展示趋势；正常状态不喧宾夺主，异常必须可见。
- 颜色不作为唯一状态编码；PASS/FAIL/WARN/NOT_READY 同时使用文字与图标。
- 图表默认显示基准、成本口径和时间范围；缩放或筛选后仍保留口径提示。
- 参考 Grafana、MLflow、TradingView、Ant Design 的信息架构与交互，不复制品牌视觉。
