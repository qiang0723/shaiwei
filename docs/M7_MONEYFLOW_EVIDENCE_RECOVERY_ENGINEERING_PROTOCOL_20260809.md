# M7-0R3 双轨证据恢复 synthetic 工程合同

## 结果目标

本目标只证明已冻结的两条恢复规则能够被安全实现、失败关闭和独立复算。完成后可决定是否值得生成
真实采集 release；它不采集数据，也不改变 M7 的数据结论。

## 实现边界

新增窄包 `src/shaiwei/research_gates/m7_moneyflow_recovery/`，按职责拆分：

- 合同：绑定已推送的 R3 协议及权限；
- 计划：从精确目标键生成 Baostock 状态窗及 Tushare 双形态请求；
- claim：请求发出前一次性消费，区分传输重试与语义失败；
- 主计算：Pandas 口径的数据质量门；
- 独立审计：DuckDB 重新计算同一裁决；
- fixture：908/541 规模的完全合成正常与对抗样本。

现有通用 S1 计划器、Baostock 适配器、P1 资金流合同和 R2 主/审实现均不得修改。新模块常态不超过
400 行，不新增 `utils/helpers` 杂物间，不新增常驻服务、外部依赖、账本或公共 schema，因此当前不需要
ADR。未来若增加上交所公告解析器、真实采集适配器或公共证据 schema，必须另行判断 ADR。

## 必测坏路径

- Baostock 返回交易、缺行或非法状态；
- Tushare 任一请求形态缺行、双边缺行或同键内容冲突；
- 目标键重复、非法或出现 `.BJ`；
- 全市场响应触及 6,000 行饱和边界；
- 不可变批次校验失败；
- 同一请求重复 claim；
- 传输错误最多三次，语义错误不重试；
- 主实现和独立审计不一致；
- 输出泄露证券代码或产生调整覆盖率、候选/效果/生产授权。

## 停止点

工程门全部通过时只裁 `GO_M7_EVIDENCE_RECOVERY_ENGINEERING_ONLY`。实现提交推送后停止，不生成
真实 release scope，不访问 `.env`，不调用 Tushare/Baostock，不读取真实证券键或资金流数值。
