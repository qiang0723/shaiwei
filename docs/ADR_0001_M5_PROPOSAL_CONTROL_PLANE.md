# ADR-0001：M5 本机研究提案控制面

- 状态：`ACCEPTED_FOR_M5_1`
- 日期：2026-08-05
- 决策范围：M5-1 proposal-only

## 问题与结果目标

M5-0 已能在浏览器生成临时研究草案，但刷新即消失，无法形成可复核的稳定意图。M5-1 的目标是让
用户把有界研究意图持久化、提交人工复核或取消，并可靠看到“未冻结、未排队、未运行”。它不是研究
执行器，也不负责决定因子、策略或模型是否有效。

## 约束证据

- 现有 `web-query` 是经过验收的 GET/HEAD-only 服务，不能直接扩成写服务；
- scheduler、生产数据、研究结果、`.env`、Docker socket 和外部网络均不属于提案所需资源；
- 单用户本机环境不能虚构多人审批，但可以做流程、内容哈希和安全边界隔离；
- M5-0 草案字段不足以成为正式研究协议，因此持久化对象必须称“非权威提案”；
- M5-0A 已补正 M3 的 24 次生成/72 个评价单元，M5-1 必须绑定补正后的 v2 快照。

## 方案比较

### A. 给 `web-query` 直接增加 POST

实现最少，但会破坏已验收的只读服务身份、挂载和安全模型，使查询与命令同故障域。拒绝。

### B. 独立 proposal-only 服务，SQLite 单事务保存操作态（选择）

新增内部 `research-control`，只持有控制数据库和冻结提案配置；浏览器经本机 `web-ui` 的严格代理访问。
SQLite 保存不可更新的 canonical proposal、哈希链事件和幂等回执。因为 M5-1 没有 Worker、外部调用、
研究产物或跨进程发布副作用，本阶段不建设 outbox、任务队列和研究账本。

优点是边界小、可事务化、可故障注入且不污染研究证据；代价是 M5-1 数据只属于本机操作态，不能单独
重建研究裁决。这个代价与“提案非权威”的定位一致。

### C. 一次建设完整任务、批准、队列、Worker、Auditor 和 outbox

长期可能需要，但当前没有获批的冻结、release、执行或外部调用，提前施工会放大权限面和恢复复杂度。
推迟到 M5-2 及以后。

## 选择与边界

- 服务：独立镜像、内部网络、无宿主端口；`web-query` 不加入控制网络且保持全写方法 405。
- 状态：只有 `DRAFT / REVIEW_REQUIRED / CANCELLED`；过期是服务端可提交性事实，不新增自动状态转换。
- 命令：create、submit-review、cancel；不提供编辑、删除、冻结、批准、release、enqueue 或 run。
- 数据：严格枚举、canonical JSON、proposal/request/submission SHA、事件哈希链和幂等回执；无证券清单、
  公式源码、自由命令、任意路径、secret、研究结果或表现指标。
- 权限：本机稳定逻辑角色 `RESEARCH_PROPOSER`；随机短会话只承担 CSRF 和限流，不宣称多人认证。
- 网络：浏览器只到 `127.0.0.1:8080`；代理做精确 Origin、SameSite 会话、CSRF、请求体上限和限流；
  UI 与 control 通过仅二者持有的本地 Docker secret 建立内部能力边界。

## 合同、迁移与回滚

M5-1 使用独立 schema 与数据库版本 1，不修改 M5-0 快照、P3 查询合同、研究 ledger 或生产 schema。
回滚时停止 `research-control`、移除 Web 控制路由并保留项目内数据库；只读策略工厂继续工作。数据库
损坏、未知 schema 或 integrity check 失败时服务 fail closed，不自动重建或覆盖。

M5-2 若引入冻结协议、Worker 或外部副作用，须另立 ADR/协议，把已提交 proposal SHA 作为输入之一，
并新增 write-once 协议、outbox/审计账本和恢复策略；不得原地把 proposal 升格为权威研究证据。

## 验收与复审触发器

验收必须覆盖幂等同键重放/异体冲突、并发状态竞争、响应丢失、进程重启、DB busy/损坏、Origin/CSRF/
会话/限流、未知字段和阻断股票池，并证明所有冻结/执行端点不存在。出现远程访问、多人身份、编辑提案、
冻结/排队、外部调用、研究产物或跨服务发布需求时，本 ADR 必须复审。
