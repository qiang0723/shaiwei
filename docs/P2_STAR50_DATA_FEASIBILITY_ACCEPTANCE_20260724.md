# P2-0 科创50数据可行性与 PIT 门禁验收（2026-07-24，UTC+8）

## 1. 最终裁决

机器裁决：**NO-GO**，不授权进入科创50策略工程、回测或效果查看。

该裁决不是权限、网络或原始数据质量失败。Tushare `index_daily` 与 `index_weight` 权限、串行采集、
有界分片、即时双查、不可变写入、重复键、日历覆盖、权重和、成分引用和北交所排除均通过；阻断项
是：

1. 冻结协议要求从 2020-07-23 开始使用历史成分，但源端首份权重快照仅为 2020-07-31；按冻结的
   “下一官方交易日生效”规则，最早可用日为 2020-08-03，2020-07-23~2020-07-31 共 7 个官方
   交易日没有可追溯成分。禁止用 7 月末或当前成分回填。
2. Tushare `index_weight` 输出只有 `index_code/con_code/trade_date/weight`，没有发布时间、版本号
   或修订原因。88 个请求各即时双查一致只证明本次源端响应稳定，不能证明历史时点看到的版本未被
   后续修订；不满足 `p2-star50-protocol-v1` 冻结的长期修订证据门。

因此当前结论必须表述为：**原始接口和采集工程可行，但冻结历史起点的 PIT 数据不可行；工程未完成，
策略有效性未评估。**

## 3. 权限、分页和采集

- 项目 `.env` 中的 Tushare token 对两个接口均有权限；没有输出、写日志或入 Git。
- 请求计划固定为 88 项：`index_daily` 按 8 个自然年分片，`index_weight` 按 80 个自然月分片；
  全部串行。
- `index_weight` 文档没有 offset/limit 分页参数，月窗作为冻结的有界分页；单批最大 50 行。
  `index_daily` 单批最大 243 行。两者均远低于本项目 6000 行拒绝线。

## 5. 样本量与窗口现实性

中证800 的六个 2016 起“3 年训练 + 1 年测试”窗口不能迁移：其中四个窗口在科创50实时发布前
开始，事后回填不能修复 PIT。预注册的三个科创50窗口日历样本为：

| 窗口 | 训练 | 验证 | 测试 |
|---|---:|---:|---:|
| STAR-W1 | 470 | 125 | 242 |
| STAR-W2 | 603 | 124 | 242 |
| STAR-W3 | 601 | 125 | 243 |

测试窗交易日数量本身达到冻结的 220 日门槛，三段压力期分别为 35、28、116 日；但 STAR-W1
冻结起点有 7 日 PIT 成分缺口，因此不能以“总体样本够多”掩盖时点证据失败。即使未来另立 v2
协议从 2020-08-03 开始，三窗口证据也仍弱于中证800六个年度窗口，必须保持独立表述。
