## 1. 结论

`r2-1-forward-checkpoint-v1` 不能再靠等待达到 `CHECKPOINT_OBSERVED`。截至 2026-08-21，机器投影为：

- `LIVE_DUAL_FORWARD=13/20`；
- `LIVE_DUAL_REBALANCE=0/2`；
- 应覆盖 15 个上交所开市日，实际完整覆盖 13 个，覆盖率 `13/15=86.67%`；
- 永久缺口为执行日 2026-08-13、2026-08-14；
- 终态为 `BLOCKED_EVIDENCE`，阻断原因是 `MISSING_LIVE_DUAL_OPEN_DAYS`。

两个账户、行情、信号和会计结果最终均为 PASS；阻断的是“执行日同日自然完成”这一证据身份，不是
策略收益或账户计算失败。不得把次日追赶行改名为自然前瞻，也不得删除缺口。

## 3. 原因分层

### 已证实

1. scheduler 容器在 2026-08-13 17:37 至次日 10:11 之间没有新的标准输出，形成约 16 小时
   34 分钟断档；随后自动追赶 2026-08-13。
2. Tushare 客户端版本为 1.4.29，单请求默认 timeout 为 30 秒；项目 `_query` 最多 6 次并有有界退避。
   单纯按正常运行中的网络重试预算不能解释上述整夜断档。
3. 2026-08-14 当晚 source cycle 很晚才形成正式日增量，随后 shadow 阶段又出现 217.9 分钟长尾。
4. 2026-08-17—21 已连续恢复 5 个同日双账户日，scheduler 当前 healthy；未发现结果计算或账户重放
   的持续故障。

### 高可信推断但未越权取证

2026-08-13 的整夜断档与宿主 Mac / Docker Desktop 休眠或挂起高度一致。为遵守“只操作筛微项目目录”
的边界，本审计没有读取项目外 macOS 电源日志，因此不把该推断写成已证实事实。

2026-08-14 的异常长尾可能来自宿主再次挂起或同机研究任务的 CPU、内存、磁盘争用；当前项目没有
保留阶段 heartbeat 与历史资源采样，不能诚实地在两者之间裁决。

### 可观测性缺口

- `WAITING_SOURCE` 只覆盖当前 health 快照，没有追加式尝试时间线；
- `health.json` 会被下一轮覆盖，不能还原历史阶段；
- 通知 ledger 保存投递结果，但不保存 scheduler 异常 payload 的本地结构化副本；
- shadow 只有整轮开始/结束时间，没有 dataset、qlib 构建、加载、训练等阶段耗时真身。

因此本次可以确认运行连续性故障，却不能把 2026-08-14 的 217.9 分钟精确归因到休眠或资源争用。

## 4. 协议问题

v1 同时规定：

1. 从固定起点 2026-08-03 起官方开市日覆盖率必须为 100%；
2. 运行异常只会让检查点顺延。

两者在出现永久缺口后不能同时成立。当前 evaluator 会一直把 2026-08-13、14 放入 missing 集合，
所以新增 7 个或更多自然日也不会让 v1 从 `BLOCKED_EVIDENCE` 恢复。这是协议终态语义问题，不能靠
补数据、改账本或降低门槛处理。
