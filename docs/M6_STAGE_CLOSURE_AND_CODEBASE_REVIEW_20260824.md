## 1. 结果结论

M6 已经得到足够清晰的阶段答案，应当关闭而不是继续做恢复链或参数变体：

1. 模型归因指向组合转换瓶颈，不支持继续无目标增加模型；
2. Top20 路线停在数值生产谱系无法证明因果，未读取 Top20 效果，不能宣称有效或无效；
3. 生产 Head30 在研究尺度通过，但相对合法控制臂更弱、换手和成本更高，生产授权始终为 `none`；
4. 50 万元退市风险恢复已闭合红股语义和独立审计，但最大现金与目标偏差触发冻结资本门，终态
   `CAPITAL_INFEASIBLE`；同家族两次尝试已耗尽，不再追加变体。

这四条不互相覆盖：研究尺度验证不等于 50 万元执行可行，后者失败也不推翻原 Head30 的历史研究
裁决。当前正确动作是保留主策略和自然前瞻，停止 M6 继续扩张。

## 3. 为什么现在不能删

`SAFE_DELETE_NOW=[]`。M6 的 release、recovery、runner、auditor 和 fixture 分别绑定已关闭 scope、
镜像、失败原因与不可重跑尝试，仍是唯一合法复核入口。九组跨度至少 12 行的精确重复函数主要集中在
authority、manifest builder、CLI mapper 和等价性检查；它们形态重复，但物理 SHA 已被不同历史
release 绑定，直接合并会破坏复算身份。

此外，`model_attribution` 仍被 TS 的四个模块直接使用，不能把整个 M6 包归档。M6 没有专用 Git tag，
镜像和忽略区真实证据也没有异机副本；A1-3B 的远端耐久性门仍未完成。因此当前只能分类保护，不能以
减少行数为目标删除或迁移。

## 4. 新发现的阻断点

构建注册表仍把 `m6-head30-delisting-entitlement-release` 标为 `ACTIVE_LOCAL_READ_ONLY`，而 M6-5C-C
已经终态关闭。不能直接把状态改成 `CLOSED_FROZEN`：R4 scope 校验器仍要求 scope 记录的历史
`registry_sha256` 等于当前持续演进注册表 SHA，状态变化会让封存 scope 自己失效。

这与 ADR-002 “封存 release 使用自身历史注册表身份”的长期裁决不一致，但不影响已经形成的研究结果。
下一小节点应只修这一发布身份语义：建立通用封存注册表校验、证明 R2/R4 旧 scope 与篡改门继续通过，
再把 R4 组件状态改为关闭。不得在该节点读取效果、运行研究、改模型或删除代码。
