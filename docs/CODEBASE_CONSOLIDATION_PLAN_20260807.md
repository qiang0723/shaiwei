# 筛微代码架构与受控整理瘦身计划

- 计划日期：2026-08-07（UTC+8）
- 状态：`SCHEDULED_NOT_EXECUTION_AUTHORIZED`
- 上位规则：`docs/ARCHITECTURE_CONSTITUTION.md`
- 补充机器规则：`config/codebase_consolidation_v1.yaml`
- 本节点权限：制定架构、基线、触发器和删除门；不删除生产代码、研究代码、证据或数据

## 1. 结果目标

整理不是为了追求更少行数，而是降低下一次改动出错、口径复制和无法回滚的概率。完成一次整理后，
项目必须比整理前更容易回答：某项事实在哪里计算、谁可以调用、失败如何表现、旧入口何时退出、删除后
怎样证明结果没有变化。

项目继续采用“稳定内核 + 窄扩展”的结构：新股票池、因子、模型、组合与页面继承注册表、PIT、执行、
成本、门禁、账本、证据和查询合同；只把合法差异放在配置或职责单一的适配器中。不得以整理名义重写
冻结研究方法、统一历史口径、移动不可变数据或把多个清晰模块合并成新的大文件。

## 3. 目标边界

```text
contracts / schemas / domain types
                ↓
domain & research kernel（PIT、因子、模型、组合、门禁、裁决）
                ↓
application orchestration（pipeline、一次性研究、release）
                ↓
ports & adapters（数据源、文件、通知、模型服务）
                ↓
read-only projections / query API
                ↓
Web / CLI / alert presentation
```

这是依赖约束而不是目录美化：领域内核不能导入 Web、Docker 或 secret；查询层不能调用生产编排；前端
不能计算新的业务口径；`tools` 可以调用稳定内核，但生产 `src` 禁止反向依赖 `tools`。新能力优先扩展
现有 typed contract 和注册表，不复制 evaluator、ledger、PIT、成本、组合或 Web 状态机。

首次机器扫描发现一处既有反向依赖：
`src/shaiwei/research/star50_residual_effect/metrics.py` 导入
`tools.p2_star50_effect_correction.executor`。它同时绑定 P2-2C 纠错执行和 M4-1 历史复算，不能在本节点
直接移动或复制。补充门将这一条精确登记为 grandfathered 债务，禁止新增第二条；A1-0 必须优先裁定
是把稳定执行内核迁入 `src`、保留复算适配器，还是继续保护到相关历史复算退出。

## 4. 增长棘轮

1. 新生产模块默认不超过 400 行，超过 600 行禁止新增；热点清单只能缩小，不能提额。
2. 超过 800 行的文件再次被业务需求触碰时，只允许薄编排或抽离一个可独立测试的职责，净行数不得增长。
3. 一个功能提交只改变一个业务变量；结构抽离可同行，但不得顺带改变结果、Schema、默认值或权限。
4. 不建立新的 `utils/helpers/common` 杂物间；公共代码按领域能力命名，并有明确输入输出和直接测试。
5. `tools`、一次性 Docker profile 和恢复入口必须有退出条件；不得因“以后也许用到”变成常驻依赖。
6. 每个重大里程碑记录核心/前端/工具/测试行数、热点数量和依赖违规，规模增长必须能对应到真实能力。

## 5. 什么才是可删除代码

只有同时满足以下证据，才进入删除候选：

- Git 搜索、Python/TypeScript 依赖图均无静态调用；
- 不在 `Makefile`、Compose、Dockerfile、CLI/entry point、配置、迁移、定时任务、测试 fixture 或 Web 路由中；
- 不被动态导入、字符串注册、插件注册表、反射、序列化类型名或历史复算入口引用；
- 不承担当前生产回滚、已冻结研究复算、事故恢复或审计解释职责；
- 有同等或更窄的权威替代实现，且调用方迁移完成；
- 删除前 characterization tests 已锁定公共行为，删除后全量测试、镜像/查询合同和关键哈希保持合法。

“最近没运行”“静态工具说 unused”“已有相似函数”都不能单独证明可以删除。

## 6. 永久保护或需专项裁决的内容

以下内容不进入普通废代码清理：

- `data/raw`、不可变产物、追加账本、真实 audit/receipt 和哈希 manifest；
- 冻结协议、验收文档、失败/REJECT/STOP/NO-GO 证据与作废说明；
- 数据库迁移、公共 Schema 旧版本和仍在兼容期的序列化类型；
- 当前生产镜像的发布、回滚、scheduler、模拟仓和通知入口；
- 为历史研究结果提供唯一合法复算能力的 runner/auditor；
- 凭据、其他项目目录或项目外文件。

如果这类内容确实需要退出，必须另立迁移/归档 ADR，证明可复算、可追溯和回滚，不得直接删除。

## 7. 首次整理检查点

首次完整整理在以下边界触发：

1. M6 当前研究系列形成终态后；
2. 启动下一项重大股票池、策略族、常驻服务或 Web 写能力之前；
3. 如果不继续 M6，则在下一重大功能开工前立即触发。

触发后先做 `A1-0` 只读清单，不直接删除：输出入口清单、依赖图、重复实现、无引用候选、热点责任、
生产/复算保护项和逐文件证据。用户复核候选清单后，`A1-1` 才按一个职责族一个提交执行删除或拆分。

后续任一条件出现时进入下一次只读复核，而不是自动大重构：距上次基线新增约 20,000 行代码；新增
3 个以上超过 400 行文件；同一热点连续两个目标被触碰；或一个重大研究/产品阶段关闭。不得以日历频率
反复整理，也不得让整理长期阻塞结果主线。

## 8. A1-0 / A1-1 验收

### A1-0 只读清单

- 不修改生产代码，不删除文件，不启动真实研究或生产任务；
- 列出每个候选的引用证据、动态入口风险、替代实现、保护等级、预期收益和回滚点；
- 区分“可删”“待迁移”“应拆分”“历史复算保护”“证据永久保留”；
- 给出按风险排序的最多三个首批施工包，不把全仓重写成一个任务。

### A1-1 受控施工

- 每批只处理一个职责族，先测试后删除，禁止跨业务顺手改口径；
- 公共输出、查询合同和必要复算哈希在改前/改后相同，或由事先批准的版本迁移解释；
- `make architecture-check`、全仓测试、Ruff、compileall、依赖、Compose 和脱敏门通过；
- scheduler 容器/镜像/创建时间不变且 healthy，不读取 `.env`，不修改数据或追加账本；
- 记录删除文件、净减少行数、热点变化、保留原因和 Git 回滚提交。

没有“至少删除多少行”的 KPI。若审计证明没有足够安全的删除候选，允许以零删除结束；错误删除比少删
更危险。
