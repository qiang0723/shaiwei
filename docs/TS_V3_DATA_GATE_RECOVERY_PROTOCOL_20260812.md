# TS-1A-R1 v3结果盲数据合同恢复协议

日期：2026-08-12（UTC+8）

机器真身：`config/ts_v3_data_gate_recovery_v1.yaml`

状态：`FROZEN_BEFORE_NETWORK_AND_RECOVERY_PROFILE`

## 1. 恢复目标而非改判

TS-1A v1 的`BLOCKED_MARKET_RULE + BLOCKED_DATA`永久保留。R1不回写v1，也不借补数读取任何TS收益；
它只修复v1已经暴露的两项输入合同遗漏，并完成原协议尚未执行的结果盲候选漏斗画像。

R1仍禁止候选入场后的收益、MAE/MFE、胜率、回测、模型拟合、参数网格、模拟账户、Web和生产。
报告只允许聚合数量、覆盖率、同期结构分布、下一开盘缺口/止损距离和身份哈希，不得出现具体证券代码、
名称或推荐。

## 2. 既有证据正式纳入

`DATA_SPEC.md`已经冻结证券存续区间为`list_date <= trade_date < delist_date`。因此R1在形成应有成员日
之前先应用`stock_basic`右开退市边界；退市生效日不是预期交易日，也不得生成价格或成交量。

缺bar的解释顺序固定为：真实日线 → Tushare全天停牌 → Baostock独立`trade_status=0`。
Baostock为1却无日线时冲突失败；状态证据只能解释未交易，绝不能制造OHLCV。这样可以合法解释v1的
90个退市边界日和5个已确认未交易日，同时保持未解释缺口必须为0。

## 3. 唯一补采请求

R1只允许一条逻辑Tushare请求：`index_daily`、`399006.SZ`、2016-01-01至2026-08-11、冻结11字段。
最多一个成功响应；底层瞬时故障可按既有配置进行不超过6次有界传输尝试。响应必须只有该指数、主键
唯一、日期属于官方SSE开市日、首日不晚于2016-01-04、末日等于2026-08-11、行数低于6,000。

真实联网前必须另生成绑定协议、实现文件哈希、精确请求和基线账本哈希的release scope，由用户用其
SHA-256逐字授权。claim一旦产生，同scope即使失败也不得重跑。Token只从项目内Git忽略`.env`读取，
不得输出、提交或写入证据；成功响应只能经`RawBatchWriter`进入不可变raw和追加式ingest ledger。

## 4. 市场与板块操作化

结果前把用户的“大盘/对应市场不创新低且处于右侧”操作化为：当日收盘高于SMA20，且最新完整周低点
不低于上一完整周低点。中证800负责全局许可；主板、创业板、科创板分别使用`000906.SH`、
`399006.SZ`、`000688.SH`，缺历史即`NOT_EVALUABLE`，禁止替代。

申万一级行业仍用PIT中证800成员的复权日收益构造等权篮子，不冒充官方行业指数。由于单一行业可横跨
不同上市板，行业基准唯一冻结为“当日有效行业成员各自所属大类指数收益的等权组合”。行业自身站上
SMA20、20/60日分别跑赢该成员加权大类基准、完整周低点不下移后，按20日超额取前三。

## 5. 个股漏斗与画像边界

硬门沿用：非ST、存续中、市值200亿元、前完整周成交50亿元、三根完整月K支持连续两月高点提高、
三根完整周K低点不下移、最新周收盘在周中位以上；日线收盘突破前日高点且收阳才形成匿名候选事件。
单日30亿元仍只是标记，不是硬门。

月低变化、连续两周振幅/实现波动、前周VWAP/中位距离、下一开盘跳空、`前周低点×98%`止损距离和
0.5%单票风险预算只做分布与可行性画像。不得从这些同期分布中选择赚钱阈值。Alpha158只检查事件键
覆盖和成熟时钟；其10日标签与TS最长15日条件退出继续标为非决策排序错配。

## 6. 验收与停止线

工程必须延续现有`trend_swing`分层，新增文件常态不超过400行，并有右开退市、Baostock 0/1冲突、
跨板行业基准、完整周/月、未完成周期、无指数、`.BJ`、重复键、Alpha158未来分数与报告泄露证券身份的
对抗测试。

真实恢复画像最多一次，manifest/report/audit write-once；独立audit须从冻结源重算关键计数。最终只
能返回`GO_TS_V3_FREEZE`或一个/多个`BLOCKED_*`。即使GO，也只允许下一节点冻结TS-1B业务口径，
不自动授权效果、模拟仓、Web或生产。
