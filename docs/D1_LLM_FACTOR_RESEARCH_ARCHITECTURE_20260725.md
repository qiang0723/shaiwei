# D1-0 LLM 持续因子研究架构裁决（2026-07-25）

## 结论先行

筛微应建设自己的窄研究控制面，不把 RD-Agent、QuantaAlpha 或其他外部框架直接接管现有数据、
G1、模型和生产调度。第一阶段采用“LLM 提出受限 DSL 候选，确定性代码编译、执行、记账和裁决”
的结构；任意 Python 程序生成、实时知识爬取、观象桥接和自动入生产全部后置。

D1-0 的裁决为 `REVIEW_COMPLETE / NOT_AUTHORIZED_TO_RUN`：架构方向明确，但当前只形成文档和机器
协议草案，不调用 DeepSeek、不生成候选、不查看新因子结果、不改变生产策略。

## 1. 为什么现在可以启动，为什么不能直接做成常设 Agent

启动条件已经满足：P0 当前版本三次前瞻闭环完成，P0.5 模拟仓有自然 FORWARD，生产与开发快照
已隔离，P1 和 P2 都有不可变终态，G1 已是可执行裁判。现有工程也已有三个可复用真身：

1. `src/shaiwei/research/alphagen_expression.py` 的算子/字段白名单、复杂度审计和未来扰动哨兵；
2. `ledger/experiments.csv` 与 `ledger/factor_admissions.csv` 的失败计数和不可变准入记录；
3. `g1-v1` 的 W1-W6、压力期、成本、DSR、HAC 和组合增量门。

尚未具备的是真实 LLM 客户端、请求/响应账本、知识源清单、提示词身份、费用熔断和隔离运行容器。
因此下一步应先做 D1-1 工程门，不能把“论文里有 Agent”误当成筛微已经具备常设研究能力。

## 2. 公开方法复核与取舍

以下只引用论文或官方仓库，作者回测结果不作为筛微有效性证据。

| 来源 | 可借鉴组件 | 本阶段不采用的部分 |
|---|---|---|
| [RD-Agent(Q) 论文](https://arxiv.org/abs/2505.15155)、[Microsoft RD-Agent](https://github.com/microsoft/RD-Agent) | 假设—开发—反馈闭环、任务分解、Qlib 适配 | 全栈框架接管、Linux/外部服务依赖、模型与数据路径接管 |
| [AlphaAgent](https://arxiv.org/abs/2502.16789) | AST 新颖性、假设—表达式一致性、复杂度约束 | 用 Agent 自评替代硬门，继承作者收益 |
| [CogAlpha](https://arxiv.org/abs/2511.18850) | 代码级变异、失败反馈、正负样本记忆 | 自由代码执行和未经本地复核的进化策略 |
| [Hubble](https://arxiv.org/abs/2604.09601) | DSL/AST 沙箱、正负双通道记忆、家族感知选择、确定性评价 | 作者数据、作者结果及未经本地冻结的检索语料 |
| [FactorEngine](https://arxiv.org/abs/2603.16365) | 逻辑修改与参数优化分离、失败知识库、LLM 与本地计算分工 | 首轮即开放图灵完备程序、自动参数搜索 |
| [QuantaAlpha 论文](https://arxiv.org/abs/2602.07085)、[官方仓库](https://github.com/QuantaAlpha/QuantaAlpha) | 轨迹级变异/交叉、语义一致性、重复和复杂度限制 | 其预计算数据、研究 UI、运行时与筛微生产路径绑定 |

综合判断：公开研究已经证明“组件形态值得做”，尚未证明任何实现能在筛微的数据、成本和 A 股交易
约束下开箱获得稳定结果。与当前工程最贴合的是 Hubble 的 DSL + 正负记忆、AlphaAgent 的 AST
约束、CogAlpha 的代码级反馈，以及 FactorEngine 的逻辑/参数分离；RD-Agent 更适合作为未来离线
适配参考，而不是首版底座。

## 3. 架构边界

```text
冻结知识包 ─┐
冻结主题/提示 ├─> DeepSeek 生成器 ─> 严格 JSON schema ─> DSL parser/sandbox
失败/成功记忆 ┘                                             │
                                                            v
实验总账 <─ 哈希/用量/失败分类 <─ 发现期确定性评价 <─ 因子面板
                                                            │
                                         Top2 + 人工经济解释闸
                                                            │
                                                            v
                                  冻结 G1（W1-W6/压力/成本/统计）
                                                            │
                                      REJECT 或研究候选（非生产）
```

### 3.1 自建控制面，复用现有裁判

- 筛微持有协议、数据身份、提示词、schema、账本、沙箱和裁决的最终控制权。
- 外部框架只能作为阅读参考或未来隔离适配器；不得直接读写生产账本、生产 qlib、模型或信号。
- LLM 只返回“假设 + DSL + 非权威解释 + 谱系”，不获得执行工具、文件、网络或环境变量能力。
- 本地确定性代码负责 schema 校验、AST 规范化、重复判定、PIT/shift、因子计算和全部统计。
- LLM 的评分、反思或“我认为可交易”永远不是 PASS。

### 3.2 首轮 DSL 优先

首轮只接受现有白名单表达式：6 个量价字段、22 个算子、窗口 1–50、token 不超过 20、AST 不超过
80。理由不是 DSL 最终表达力最佳，而是它已经有实测 parser、未来扰动哨兵和 G1 通路，能把本次
唯一新增变量收敛为“生成方法从 GP 变为 LLM”。

首轮禁止 Python、import、文件、网络、环境变量、反射、动态执行、shell 和未声明库。若 DSL 臂
失败，不能据此证明程序级因子无效；若 DSL 臂通过且后续确认表达力成为瓶颈，再单独预注册程序级
沙箱，参考 FactorEngine 的逻辑/参数分离，不在本轮顺带开放。

### 3.3 四层数据与时钟

| 层 | 内容 | 权威时钟 | 首轮状态 |
|---|---|---|---|
| 数值数据 | OHLCV/VWAP、PIT 行业、市值 | 交易日可得时点 | 复用 GP 同一输入 |
| 知识数据 | 论文、规则、官方仓库的人工摘要 | `published_at/retrieved_at` | 固定清单，禁止运行中联网 |
| 实验记忆 | 成功、失败、重复、沙箱拒绝、发现期指标 | 尝试完成时 | 同主题正负记忆 |
| 裁决证据 | W1-W6、压力期、成本、DSR、HAC | 冻结评价窗 | 只有 Top2 人工闸后可读 |

2026 年论文用于 2016–2018 发现期时，必须标记 `retrospective_discovery=true`。这可以测试“今天的
LLM 能否从当前知识形成可验证假设”，但不能宣称该知识在历史时点已经可得。论文/网页只提供知识，
不能把文中数字直接当作回测因子值。

### 3.4 正负记忆不是结果泄漏

首轮每个主题固定 8 次：前 4 次独立提案，后 4 次只读取同主题的语法/沙箱、规范 AST、覆盖、复杂度
和发现期 RankIC 反馈做有界变异。不得读取 W1-W6、压力期、G1 或前瞻结果。主题顺序固定，记忆不跨
主题，避免早期主题的结果改变后续主题预算。

任何完成的模型响应都计一次 N；空输出、截断、格式错、语法错、沙箱拒绝和重复 AST 均计 N。
“请模型修一下”是新的响应，也消耗下一次预算。只有未产生完成响应的网络重试可保留同一尝试号，
最多两次；完整请求和响应保存在项目内 Git 忽略区，Git 只留脱敏哈希清单。

## 4. DeepSeek 接口与成本裁决

截至 2026-07-25，官方文档列出 `deepseek-v4-flash` 与 `deepseek-v4-pro`；旧
`deepseek-chat/deepseek-reasoner` 已在 2026-07-24 进入弃用切换。V4 Pro 支持 thinking、JSON
Output 和工具调用，1M 上下文；当前公开价格为缓存未命中输入 $0.435/百万 token、输出
$0.87/百万 token。[官方模型与计费](https://api-docs.deepseek.com/quick_start/pricing/)

首轮建议固定 `deepseek-v4-pro`、thinking=`enabled`、effort=`high`，理由是本轮评价的是受限表达式
推理质量，过早用低成本模型失败会混入模型能力不足这一解释。thinking 模式下 temperature/top_p
等参数不生效，因此协议不伪装成可控随机种子。[官方 thinking 说明](https://api-docs.deepseek.com/guides/thinking_mode/)

输出使用正式 JSON Output，不使用 beta strict tool calling，也不给模型工具。官方说明 JSON Output
仍可能空返回或被截断；本项目把这类响应计为失败尝试，不自动免费重生。
[官方 JSON Output 说明](https://api-docs.deepseek.com/guides/json_mode/)

每次最多 16k 输入和 8k 输出，40 次全部缓存未命中的理论上限为 $0.5568，硬熔断暂定 $0.75。
缓存由服务端自动管理，只记录 hit/miss 用量并降低费用，不作为复现条件；输出仍具有随机性。
[官方缓存说明](https://api-docs.deepseek.com/guides/kv_cache/)

由于提供方别名不保证权重永久不变，系统必须记录返回模型名、完整 usage、请求/响应哈希和时间；
40 次应在同一受控批次串行完成，返回模型身份变化即 fail closed。这里能保证的是输入、输出、代码和
评价可审计，不声称模型生成可逐 bit 复现。

## 5. 与 GP 的诚实比较

冻结 GP 最终报告确有 40 个表达式，其中 4 个通过完整样本/安全审计，最佳 `|RankIC|` 为
0.0201423；但 `g1-v1` 按该家族历史中所有纠错和失败机械统计了 166 次尝试。新建一个“干净 GP
家族”把 N 重置为 40 会降低 DSR 惩罚，违反失败留账原则，因此禁止。

比较分成三层：

1. 生成层：40 对 40，比较有效候选率、重复率、沙箱拒绝率、最佳发现期 `|RankIC|` 和单位成本；
2. 组合层：LLM Top2 与旧 GP Top2 使用相同 Alpha158、成本、窗口和压力期，比较增量 ICIR/净超额；
3. 裁决层：LLM 使用自己真实的全部尝试 N 走 G1；GP 保留原 166 次裁决，不声称 DSR 完全配对。

首轮主判只有一个：至少一名 LLM 候选通过全部 G1，才 `GO_BOUNDED_PILOT`；否则 `PAUSE`。GP 数值
用于解释生成方式差异，不用于降低 LLM 或 GP 的门槛。

## 6. 人工闸与结果隔离

发现期结束后机械选 Top2，不先看 W1-W6。LLM 提供的经济解释只作草稿；G1 要求的人工解释必须
在 W1-W6 解盲前由研究者审核并写入。若某候选无法形成可信经济机制，则它失败且不递补第三名，防止
人工不断换候选追求通过。

即使历史 G1 PASS，也只授权进入独立研究候选和前瞻影子，不进入生产模型、模拟基准仓或实际交易。
成为常设因子研究线至少还需一个独立目标：固定频率、预算、衰减/退役、前瞻门槛和异常熔断。

## 7. 观象与多源输入边界

观象仍是未来重要输入之一，但首轮禁止接入。本次未访问观象目录、仓库、数据库或服务。未来若用户
单独授权，只允许把经过字段语义、PIT、授权和质量审计的版本化快照复制到筛微项目研究区；单向、
只读、无共享数据库、无在线依赖，且“观象判断”不能直接当收益标签。

同理，知识雷达首轮不常驻爬取。D1-1 只构建来源清单和人工摘要；D1-4 获准后才讨论定期发现、版权
边界、提示注入隔离、内容哈希和变更审批。

## 8. 实施序列

1. **D1-0（本次）**：架构裁决、协议草案、公开资料复核；零 LLM 调用。
2. **D1-1**：实现控制面、LLM 尝试账本、JSON schema、mock provider、DSL 沙箱、Docker 一次性
   研究入口和 synthetic fixture；仍为零真实 LLM 调用、零市场结果。
3. **D1-2**：用户确认模型与 $0.75 上限后，先冻结并推送协议/提示/知识清单，再串行完成恰好 40 次
   生成与发现期评价。
4. **D1-3**：Top2 人工经济解释闸和冻结 G1；不通过即暂停，不调门槛、不加候选。
5. **D1-4**：仅在 D1-3 GO 后设计低频常设研究试运行；知识雷达、观象和程序级因子均需另案。
