# ADR-002：封存组件 release 使用自身注册表身份

- 日期：2026-08-23（UTC+8）
- 状态：`ACCEPTED`
- 范围：已封存组件 release 的离线复核；不改变任何真实执行授权

## 问题与结果目标

`build_asset_registry_v1.yaml` 是持续演进的全仓所有权注册表。M6-5C-C R2 scope 同时封存了当时的
注册表 SHA、组件资产路径、逐资产 SHA 和组件构建快照。旧校验器却要求 scope 中的历史注册表 SHA
必须等于当前全仓注册表 SHA；这样只要登记一个完全独立的新组件，旧 release 就会被误判失效。

目标是同时满足两件事：历史 scope 可永久复核；当前注册表仍能严格覆盖所有当前构建资产。

## 候选方案

1. 禁止注册表继续增长：会阻断任何新 Docker 组件，拒绝。
2. 新组件不登记：破坏 100% 资产归属门，拒绝。
3. 封存 scope 使用自身绑定的历史注册表 SHA 和组件资产快照；新 release 使用构建时当前注册表：采用。

## 裁决与边界

封存 R2 scope 的自哈希已经绑定历史 `registry_sha256`、三条组件资产及逐文件 SHA。复核旧 scope 时，
以其协议绑定的前序 scope 注册表 SHA 和固定三资产集合为权威，不再要求等于当前可演进注册表。
组件快照、容器路径、镜像标签、源码 bundle 和 scope 自哈希门全部保留。

当前/未来 release 仍必须从当前注册表生成身份，且被跟踪的 `Dockerfile*` 与 `compose*.yaml` 必须
恰好登记一次。这个裁决不能作为跳过当前注册表、放宽资产哈希或重开旧 scope 的理由。

## 迁移、回滚与验证

只修改旧 scope 的只读验证逻辑，不改旧 scope、协议、镜像或产物。回滚点为本 ADR 前提交，但回滚
会再次使注册表不可扩展。验收须证明：旧 R2 scope 继续通过；篡改历史 registry 或资产记录仍失败；
新增 successor 组件后旧 scope 仍可复核；全仓注册表继续 100% 覆盖当前资产。
