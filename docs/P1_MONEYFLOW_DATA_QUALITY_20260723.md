# P1 主力资金流数据可用性与 PIT 验收

日期：2026-07-23
结论：**GO_DATA_ONLY** —— 允许下一目标开展隔离增量因子实验；生产授权仍为 `none`。

## 1. 验收范围

本轮只回答“数据能否被可信地采集并安全进入研究”，不回答“因子是否有效”。未修改 `src` 中的生产模型/信号逻辑、G0/G1 门禁、调仓规则、Docker scheduler 或现有模拟组合。

实现包括：

- 三类 Tushare 资金流精确 schema 与按日采集计划。
- 追加式原始批次、请求参数、Parquet 内容哈希和采集账本。
- 北交所过滤前的 6000 行截断门、`.BJ` fail closed、默认幂等和显式刷新语义。
- 覆盖、缺失、重复、数值、极值、停复牌、行情一致性、修订和 PIT 质量报告。
- `tools/p1_moneyflow/` 独立工具边界；生产 `src/`、`tests/`、配置和 scheduler 保持原快照。

## 2. 主候选真实证据

`tushare.moneyflow` 对 2016—2026 每年选取一个官方开市日，共 12 个检查点：

```text
20160104 20170103 20180102 20190315 20200102 20210104
20220104 20230911 20240102 20250102 20260105 20260723
```

| 指标 | 结果 |
|---|---:|
| 最新请求合计行数 | 50,252 |
| 日期级质量门 | 12/12 PASS |
| 对日行情覆盖率 | 99.6465% — 100% |
| 重复键 | 0 |
| 空值单元 | 0 |
| `.BJ` | 0 |
| gross 分桶负值 | 0 |
| 每个请求快照数 | 2 |
| 每个请求唯一内容哈希数 | 1 |

最低覆盖出现在 2017-01-03，仍为 99.6465%；差异主要表现为少量旧代码/当前代码口径不一致，未做猜测映射。2026-07-23 与 `daily` 为 5198/5198 全覆盖。

金额与成交量双边分桶相对官方日行情的中位比例为约 1.983—2.000，符合双边统计预期并同时校验了万元/千元与“手”的量纲。

极值检查发现 2026-07-23 的 `603221.SH`，`|net_mf_amount| / 当日成交额 = 1.1332`，同日净量比例为 1.1332；12 日 50,236 个可比样本中仅该条 materially 超过 1.01。由于官方明确 `net_mf_*` 不是分桶重算恒等式，本轮保留原值并输出 `NET_FLOW_EXCEEDS_DAILY_SCALE_TAIL`，不在原始层裁剪；后续实验必须预注册 robust scaling/winsorization。

停复牌行为符合源差异预期：2026-07-23 有 3 个 `S` 停牌代码，基础主源包含 0 个；有 2 个 `R` 复牌代码，基础主源包含 2 个。质量报告已将 S/R 分列，避免把复牌日误判成停牌污染。

## 3. 交叉源结论

### 同花顺 `moneyflow_ths`

- 已提交的 2016、2019、2023、2024 检查点均为 0 行，不能支撑 W1—W6。
- 2026-07-23 返回 5200 行；覆盖全部 5198 个当日日行情代码，另有 2 个当日停牌代码。
- 与日行情交集存在 2 个价格不一致，最大收盘差 1.00、最大涨跌幅差 1.9576 个百分点，不能把其 `latest` 当官方行情替代品。
- 首轮施工由 fail-closed schema 门发现实际字段为 `buy_*_amount_rate`，并确认 `buy_*_amount` 是可为负的分档净流入。修正后才允许入账。

### 东财 `moneyflow_dc`

- 官方历史始于 2023-09-11，天然不能覆盖 2016 年起的冻结窗口。
- 2023-09-11、2024-01-02、2026-07-23 对当日日行情覆盖率分别为 99.9802%、99.9803%、100%，但额外代码分别为 360、363、458。
- 当前原始提供方响应含 229 条 `.BJ`；采集边界排除后入账 5656 行，已提交批次 `.BJ=0`。
- 额外代码包含 B 股、历史/无当日行情代码和停牌代码。交集内收盘价完全一致，涨跌幅最大差 0.005 个百分点，为展示精度差异。

因此 THS/DC 只保留交叉诊断地位，不能替代长期主候选，也不能把其预计算五日流或数据商“主力”标签直接作为正式因子。

## 4. PIT 裁决

- 官方资料只给出盘后/日度更新语义，未提供足以证明项目 19:30 稳定可用的承诺。
- 2026-07-23 22:35（UTC+8）的实测只证明该时点可用。
- 正式冻结 `moneyflow-pit-v1`：资金流 D 日值从下一官方交易日起才可用于特征，即交易日 `shift(1)`。

该裁决消除了等待多日 19:30 观测才能开工的依赖，同时不会引入同日未来数据。

## 5. 幂等、修订与证据

- 22 个唯一请求（12 个主源 + 5 个 THS + 5 个 DC）均显式刷新一次；每个请求两份不可变快照、唯一内容哈希数均为 1，未见即时修订。
- 15 请求默认模式复跑结果：`collected=0`、`skipped=15`；复跑前后采集快照哈希均为 `18e2dc9e99892c0e95748802ff778e39e836a02071e353b21210a82dfe6342ef`。

`logs/` 与 `data/` 按项目纪律不进入 Git；可迁移真身由项目内 Parquet、追加式 `ledger/ingest_batches.csv`、内容哈希与本验收摘要共同定位。

施工中曾发现：把隔离研究代码放入 `src/`/`tests/` 会改变生产代码快照，使既有 FORWARD 产物被验收器正确拒绝并令 scheduler degraded。本轮没有放宽该门禁、没有重写 FORWARD 产物；而是撤回全部受控目录改动，将工具迁至隔离目录，使生产快照恢复原值。这一处理保留了门禁含义，也避免研究施工阻断日常后台。

回归验证：生产主测试 184/184 PASS；隔离 P1 测试主机 12/12 PASS、现有 Docker scheduler 容器 12/12 PASS；Ruff、compileall、`pip check`、`git diff --check` 与脱敏扫描通过。

## 6. GO 的准确含义

允许的下一步：

1. 用主候选完成 2016—2026 隔离回填和 T+1 派生层。
2. 在看结果前冻结候选公式、缺失处理、截尾/标准化、行业/市值/成交额/换手残差化和实验预算。
3. 与 Alpha158 使用相同 W1—W6、成本、调仓及风险口径，验证增量 RankIC/ICIR 与组合结果。

仍然禁止：接入生产 scheduler、改正式信号、把数据可用当成因子有效、绕过 G1，或依据本轮极值与收益事后调门槛。
