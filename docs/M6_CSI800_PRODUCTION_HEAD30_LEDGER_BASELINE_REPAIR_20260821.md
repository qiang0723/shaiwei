## 根因

补录施工时，为避开工作树中 scheduler 尚未提交的合法追加，使用 Git index patch 仅暂存了两条
Head30 记录。既有门禁只比较 `HEAD -> 工作树`，没有比较 `HEAD -> 暂存区 -> 工作树`；测试在提交
前读取完整工作树而通过，提交后却只留下“旧 HEAD + 两条 Head30”的不完整候选。这属于提交管线和
暂存区身份缺少机器约束，不是 scheduler、账本追加器或研究计算错误。

## 修复边界

- 本次提交完整活账本，恢复 8 条自然前瞻记录和两条 Head30 记录的真实顺序。
- 不新增研究尝试，不改效果、裁决、模型、预测、回测、模拟仓、Web、scheduler 或生产授权。
- 后续提交另加两道永久门：`HEAD -> Git index -> 工作树` 前缀链，以及 `HEAD^ -> HEAD` 提交历史
  前缀链；本次唯一非前缀纠偏只允许由精确提交、父提交、文件哈希和本收据共同授权。
- M6-5B、M6-5C、旧 runner 与退市方法节点继续暂停。

## 后续原则

任何账本提交都必须先验证暂存候选，而不能用工作树测试结果替代；任何已提交的非前缀变化都必须默认
失败关闭。历史纠偏只能使用窄、逐哈希、一次性的机器例外，不能设置通配符或人工跳过开关。
