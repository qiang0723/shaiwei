# G8-2 管理人 HTTPS 交叉核验与费率谱系协议（结果前冻结）

> 协议：`g8-fund-manager-crosscheck-v1`
>
> 冻结日期：`2026-07-26`
>
> 当前 G8 状态：`NOT_READY`

## 1. 目标与边界

本阶段把 G8-1R 已捕获的六只产品、48 个监管 HTTP 主源净值逐值与基金管理人官方 HTTPS 来源核对，
同时建立 A 类标准申购费、赎回费的有效期谱系。它只回答“证据能否认证、费率在何时适用”，不构造
产品总收益、不读取策略收益、不运行 G8、不改 G8 公式或门槛，也不接 scheduler、Web 或生产路径。

六只产品是一个完整篮子。任何一只缺少管理人 HTTPS 身份、缺少冻结窗口八个日期、单位/累计净值
不一致，或费率法律文件谱系不完整，整体裁决均为 `NO_GO_G8_2`，G8 继续 `NOT_READY`。不得用聚合站、
搜索摘要、CNINFO 或监管 HTTP 冒充管理人 HTTPS，也不得删掉失败产品后缩小篮子。

## 2. 净值核验

冻结日期为 `2026-07-15/16/17/20/21/22/23/24`。每只产品必须在管理人官方 HTTPS 来源获得恰好
八行 A 类净值，产品代码、产品名称、单位净值和累计净值与 G8-1R 不可变证据逐项完全一致。比较采用
十进制数值相等，不用浮点近似、不接受四舍五入容差、不前向填充。

HTML 页面双取必须原字节一致。JSON API 同时保存两次原文，只允许剔除协议列明的顶层响应时间戳后
做规范 JSON 比较；其余字段必须完全一致。连接、TLS、HTTP、结构、身份、重复、缺日、内容修订或
主源冲突均保留证据并 fail closed。

## 3. 费率定义与谱系

本阶段冻结的是基金法律文件载明的 A 类标准申购/赎回费率，不假设任何销售渠道折扣。动态产品页只
能交叉确认当前展示，不能单独证明历史有效期。每条费率记录必须绑定官方管理人法律文件 SHA-256、
页码或章节、公开日期和适用区间；费率变更必须有明确生效日。

谱系从基金成立覆盖至 `2026-07-26`，至少包括原始合同/招募说明书、冻结日前最新法律文件锚点，及
之后全部费率变更公告。不得以下载日期代替生效日，不得因搜索不到公告就推断“从未变更”，不得用
当前费率回填历史。

## 4. 执行与证据

网络请求仅允许访问协议逐产品列明的管理人域名、路径和方法；TLS 必须校验，零自动重试，串行限速，
每个逻辑请求双取。两次原文、请求身份、安全响应头、解析结果、哈希和失败状态保存在项目内 Git 忽略
的 `data/g8/manager_evidence`，跟踪账本只记相对路径、哈希、计数和状态，不得出现净值、费率数值、
绝对路径或凭据。

真实执行完成后必须再做断网只读复核，复算全部 bundle/文档/报告哈希，并证明相同入口复跑不新增
请求、不追加账本。生产 scheduler 容器、镜像、挂载和创建时间必须前后一致。

## 5. 结果解释

全部硬门通过时只授权另立 G8-3 总收益构造协议；仍不授权直接计算 G8。任何硬门失败时保留已通过
产品的诊断证据，但不得把部分覆盖表述为 VERIFIED，也不得通过替换产品、改来源或放宽 HTTPS 条件
改判。
