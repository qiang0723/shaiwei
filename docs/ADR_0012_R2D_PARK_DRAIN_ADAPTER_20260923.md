# ADR 0012：R2D 停放、旧任务排空和发布谱系的分阶段适配

日期：2026-09-23。状态：DESIGN / SYNTHETIC_ONLY；不是生产授权。

## 目标、权威与现状

结果目标是使收盘后的宽窗口可实施，而非每天移动旧协议日期。本轮只设计适配边界并用纯内存
参考实现验证；真实入口、镜像、控制器与生产状态不变。权威是冻结 R3L 合同、版本化源码和未来
经独立核验的不可变证据，不是会话里的 PASS 或当前日期推断。

本轮只读源码发现：daily.run_once 即使最终 NOOP 也可能先刷新日历；scheduler 在 NOOP 后仍执行
shadow/paper/verify/acceptance。旧生产源码版本 210af4dab33c85b38c05b28f56c176b7970c41db 的
SIGTERM 处理只设置停止事件，退出前可能继续完整同步周期；最终 health=stopped 不保证退出码为0。
Compose 文本含 restart=unless-stopped、stop_grace_period=30s。以上是源码事实，不是运行现场证明。
旧代码不遵守未来新增维护锁；宿主 flock、noop 或两次静态计数相同不能证明排空。

## 候选方案与裁决

1. 延长旧窗口或只过滤 daily 的返回日期：拒绝，无法阻止已发生的副作用，也绕不过旧 readiness。
2. 新候选在全部业务入口之前停放，旧写入者以独立退出证据隔离：选择；代价是新镜像、新 fixture、
   版本化切换控制器及可能的维护停机，均须后续独立授权。
3. 直接给旧生产注入维护锁/热补丁：拒绝，改变不可变发布身份且不能证明全入口参与。

## 开工合同与分层

新增 r2d_parking_rehearsal 只接收严格、不可变、内存模型和显式时钟，不导入 scheduler/release/
runtime、文件、Docker、网络或环境。复用 R3L 的日期、身份、完整闭环和窗口裁决，不复制效果口径。
入口 rehearse_handoff / rehearse_first_day 都是纯模拟，输出 production_authorized=false；
WOULD_* 不是可供生产控制器执行的许可。模拟中传入的 SHA/布尔证明也不是已核验的真实字节。

真实适配必须分阶段：

1. 只读预检并冻结全写入者清单、三方身份（旧运行、已提升但未运行、新停放候选）与窗口。
2. 精确授权及一次 claim 后，在**首个旧生产变更之前**持久化 MAY_HAVE_WRITTEN 屏障；旧版本的
   “候选派发前才记屏障”不足以覆盖停止旧进程或调整重启策略。不得自动杀进程或超时强杀。
3. 封住新写入入口，允许旧在途任务安全结束，证明清单中所有旧写入容器退出码0、无遗留子进程、
   无重启、无未知或宿主 writer，退出后再核验闭环/计数/发布身份未漂移。未知即停，不自动恢复旧服务。
4. 将停止前的真实 noop 作为有时间戳的归档证据；退出后的状态另立 ExitWitness，绝不把 stopped
   改写成 fresh noop。R3L 的3600秒新鲜度仍对归档心跳生效；太旧或排空期间新增尝试即 BLOCKED。
5. 冻结新候选的停放配置，原子比较 state/audit 前值后实施新谱系；确认候选停放及排他所有权后才
   交接维护隔离。任何缺证都不能继续。原始批准文本、scope、失败回执不覆盖。

真实全入口隔离不能仅靠一个新锁：旧进程不参与。必须同时证明旧容器及子进程退出，并由经过
fixture 验证的入口控制排除新容器/手动 daily、shadow、paper/宿主 writer。无法枚举或强制覆盖则
该方案不可上线。本轮不声称已经解决 OS/Docker 层的证明，也不创建锁或生产适配器。

## 候选停放与首次派发

停放门必须早于配置中的 secret 装载、daily.run_once、日历刷新、行情探测、shadow、paper、verify、
acceptance 和业务通知。停放只允许另行冻结的白名单元数据读取与自身 health；这些也不是本轮权限。
手动入口、scheduler 和子命令均须受同一版本化门约束，不能只在 while 循环里加日期判断。

首日由冻结交易日历与调度截止共同确定，不以自然日+1计算；未来真实适配不得重复实现 daily 的
日期权威算法，应拆出只读元数据端口复用它，并绑定源码与配置哈希。模拟只消费已验证日期。
首日之前全部业务调用为0；到首日零尝试、唯一缺失日期等门通过后，仅可进入持久化单次 claim
阶段，不等于行情已就绪或业务可直接派发。源码中的 market_source_ready 本身可能联网和写原始批次，
不能放进“停放只读检查”，也不能要求它先成功才能取得首次 claim 而造成循环等待。
源就绪探测必须在首日 claim 之后按原数据门执行；WAITING_SOURCE 不得进入 shadow/paper。其持久化
阶段、同一 claim 下只读对账和安全续接须在后继集成及故障注入中证明，本轮没有实现自动续接。
中断/已 claim/部分尝试未知时阻断，禁止盲重跑；完整首日验收后也不重跑首日。
错过首个自然日不得自动补跑或顺延。后续正常运行只在首日完整验收证据落盘、入口集成回归通过后
启用；本轮模拟不实现这个后继常驻生命周期。

操作窗口限制切换，不等于限制已批准停放候选的首日运行时间；周末停放后首日可在切换窗口之后。
此区别须出现在未来准确批准文本，不是用过期 scope 再切换。单次 claim、最终变更前复核、
FORBID_AFTER_DISPATCH、不自动回滚等边界保留；新 scope Schema 不沿用旧版本。

## 发布迁移、回滚与退出条件

原 Phase A 不重做。现有 current 是已准备候选、previous 是旧生产；新停放候选另有 image/code/
revision/fixture 身份。未来迁移必须保持 previous=**经核验实际运行的旧版本**，而不是普通 promote
导致 previous 变成从未运行的准备候选。准备候选作为不可变历史保留；新 current/previous 与审计
需要受锁保护的 CAS/可恢复提交协议，部分落盘进入未知态，不以补写覆盖证据。纯模拟只给出期望值。

现在回退仅是不接入新模块；不修改任何历史合同。未来停止旧服务后的恢复和任何 rollback 都需
独立批准，失败不自动重启，派发后尤其禁止自动回滚。新镜像和 fixture 不能借用旧 R3A 的身份。
若旧进程不能无强杀排空、全入口隔离无法证明、谱系无法可靠提交，须复审本 ADR 而非放宽门槛。

## 验收与本轮非目标

合成对抗覆盖时间/次序、旧容器遗漏/重复/未知、非零退出/重启/子进程、身份与闭环漂移、过期心跳、
缺少屏障、首日旧日/未来日/积压/部分尝试/claim、停放零业务调用及三方迁移方向。回归 R3L 和旧
readiness 拒绝路径；新模块<=400行，旧热点不增长，受保护架构/Ruff/静态检查。
不跑真实业务全仓测试，不读效果/密钥，不生成 scope，不构建或运行 Docker，不联网、不改生产。
下一工程节点是按本 ADR 实现可替换的只读元数据/持久化 claim 端口和全入口停放集成及离线故障注入；
真实 Docker fixture、镜像构建和切换另立精确权限。R2D 首日验收前不进入 G1。
