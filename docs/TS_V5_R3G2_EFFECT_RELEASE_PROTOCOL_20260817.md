## 目标

本节点只把已冻结的三个 BREAKOUT_RETEST 点施工成可审计的一次性效果入口，并形成绑定 Git、镜像、
输入、权限、命令和空输出目录的唯一 release scope。它不读取真实分数值、排名、入场后行情、H00906
数值或策略收益；完成后仍必须由用户批准精确 scope 才能首次读取效果。

## 架构边界

实现按职责拆为输入与身份适配、纯组合执行、指标与门、不可变产物、薄编排和独立审计。runner 可以在
获批后只读冻结市场、事件、W2—W7 分数与基准；auditor 只读封存的 NAV、交易、基准和清单，不挂载
原始行情、分数、模型或生产账本，也不导入主执行器的组合和裁决模块。

运行严格分两层：先只用键与元数据完成输入哈希、事件重建、`.BJ=0`、重复键、95% 分数键覆盖、分区
末端可退出和空目录检查；这些检查通过后才写入“效果读取开始”证据并一次性消费三个尝试。发现期先
运行并裁决，只有三个点全部通过发现期硬门，holdout 适配器才允许打开 2024—2025 的入场后行情与
基准值。发现期失败时，holdout 产物必须物理不存在。

## 执行细则补正

原效果协议已经冻结经济假设，但部分交易细节需要机器化，现结果前固定如下：

1. 涨跌停以原始开盘价相对上一有效原始收盘判断并保留一档 0.01 元容差；主板10%，科创板20%，
   创业板2020-08-24前10%、之后20%；上市前五个官方交易日不套普通涨跌停门。ST已在上游剔除。
2. 容量只用此前20个已完成证券交易日成交额中位数的5%，不看当日成交额。买入按100股向下取整，
   未成交余量取消；卖出可按容量部分成交，余量继续挂起。历史不足20日或中位数无效时不买、待卖。
3. 两批分别记账，只有早于当日买入的批次可卖；同日第二批不能被日内止盈卖出。第二批不重置首批
   冻结的止损、止盈或15日持有时钟。
4. 开盘顺序固定为待退出、第二批、新首批；收盘先判止损，再判第二批机会；风险/时间退出优先于
   止盈。任何持仓未清时忽略同票新事件。
5. 三个成本场景分别重走现金、整数股和容量路径。2倍场景把佣金、最低佣金、过户费和印花税全部
   乘2；额外10bp场景先把成交价向不利方向移动，再计算数量和费用。
6. 年度收益只是连续账户的年度子区间度量，不在年初重置账户。分区末仍有合法退出未完成时返回
   `BLOCKED_PRE_EFFECT`，禁止虚构清仓。

这些细则只消除实现歧义，不更换三个参数点、不改变50万元、持仓/风险上限、15日退出、1.5R/20%
止盈、成本费率、发现/留出样本或硬门阈值。

## 验收与停止点

工程必须先通过完全合成数据的首遍、完整 replay、独立审计、篡改失败、发现失败不读 holdout、分批
T+1、容量部分卖出、涨跌停、费用、整数股、风险/行业/总仓上限和写一次夹具。随后构建断网不可变
镜像，生成并推送唯一 scope；scheduler 不得重启或改变。到此停止，不创建 approval，不运行真实
runner，不写实验账本，不接模拟仓、Web或生产。
