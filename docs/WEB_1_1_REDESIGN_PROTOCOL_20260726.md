# Web 1.1 重设计协议

> 冻结日期：2026-07-26（Asia/Shanghai）
>
> 状态：`FROZEN_FOR_FRONTEND_IMPLEMENTATION`
>
> 适用范围：七个现有本机只读页面的前端信息架构与视觉表达
>
> 上位真身：`WEB_ARCHITECTURE_RULINGS_20260723.md`、现有查询契约与指标字典

## 1. 不可变目标

Web 1.1 必须让使用者：

1. 5 秒内识别系统是否正常、是否有异常、是否需要行动、最新结果属于什么证据等级；
2. 15 秒内找到原因、关键明细和证据下钻；
3. 在任何页面都能区分运行状态、证据状态、研究/绩效成熟度和行动时钟；
4. 不因视觉强化而扩大后台结论，不因界面简化而隐藏 WARN、REJECT、NOT_READY、BACKFILL 或失败恢复历史。

本协议不改变任何 API、计算、指标、模型、门禁、数据、账本、调度或 Docker 隔离边界。

## 2. 页面统一骨架

每页固定为五层，不能用重复卡片补层级：

1. **Context**：短页面名、一个状态、截止日、生成时刻、证据入口；
2. **Decision**：一句结论 + 一句影响；只允许一个第一视觉焦点；
3. **Primary evidence**：最多 3 个直接支持结论的主指标/事实；
4. **Diagnosis & detail**：原因、表格、图表、异常、筛选；
5. **Lineage**：证据等级、短身份和下钻，不重复主结论。

跨页阅读顺序冻结为：`结论 → 行动/影响 → 主结果 → 原因 → 明细 → 证据`。

## 3. 导航

- 桌面 ≥1100px：208px 左侧导航，分为“今日 / 研究 / 组合 / 运行”；当前项只用左侧标记、字重和低对比底色，不使用大胶囊。
- 700–1099px：隐藏固定侧栏，顶部保留菜单按钮和上下文；抽屉承载完整导航。
- <700px：顶部菜单 + 底部“总览 / 因子 / 组合 / 更多”；页面内容不因导航隐藏而丢失。
- `as_of` 是唯一全局筛选；研究与运行页面仅改变标签，不改变含义。账户继续锁定 `model_baseline`。
- 证据抽屉保持全局一致，不增加编辑、重跑、下载或文件浏览入口。

## 4. 栅格与密度

- 工作区最大宽度 1600px；桌面 12 列，列间距 20px；页面边距 28px。
- 1024px 页面边距 24px；768px 及以下 18px；390/320px 为 14px。
- 垂直节奏：页面级 28px、区块级 20px、组件内 12/16px；8px 为最小基准。
- 主要结果区允许 7:5 或 8:4，不强制对称；支持区才可均分。
- 事实卡默认改为同一表面内的分隔项；只有独立问题或独立交互才使用卡片。
- 阴影仅用于抽屉/浮层；普通区块使用 1px 边界或背景分层，圆角 6–8px。

## 5. 排版

- 字体保持系统中文无衬线；数字用等宽数字特性，不把所有数值强制改为代码字体。
- 页面 H1：桌面 28–30px / 700，移动 24px；使用短名词标题，不再用完整长问句。
- 决策句：22–26px / 700；区块 H2：18–20px / 650；正文 14px / 1.55；辅助信息 12px。
- 英文 eyebrow 只作短分类，字距收敛；不得与中文标题竞争。
- 金额、比例、日期、哈希右对齐或列对齐；不使用视觉上难比较的居中数字。

## 6. 色彩与状态

色彩只辅助文本和图标，不能单独承载语义：

| 角色 | 色彩 | 使用规则 |
|---|---|---|
| 主文本 | 深墨色 | 标题与关键数字 |
| 次文本 | 中性灰蓝 | 说明、元数据 |
| 主品牌 | 深蓝 | 导航、链接、非语义重点 |
| PASS | 冷绿 | 小面积标签/图标，不铺满正常页面 |
| WARN/STALE | 琥珀 | 需解释或时效问题 |
| FAIL/REJECT | 暗红 | 阻断、无效研究或负向数值；REJECT 必须带“研究结论”文本 |
| OBSERVING/NOT_READY/NOT_DUE | 中性蓝灰 | 成熟度或时钟，不伪装成好坏 |

状态优先级冻结为 `FAIL > STALE > WARN > NOT_READY/OBSERVING/NOT_DUE > PASS`，但不同状态轴不互相覆盖。页面必须显式标注状态轴，例如“核心运行 / 通知 / 证据 / 前瞻成熟度”。

## 7. 组件协议

### 7.1 决策带

- 总览固定显示四个槽位：`系统运行 / 证据完整 / 今日行动 / 结果成熟度`。
- 其余页面显示一个决策句和最多三个支持事实。
- 异常存在时，“需要关注”模块紧邻决策带；没有异常时不显示空异常卡。

### 7.2 事实与 KPI

- 每页主 KPI 1–3 个；驱动和护栏放在同一组内分隔展示。
- 标签必须含范围或分母：如“FORWARD 净值差（2 日）”“现金比例（账户日）”。
- 不为了对称补卡，不把状态徽标当成 KPI 数字。
- 0、无数据、不适用、未评估严格分开。

### 7.3 表格

- 表格用于精确查找；表头 sticky、数值右对齐、行高 42–46px、关键首列保持可识别。
- 移动端优先保留紧凑表 + 局部横向滚动；只有字段需要纵向解释时才用卡片。
- 行内状态使用短标签；当整列状态相同，在列头/表注解释一次，行内降噪。
- 实验目录移动端不再渲染 25 张高卡；保持分页、紧凑行和局部横滚。

### 7.4 图表

- 连续趋势至少 8 个可比观察点才绘折线；不足时展示精确值表、端点比较和“样本不足，不绘制趋势”。
- 净值图不平滑、不填充、不用进度条；组合与基准直接标注，回撤独立显示。
- BACKFILL 与 FORWARD 不连接成一条前瞻曲线；审计视图必须分段并常驻模式标签。
- 图表必须带范围、样本数、基准、费用/成本口径和等价数据表。
- 颜色之外使用直接标签、线型或状态文字；轴不截断制造夸张。

### 7.5 证据

- 默认只显示短哈希；完整哈希和来源在抽屉。
- 证据入口顺序固定：`结论等级 → 缺口 → snapshot → code/data/model/signal/artifact → source refs`。
- `SNAPSHOT_CHANGED/EVIDENCE_MISMATCH` 直接进入阻断错误态，不签发或显示 PASS 快照。

## 8. 数字与语义

- 沿用 `WEB_METRIC_DICTIONARY.md` 和现有 `format.ts` 精度；本轮不改公式。
- 百分比与百分点保持中文单位，带符号数保留正负号；金额使用人民币符号和千分位。
- FORWARD 主结果只用最后 BACKFILL 日锚定专属序列；样本不足继续 `OBSERVING`，隐藏年化、Sharpe、信息比率。
- `planned_trade_leg_count` 的展示语义冻结为“目标变更证券数”；它不是订单腿。`planned_weight_delta` 显示为“目标权重差/诊断差”，不是计划订单。
- 真实订单、成交、停牌、涨跌停、开盘、成本仅在执行日 reconciliation 形成后展示；此前为 `NOT_DUE`。

## 9. 七页首屏冻结

| 页面 | 短标题 | 第一焦点 | 进入明细前必须看见 |
|---|---|---|---|
| 总览 | 今日概览 | 四轴决策带 + 需关注事项 | 是否行动、OBSERVING 样本数、最近完整交易日 |
| 模拟组合 | 模拟组合 | FORWARD 结果、样本数、回撤、现金 | 锚点、基准、重放、会计恒等 |
| 股票池/信号 | 股票池与信号 | 是否调仓 + 目标变更证券数 + 执行证据 | 目标数、实际权重日期、NOT_DUE 解释 |
| 因子工厂 | 因子工厂 | 正式库 0、权威 REJECT、研究范围 | 不排名、不推荐上线、目录入口 |
| 模型/回测 | 研究证据 | 当前权威/失效/工程/发现分层 | 记录不是有效模型、精确筛选和分页 |
| 数据质量 | 数据质量 | 数据门 PASS / 证据 WARN | 未哈希绑定、未重验、.BJ=0 |
| 系统运行 | 系统运行 | 当前需处理项；核心/通知分列 | 失败后恢复链、实时身份 NOT_EVALUATED |

## 10. 响应式与无障碍

- 1440、1024、768、390 和 320 CSS px 均为强制验收视口。
- 320px 等效 1280px 视口 400% 缩放；除数据表/图表二维区域外，整页不得横向滚动。
- 390/320px 页头元数据改为紧凑两列；证据按钮不单独占满一行。
- 键盘顺序与视觉顺序一致；跳转链接首先进入主内容；抽屉 Esc 关闭并归还焦点。
- 触控目标至少 36×36px；焦点环对比明确；状态均有文字+图标。
- 动态刷新使用 `role=status`，阻断错误使用 `role=alert`；日频数值不连续播报。
- 图表有摘要和等价表；局部横滚表格可聚焦并有可访问名称。

## 11. 加载、空态和错误态

- 首次加载骨架保留，但首屏高度不超过 360px，并明确正在核对的对象；不得让旧数据无标识地冒充最新。
- `placeholderData` 刷新时必须保留“正在刷新旧快照”提示。
- 空态说明“为什么为空 / 这意味着什么 / 可下钻到哪里”，不虚构示例数据。
- WARN/REJECT/NOT_READY 使用领域文案；请求错误显示稳定错误码和可重试动作。
- `.BJ`、哈希断链、快照变化、未知 enum、字段缺失继续 fail closed。

## 12. 实现与验收门

实现只允许修改前端展示层、前端测试、Web 设计文档与项目内截图：

- 不改 `src/` 后台、`config/`、模型、门禁、数据、账本、scheduler 或 Docker 生产服务；
- 不新增 API，不补算指标，不读取未授权文件；
- 构建、单元、fixture E2E、真实部署 E2E、axe、键盘、五视口、320px reflow、状态/空态/错误态、安全头与脱敏检查全部通过；
- 改后用同一真实只读数据保存关键截图；
- 施工提交与本协议提交分开，不 push，由主控复核。
