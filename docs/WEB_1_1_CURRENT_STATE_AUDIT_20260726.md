## 1. 审计方法与基线

- 运行入口：`http://127.0.0.1:8080`；审计开始时 `web-query/web-ui` 已运行约 4 小时且 healthy，本专项没有启动或重启服务。
- 浏览器检查：1440×900、1024×768、768×1024、390×844；400% 缩放按 WCAG 2.2 的 1280 CSS px → 320 CSS px 等效重排检查。
- 数据：真实本机只读响应；没有读取 `.env`、没有对外发送项目数据、没有补算指标。
- 证据：改前截图位于 `artifacts/web-1.1/before/`。长页同时记录文档高度与横向溢出。

## 2. 跨页问题清单

### P0 — 影响 5 秒判断

1. **状态同权竞争**：总览同时突出总体 WARN、核心 PASS、证据 PASS、通知 WARN、OBSERVING、NOT_DUE；用户必须自己推导“系统可用但有恢复历史、无需行动、策略仍观察中”。
2. **关键问题没有固定答案槽位**：七页都使用标题 + Hero + 卡片墙，但“结论 / 是否行动 / 证据等级 / 原因”没有跨页稳定位置。
3. **坏消息与普通元数据视觉接近**：恢复历史、未哈希绑定、原始文件未重验与一般说明文字使用相似面积和对比，异常不够早、不够集中。
4. **重复展示冒充层级**：同一个状态在页头、Hero、指标卡、表格行、页脚反复出现，增加阅读量但没有增加证据。

### P1 — 影响 15 秒下钻

5. **均匀卡片墙**：四至六张同尺寸卡片让主指标、驱动、护栏看起来同等重要。
6. **短序列图形不科学**：模拟组合只有 2 个自然 FORWARD 账户日，当前仍用平滑折线和多张重复图表示趋势；这会放大视觉确定性。
7. **研究目录移动端过长**：模型页每页 25 张卡，390px 高度超过 10,000px；因子页也把目录行改成高卡片，精确比较效率下降。
8. **高频状态徽标噪声**：信号表每行重复 `NOT_DUE`；实验表长英文枚举在 pill 内换行，扫描效率低。
9. **筛选器抢首屏**：模型页七个筛选器在看清证据分层之前出现，且所有筛选同权。
10. **证据入口分散**：页头证据按钮、底部哈希条、局部哈希和抽屉入口缺少统一的“证据等级 → 身份 → 来源”顺序。

### P2 — 视觉与响应式

11. **768px 断点错误**：固定侧栏占据 31% 宽度，主要内容被压缩。
12. **页面标题过长**：标题使用完整问句，窄屏占 240–268px 高度；标题没有为“状态”和“行动”让位。
13. **卡片装饰偏多**：圆角、阴影、描边和大留白同时使用，降低专业工作台的信息密度。
14. **表格虽可横滚但缺少扫描优化**：关键列没有稳定的主次对比；表头、行高和状态 pill 占用过多空间。

| 总览 | 今天系统是否可信、是否需行动、结果属于什么证据等级 | 四格“系统 / 证据 / 行动 / 结果成熟度”决策带，异常优先 | 前瞻结果、账户诊断、证据链 | 当前由使用者自行合成多个状态；净值进度条把 NAV 错当完成度 |

| 股票池/信号 | 本期目标是否变化、执行证据是否到期 | 调仓结论 + 目标变更证券数 + 执行证据 | 目标/实际/权重差表、证据身份 | `planned_trade_leg_count` 文案易被理解为订单；每行 NOT_DUE 重复 |

| 模型/回测 | 记录属于什么证据，哪些结论当前权威 | 证据范围和权威/失效/拒绝分层 | 精确筛选、目录、类型化详情 | 783 被醒目强调但没有先给“当前可用结论”；移动 25 卡过长 |
| 数据质量 | 数据能否用于今日信号，证据强度有何缺口 | “数据门 PASS / 证据 WARN”并列判决 | 仅异常哨兵优先、规模、批次和边界 | 六张规模卡 + 十哨兵卡形成卡片墙，WARN 被下推 |
| 系统运行 | 哪里失败过、是否恢复、是否需处理 | 当前需处理异常；核心和通知终态分列 | 顺序、逐步证据、通知、release/heartbeat | 两张大 Hero 和步骤条重复；恢复历史需从多处拼接 |

## 4. 状态、数字和证据问题

- `PASS` 只能回答其所属层：数据门 PASS 不能扩大成策略有效；核心任务 PASS 不能覆盖通知 WARN；重放 PASS 不能覆盖观察期不足。
- `OBSERVING` 是样本成熟度，不是好坏或进度条；必须与数值相邻并显示观察数。
- `NOT_DUE` 是执行时钟，不是异常；默认只在页面决策区和执行列标题解释一次，行内可用短值或继承说明。
- 负收益/回撤用带符号数字、文本标签和适度语义色；不使用大面积红色背景制造结论。
- 哈希默认显示短身份，完整值只在证据抽屉；页面主内容先显示“证据等级与缺口”，再显示身份。
- `planned_trade_leg_count` 首版显示文案统一改为“目标变更证券数”，不得称“计划订单数/计划交易腿”；真实订单与成交只由执行日证据陈述。
