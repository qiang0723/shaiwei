# RF-0A 中证800单机制结果盲准备裁决

日期：2026-08-12（UTC+8）
状态：`GO_PREP_ONLY_NOT_EXECUTION_AUTHORIZED`

## 1. 结论

在不改变 R2-1 自然前瞻主目标的前提下，下一项研究准备选择：

> **中证800“隔夜信息吸收与日内反转状态”机制**：在当日收盘时，区分前收盘至当日开盘的隔夜
> 跳空，以及当日开盘至收盘的信息吸收或反转，检验其联合状态能否在现有 Alpha158、行业和市值
> 暴露之外提供稳定、扣成本的增量信息。

本裁决只允许继续做字段覆盖、PIT 时钟、公式身份和重复风险的结果盲准备；不代表该机制有效，也不
授权 DeepSeek、候选生成、发现指标、标签、收益、模型、回测、模拟仓或生产。正式研究批仍须等待
R2-1 检查点完成和用户阅读其诊断后，另立结果前协议。

## 2. 为什么选择这个机制

### 2.1 现有研究空间已经拥挤

只读取尝试身份、主题、规范公式哈希和失败分类，不使用 `discovery_rank_ic`、`result_json` 或任何
效果字段，得到：

- 三份既有 LLM 因子尝试账本共 104 次尝试；70 行形成非空规范公式，合并后为 63 个唯一公式哈希；
- 既有主题已覆盖趋势/动量、反转/均值回归、波动/振幅、流动性/成交量、量价状态五类通用方向；
- 70 行非空公式对字段的引用次数为：`close=115`、`volume=40`、`high=18`、`low=16`、`vwap=4`，
  `open=0`；
- G1 准入账本现有 29 个版本、21 个“研究族 + 精确公式”身份，正式准入仍为 0。21 个身份由
  基本面 6、基本面动态 5、资金流 6、旧 GP 量价 4 构成。

因此，继续泛化地要求“再做一个动量、反转或量价因子”很可能只增加表达式数量。`open` 没在历史
LLM 公式中出现，提供了一个可核验的身份缺口；但这不是有效性证据，也不等于相对 Alpha158 新颖。

### 2.2 文献只支持机制问题，不支持预判结果

- Berkman 等关于开盘买入成本的研究发现，隔夜上涨后可能发生日内反转，并把它与投资者注意力、
  估值困难和套利约束联系起来：
  [Paying Attention: Overnight Returns and the Hidden Cost of Buying at the Open](https://www.cambridge.org/core/journals/journal-of-financial-and-quantitative-analysis/article/paying-attention-overnight-returns-and-the-hidden-cost-of-buying-at-the-open/F9AAD159B512C651F09D5D52011D88E0)。
- 中国市场研究发现，不同投资者在开盘和收盘附近的交易行为不同，A 股样本呈现负隔夜收益后正日内
  反转的特征：
  [When do they trade? Heterogeneous investors in China](https://www.sciencedirect.com/science/article/pii/S1544612323001034)。
- 另一项中国市场研究发现隔夜/日内反转形态可以持续，但其“对抗强度”并不能预测未来股票收益：
  [Overnight returns, daytime reversals, and future stock returns: Is China different?](https://www.sciencedirect.com/science/article/abs/pii/S0927538X22001044)。

这组证据把问题限定为一个值得证伪的市场微观结构机制，同时明确提醒：观察到隔夜—日内反转，不等于
拥有未来 Alpha。外部论文只用于解释为什么值得提出问题，不进入本项目的效果裁决。

## 3. 与 Alpha158 的重复风险

当前环境的 `qlib.contrib.data.loader.Alpha158DL` 已明确包含：

- `OPEN0 = open / close`；
- `KMID = (close - open) / open`；
- K 线长度、实体位置、上下影和收盘位置；
- 多窗口的收盘收益、均线、波动、斜率、极值、量价相关等特征。

所以“当日开收盘差”本身已经是高重复风险特征。本批唯一可能的新信息，是把：

1. 隔夜分量：`open_t / close_(t-1) - 1`；
2. 日内分量：`close_t / open_t - 1`；
3. 二者的方向、强度或吸收/反转关系；

构造成一个有经济含义、低复杂度的状态，而不是机械增加同义公式。RF-0A 不冻结任何精确公式。

后续去重必须同时通过五层，不得仅凭公式字符串或单一相关系数：

| 层级 | 必须回答的问题 | 当前状态 |
|---|---|---|
| 语义/机制 | 是否只是已有动量、反转、K 线位置的改名 | 待 RF-0B |
| 规范 AST | 是否与 63 个既有 LLM 公式及 21 个 G1 身份等价 | 待 RF-0B |
| 因子暴露 | 是否主要复制行业、规模、波动、流动性或 Alpha158 | 正式批前冻结 |
| IC 增量 | 对 Alpha158 和核心暴露残差化后是否仍有信息 | 效果阶段，当前禁止 |
| 组合增量 | 固定成本和执行规则后是否改善净结果 | 效果阶段，当前禁止 |

## 4. 数据适用性检查

### 4.1 目标数据粒度与时钟

- 粒度：PIT 中证800成员 × 交易日；
- 信号形成：交易日 `t` 收盘后；
- 可用输入：`t-1` 收盘、`t` 开盘与收盘，必要时只使用不超过 50 日的历史 OHLCV；
- 进入价格：`t+1` 官方开盘；
- 标签与退出：继承既有 `t+1` 开盘进入、`t+11` 开盘退出时钟；
- 停牌：OHLCV 保持缺失，不以 0 或前值伪造；
- 股票池：PIT 中证800，`.BJ` 返回即失败关闭。

### 4.2 已有证据

- 既有 Alpha158 管线实际使用 `open/high/low/close/vwap/volume`，说明字段和表达式能力已存在；
- 中证800 PIT 基础在既有质量期形成 101,600 个成员形成日记录、每期恰好 800 只、`.BJ=0`；
- 已登记的残差面板覆盖 2016-06-01 至 2026-06-30，六窗冻结 Alpha158 预测覆盖
  2019-01-02 至 2024-12-31、1,164,697 行，相关产物主键重复为 0；
- 数据规范已经冻结复权、停牌、交易日历、历史成分和次日开盘执行语义。

这些证据足以支持“继续准备”，但不足以支持“数据可直接进入正式因子评价”。尤其需要在 RF-0B
单独核验开盘价链路：成员日覆盖、相邻日可比性、除权除息、上市初期、停复牌、涨跌停开盘、异常
跳空和跨交易日引用。没有这份专项目标字段画像，不得生成候选。

### 4.3 数据质量裁决

| 用途 | 裁决 | 理由 |
|---|---|---|
| 机制与协议准备 | `FIT` | 字段、PIT 成员、时钟与复用执行能力均已存在 |
| 精确候选生成 | `NOT_READY` | 尚未完成 open/前收盘专属覆盖与异常画像 |
| 效果评价 | `NOT_AUTHORIZED` | R2-1 未完成，且没有结果前候选/尝试预算协议 |
| 生产或模拟仓 | `NOT_AUTHORIZED` | 没有历史有效性、独立审计和自然前瞻证据 |

## 5. 可证伪假设与决策价值

研究问题不是“隔夜反转是否存在”，而是：

> 在中证800、PIT 成员、既有 Alpha158、行业/市值中性化、固定标签、成本和执行规则下，隔夜跳空与
> 日内吸收/反转的联合状态，是否提供稳定、非重复且可转化为组合净结果的增量信息？

以下任一情况都应停止该机制，而不是改口径追结果：

- 精确候选在规范 AST 或语义上与既有身份重复；
- open/前收盘目标字段画像未达到事前门槛；
- 主要暴露可被 Alpha158 或核心风险暴露解释；
- 增量 IC、跨窗稳定性、成本后组合或独立审计不通过；
- 中国市场中隔夜和日内分量相互抵消，不能形成未来收益增量。

通过也只允许建立独立候选和独立模拟账户，不能覆盖现有中证800生产主策略。

## 6. 下一合法节点

### 可立即执行：RF-0B 结果盲数据与身份预检

1. 冻结只读输入清单和字段定义；
2. 生成 open/前收盘目标字段覆盖与异常画像，只输出计数、覆盖和失败分类，不计算候选值或收益；
3. 建立跨三份 LLM 尝试账本、G1 身份和 Alpha158 公式族的规范去重清单；
4. 写对抗 fixture：停牌、除权、上市首日、缺 open、跨非交易日、`.BJ`、同义 AST；
5. 给出 `GO_FORMAL_PROTOCOL / REJECT_DUPLICATE / BLOCKED_DATA` 三选一裁决。

RF-0B 仍不得调用 DeepSeek、读取封存效果、训练或回测。它可以在等待 R2-1 自然证据期间施工，但
不得修改 scheduler、生产数据、模型、门禁、信号、模拟账户或 Web。

### 等待 R2-1 后：正式单机制小批

只有 R2-1 达到检查点、用户读完诊断且 RF-0B 为 `GO_FORMAL_PROTOCOL`，才可另立单机制正式协议：
8 个完成响应、最多 3 个合格候选、机械 Top1/Top2、重复/失败计入预算且不补位。DeepSeek 的模型、
知识摘要、费用上限和发送内容仍须逐批明确授权。
