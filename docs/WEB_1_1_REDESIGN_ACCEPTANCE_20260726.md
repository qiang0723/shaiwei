## 2. 解决的首要问题

旧版主要问题不是配色，而是所有状态、卡片和证据争夺注意力：总览不能在首屏给出单一结论，短样本被折线图放大，移动目录变成长卡片墙，长问句标题、重复状态标签和均匀卡片让异常与行动失焦。

Web 1.1 的主要裁决：

1. 导航按“今日 / 研究证据 / 组合与执行 / 数据与运行”组织；页面标题改为稳定名词，页面内再陈述当前判断。
2. 总览首屏固定为“具体结论 + 核心运行 / 证据完整 / 今日行动 / 结果成熟度”四轴，运行、通知、证据和绩效成熟度不合并。
3. 取消均匀卡片墙和装饰性阴影；高密度数据使用事实条、紧凑表格和局部横向滚动。
4. FORWARD 连续可比样本少于 8 个账户日时不画趋势，只展示精确值；当前 2 日保持 `OBSERVING`，不展示年化、Sharpe 或信息比率。
5. `planned_trade_leg_count` 只显示为“目标变更证券数”；执行事实显示为“已执行订单腿”，两者不得互换。
6. 因子和实验的精确筛选默认折叠；移动端保留表格语义，不再把每条记录展开为高卡片。
7. 1099px 以下隐藏固定侧栏并使用抽屉导航；900px 以下双栏收敛单栏；390/320px 页面不发生文档级横向滚动。

## 3. 七页结果

| 页面 | 首要判断 | Web 1.1 第一焦点 | 关键处理 |
| --- | --- | --- | --- |
| 总览 | 今天是否正常、异常、需行动、证据到哪一级 | 具体判断与四轴状态 | WARN 原因不弱化；行动与前瞻结果分栏 |
| 模拟组合 | 实际账户发生了什么 | 锚定 FORWARD 精确结果 | 短样本不画线；BACKFILL 与 FORWARD 分档说明 |
| 股票池/信号 | 目标是否变化、执行证据是否到期 | 调仓结论与执行证据状态 | 目标变化、权重差、订单、成交严格分开 |
| 因子工厂 | 有什么可用因子、为何未入库 | 正式库 0 与权威 REJECT | 无综合分、排行榜或最佳因子 |
| 模型/回测 | 记录是什么、当前是否权威 | 783 条记录不是 783 个有效模型 | 目录紧凑、筛选折叠、失效方法保持显著 |
| 数据质量 | 数据是否足以支持信号 | 数据门与证据缺口分列 | PASS 不覆盖 WARN/NOT_EVALUATED |
| 系统运行 | 哪里失败、是否恢复、还需处理什么 | 当前闭环与恢复状态 | 核心与通知分列，失败尝试永久保留 |
