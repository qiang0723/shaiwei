# P3-2B 数据质量与系统运行页面协议（结果前冻结）

> 冻结日期：2026-07-25（Asia/Shanghai）
>
> 协议：`p3-web-operations-ui-v1`
>
> 状态：`FROZEN_BEFORE_IMPLEMENTATION`

## 1. 目标与边界

P3-2B 只把 P3-2A 已冻结、已验收的三个只读 HTTP 入口接成两个正式页面：

1. `/data-quality`：回答“最新已登记数据能否用于信号，证据还有哪些缺口”；
2. `/system-runs`：回答“最新日周期是否完成、哪里失败过、是否恢复、通知是否送达”；
3. 从系统运行页按稳定 `message_id` 打开通知投递详情，不新增独立页面。

本阶段不修改 P3-2A schema、查询公式或权威输入，不修改 scheduler、生产镜像、策略、模型、信号、
门禁、原始数据或追加式账本；不提供日志搜索、文件浏览、重跑、写接口、导出、认证、远程访问或
交易能力。

## 2. 数据与快照边界

数据质量页只请求一次 `GET /api/v1/data-quality`；系统运行页只请求一次
`GET /api/v1/system/runs`。页面结论、卡片、步骤、批次和证据只能来自各自原子响应，不从总览、
模拟仓或信号端点补数。

通知详情按用户点击后请求 `GET /api/v1/notifications/{message_id}`。由于可变心跳可能使其
`snapshot_id` 与系统页不同，详情必须显示自己的 `as_of/generated_at/snapshot_id`，并明确标注
“独立证据切片”；不得把详情响应静默合并进系统页主结论。legacy 通知只有计数，没有稳定 ID，
不得生成链接或合成身份。

URL `as_of`、`cache: no-store`、5 秒超时、零自动重试、刷新/错误/旧值处理沿用 P3-1。未知状态、
无效数字/哈希/日期、缺少必需字段、超限响应或任何 `.BJ` 必须页面级 fail closed。

## 3. 数据质量页面

阅读顺序固定为：

1. 第一视觉焦点：数据可用结论与证据强度并列，禁止用 `PASS` 覆盖 `WARN`；
2. 关键规模：最新完整交易日、当日市场行数/批次、登记总批次/总行数、数据快照；
3. S1—S10 哨兵矩阵：编号、状态、是否接受、异常数和脱敏指标；
4. 当日新增批次表：批次 ID、来源、行数、采集时刻、内容哈希；
5. 来源 API 批次数和登记身份链；
6. 证据缺口与完整证据抽屉。

页面必须常驻显示：

- `SENTINEL_REPORT_NOT_HASH_BOUND`；
- `IDENTITY_MATCH_UNHASHED`；
- `raw_parquet_rehash_status=NOT_EVALUATED` 与“不挂载 `data/raw`”；
- `.BJ=0` 的三个层次，但不得把返回计数 0 冒充逐字重哈希原始文件；
- S10 的 `NOT_APPLICABLE` 是允许状态，不渲染为失败。

当前响应没有历史序列，因此本页不制造趋势图、成功率或伪时间线。批次规模用卡片和表格，哨兵用
可扫描矩阵；图形不会比精确文本更清楚时不画图。

## 4. 系统运行页面

阅读顺序固定为：

1. 第一视觉焦点：核心任务状态与通知状态分列；
2. 固定阶段时间线：日增量 → 哨兵 → 次日开盘对账 → 影子信号 → 模拟仓 → 独立重放；
3. 步骤表：终态、尝试数、失败数、是否恢复、首错类型、终态时间和运行身份；
4. 通知摘要：可寻址消息、尝试、失败、恢复和 legacy 不可寻址计数；
5. 核心故障消息列表；点击稳定 ID 打开独立通知证据抽屉；
6. release 身份、只读根和挂载目标；
7. scheduler 已登记心跳与证据抽屉。

系统 `WARN` 必须解释为“存在失败恢复或核心故障记录”，不得渲染成当前失败。终态 PASS 不能删除
先前 `ForwardQlibError`。release 只证明运行前最后一个已登记 `START_PASS`；实时 Docker 身份继续
`NOT_EVALUATED`。scheduler 心跳只显示“已登记记录”，不根据浏览器时钟推导实时健康度。

## 5. 通知详情

通知抽屉显示消息 ID、事件、终态、尝试/失败数、恢复和重复投递风险，并按时间顺序展示九字段脱敏
尝试。正文、Webhook、签名、环境变量、原始异常文本和业务载荷均不展示。非法 ID、找不到、证据
冲突或不同 `as_of` 不回退到缓存详情；显示稳定错误码和请求 ID。

## 6. 导航、视觉与响应式

桌面侧栏新增“运行与证据”分组，放置数据质量和系统运行；因子工厂与模型/回测继续禁用。移动端
底栏为总览、组合、信号、数据、运行五项；390/320 px 必须仍有至少 24 px 目标、文本不截断关键
状态，宽表只在自身容器横向滚动。

沿用 Web 1.0 浅色、克制、证据优先视觉：每页一个第一焦点、最多两个第二焦点；状态始终使用图标、
文字和颜色；完整哈希默认进入证据抽屉。1440/1024/768/390、320 px 和 400% 缩放、键盘、焦点返回、
reduced motion、axe critical/serious 0 继续作为硬门。

## 7. UI 代理与安全

UI 静态 allowlist 只新增 `/data-quality`、`/system-runs`；API allowlist 只新增：

- `/api/v1/data-quality`
- `/api/v1/system/runs`
- 严格匹配 `/api/v1/notifications/[0-9a-f]{16}`

通知路径不得使用任意通配代理。GET/HEAD、1 MiB 上游响应限制、随机 CSP nonce、同源连接、零外部
资源、无 `.env`/Docker socket/挂载、非 root、只读根和 127.0.0.1 绑定保持不变。

## 8. 测试与通过条件

必须全部满足：

1. 本协议与机器配置提交、推送早于页面源码、代理变更和真实构建；
2. 两页对必需字段、状态、数字、哈希、日期、`.BJ`、未知状态和缺字段 fail closed；
3. 数据 PASS 与证据 WARN、核心 WARN 与通知 WARN 都能被独立识别，S10 NOT_APPLICABLE 不误报；
4. 失败—恢复链、legacy 通知和独立详情快照不被隐藏或合并；
5. 静态/API 精确 allowlist、GET/HEAD、CSP、响应上限和脱敏通过；
6. fixture 浏览器覆盖加载、刷新、错误、详情抽屉、导航、五视口、键盘和 axe；
7. 真实本机页面与 P3-2A 响应逐项对账，外部请求、console/page error 和 CSP violation 均为 0；
8. TypeScript、Vite build、前端单元/浏览器、全仓 Python、Ruff、compileall、依赖、Compose、
   `git diff --check` 和脱敏检查通过；
9. Web 容器资源和隔离不放宽，scheduler 容器、镜像、创建时间和健康状态施工前后不变。

## 9. 停止条件

若页面完成需要新增后台字段、读取日志/原始文件、猜测实时健康、合成通知身份、放宽代理或 Docker
隔离，立即停止并回主控裁决。不得以“看起来更完整”为理由改变 P3-2A 的 `WARN/NOT_EVALUATED`。
