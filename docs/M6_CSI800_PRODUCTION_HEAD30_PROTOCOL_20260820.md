# M6 中证800生产 Head30 转换器结果前协议

## 要回答的问题

现有历史回测使用 `Top30/n_drop=3`，生产信号则每10个交易日生成当期排名前30名并等权到100%。本批
只验证后者：在同一份干净六窗口预测、同一中证800、同一开盘成交和成本下，它能否通过原 G0。

协议真身为 `config/m6_csi800_production_head30_v1.yaml`。冻结时未读取新的 Head30 收益、净值、
换手或成本结果。

## 为什么把它视为一个变量

生产转换器的业务含义是“把分数投影为完整目标持仓”。当目标名单变化时，它同时决定成员替换、
保留成员再平衡和目标投资比例；拆开其中任意一项就不再是生产规则。因此本批把
`portfolio_converter` 作为一个类别变量，同时强制输出三项分解诊断，禁止把它扩展成参数网格。

## 冻结输入与对照

- 只用 M6-2 `clean_lgbm_control_v1` 的 W1—W6 封存预测；first pass 与 replay 身份必须一致。
- 不拟合模型、不重算分数、不加入 Ridge/融合臂，不读取 2025—2026 结果。
- 对照直接读取 M6 封存的 `Top30/n_drop=3` 日报；不要求在新镜像里逐位重放旧日报。
- 处理臂在1亿元研究账户上运行，TopK=30、10日调仓、次日开盘、基准与费用完全不变。

这样绕开 M6-3 已证明没有决策意义的 `1e-16` 级跨镜像浮点复现障碍：旧对照以哈希绑定的不可变
产物为准，新处理臂内部 first pass/replay 仍必须物理一致。

## 主判与诊断

主判不新增阈值：六窗中基础成本扣费后超额至少4窗为正，并且六窗合并的1.5倍成本累计超额不低于
0。通过只记 `VALIDATED_RESEARCH_SCALE`，失败记 `REJECTED_RESEARCH_SCALE`；身份、执行或审计缺证
一律 `BLOCKED`。

必须同时报告：逐窗超额、三档成本、总换手、目标成员替换数量、保留成员再平衡金额、实际持仓数、
现金比例、相对旧转换器的日收益差和最大回撤。除原 G0 外均是诊断，不得结果后升级为判决门。

## 尝试与授权

本批只有一个新组合转换尝试。第一次获批读取 Head30 真实效果时计入
`ledger/experiments.csv`；读取后即使实现失败也计数，不允许同 scope 重跑或补一个替代转换器。

结果盲实现完成后必须生成绑定 Git、代码快照、镜像、输入、命令、挂载和输出的 release scope。
只有用户逐字批准动作
`M6_PRODUCTION_HEAD30_G0_EFFECT_ONCE_WITH_REPLAY_AND_INDEPENDENT_AUDIT` 并绑定该 scope SHA，才允许
一次 runner（内部 first pass + replay）和一次独立 auditor。`pending`、自然语言继续或旧 M6 授权均
必须失败关闭。

## 明确不回答

本批不判断50万元账户是否足够。把资金同时从1亿元改为50万元会混入最低手数、现金占用和费用离散
性，破坏单变量归因。资金规模须另立协议；在此之前，50万元模拟仓只作工程闭环和自然前瞻观察，
不构成 G8 最终有效性口径。

本批也不修改生产信号、模拟仓、scheduler、Web、因子门或 G1，不授权生产切换。
