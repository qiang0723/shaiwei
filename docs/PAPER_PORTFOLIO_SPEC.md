# P0.5 模拟组合与前瞻绩效闭环设计草案

> 状态：v0.1，2026-07-22 已授权立项。P0 三次完整影子闭环和验收后健壮性复核完成前，只允许完善本文，不施工代码、账本或服务。

## 1. 要回答的问题

正式信号在真实下一交易日开盘、涨跌停/停牌、交易单位、费用和公司行为约束下，形成了什么实际持仓与扣费结果；相对中证800是否产生可持续净超额。

模拟仓不是新的选股器，也不是把回测曲线换个名称展示。它只消费已登记信号和真实可用行情，并持续维护可复算的组合会计状态。

## 2. 首版范围

- 账户固定为 `model_baseline`，输入只能是当前正式模型的不可变信号 manifest。
- 只模拟交易，不连接券商、不提交真实委托、不提供在线改参。
- 股票范围继续排除 `.BJ`；中证800仍是基准。
- 未来 `llm_judgment`、资金流候选和科创50必须使用独立账户、执行策略版本和业绩，不得与基准仓合并。
- 首版不引入止盈、止损、盘中择时或主观限价。任何执行增强都必须先成为独立的预注册研究臂。

## 3. 时间和成交语义

1. 交易日 T 的完整数据、门禁和模型产出信号后，只在 T+1 官方开盘尝试执行。
2. 成交判定只使用当时已知的官方开盘、交易状态、方向性涨跌停和事前冻结规则。
3. 买入受阻时资金留在现金；卖出受阻时继续持有原股票。未成交订单在该次开盘执行窗口结束后失效，不自动追价或事后补成交。
4. 下一次调仓从实际持仓和现金计算订单，不从上一期目标权重计算；目标、订单、成交和持仓必须是四个不同概念。
5. 成交价格使用未复权真实价格；分红、送转、拆并股和配股等通过独立公司行为事件调整股份和现金，禁止用复权价格伪造现金流。
6. 每个执行规则变更都提升 `execution_policy_version`；旧账户和历史净值不得按新规则覆盖重算。

## 4. 组合会计对象

### 账户

`account_id`、策略身份、初始资金、基准、执行策略版本、创建时间、状态和配置哈希。

### 订单

信号哈希、证券、方向、目标权重、下单前实际数量/现金、计划数量、有效执行日、状态和拒绝原因。

### 成交

订单主键、证券、成交日、价格、数量、成交额、分项费用、行情批次与成交判定证据哈希。

### 持仓与现金

每次成交/公司行为后的数量、成本基础、已实现盈亏、现金变化和事件主键。状态只能由上一状态追加事件重放得到。

### 每日净值

交易日、现金、持仓市值、净资产、归一化净值、中证800净值、扣费净超额、当日/累计费用、回撤和证据哈希。

## 5. 指标框架

### 结果指标

- 扣除全部费用后的累计收益与年化收益。
- 相对中证800的扣费净超额。
- 最大回撤及回撤持续时间。

### 执行诊断

- 订单数、实际成交率及买卖方向分解。
- 涨跌停、停牌、缺失行情等未成交原因。
- 信号收盘到次日开盘偏差、实际换手和累计费用。
- 未成交与整手约束产生的现金拖累。

### 组合解释

- 当前持仓、目标权重与实际权重偏差。
- 个股和行业对组合盈亏及超额的贡献。
- 已实现/未实现盈亏、现金比例和集中度。

收益不得脱离基准、费用、回撤和时间范围单独展示；正式观察期不足时必须显示 `NOT_READY`。

## 6. 证据和幂等契约

- 订单、成交、持仓事件、公司行为和每日净值均使用追加式账本；不得直接改写旧行。
- 每条结果绑定 `code_snapshot_sha256`、`data_snapshot_sha256`、`signal_sha256`、行情批次和执行策略哈希。
- 同一账户、信号和执行日只能形成一个确定结果；重复运行验证产物和账本不变。
- 每日必须机械验证“净资产 = 现金 + 持仓市值”以及前后状态连续性；差异非零即失败停止。
- 不完整行情、公司行为歧义、证据哈希不一致或账本断链时，不得补零或沿用旧净值。

## 7. 首批只读查询契约

- `paper_portfolio_snapshot(account_id, as_of)`：实际持仓、现金、净资产、累计成本、状态与证据。
- `paper_orders_fills(account_id, signal_sha256)`：订单、成交、未成交原因、价格、数量、费用和持仓变化。
- `paper_nav_series(account_id, start, end)`：模拟仓、中证800、净超额、回撤、换手和现金拖累。

接口只读且必须返回 `as_of`、`generated_at`、`execution_policy_version`、`source_refs`、`evidence_hashes` 和 `freshness_status`。来源不完整时返回显式状态，不拼接或前填。

## 8. 代码施工前必须冻结的数值

- 初始资金：建议候选人民币 100 万元，同时输出以 1 为起点的归一化净值；用户确认后冻结。
- 各市场板块的买入/卖出交易单位和零股处置。
- 佣金、经手/过户费、印花税、最低费用及生效日期。
- 公司行为权威来源、到账日期和歧义处理。
- 收盘估值价格、长期停牌估值和退市处置规则。

这些数值影响真实数量、费用和收益。在首次正式模拟前必须预注册并形成版本哈希，不能观察结果后修改同一账户历史。

## 9. 首版验收

- 无未来数据，`.BJ` 为 0，正式模型和信号零改动。
- 订单 → 成交 → 持仓 → 现金 → 净值可逐笔重放，账户恒等式每日通过。
- 涨跌停、停牌、未成交、交易单位、最低费用和公司行为边界测试通过。
- 同一不可变输入双跑，产物哈希一致、账本行数不变。
- Docker 日任务完成，飞书开始/完成/失败守护生效，故障不覆盖旧证据。
- Web 只能通过冻结的只读查询契约展示，不扫描生产 Parquet 或自由拼接账本。

## 10. 施工顺序

1. P0 第三次完整闭环和验收后健壮性复核完成。
2. 冻结第 8 节数值与 `execution_policy_version`。
3. 实现纯函数成交/会计内核和 fixture，再实现追加式账本与历史重放。
4. 接入 Docker 日任务、幂等、异常恢复和飞书守护。
5. 冻结三组只读查询契约，完成真实信号的首个前瞻账户日。
6. 模拟仓首版验收通过后恢复 P1 资金流增量验证；Web 代码使用已稳定契约旁路施工。
