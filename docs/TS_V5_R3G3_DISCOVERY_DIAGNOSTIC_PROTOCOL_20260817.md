# TS-v5 R3G-3 发现期失败诊断协议

## 目的

R3G-2 已权威裁决 `REJECT_TS_V5_R3G2_DISCOVERY`。本节点不尝试挽救旧结果，也不增加策略效果
尝试，而是只读封存的 2021—2023 发现期产物，回答两个运营问题：为什么平均现金接近 98%，以及为什么
已经成交的交易仍为负期望。诊断通过后也只形成未来 TS-v6 的机制问题，不直接选参数或启动新回测。

协议真身为 `config/ts_v5_r3g3_discovery_diagnostic_v1.yaml`。协议冻结时只查看了 R3G-2 聚合报告、
产物文件名、Parquet schema 和执行代码定义，没有读取逐订单、逐交易或逐日持仓值。

## 冻结输入与防火墙

- 只读 recovery first pass 的 discovery 分区，时间固定为 2021-01-04 至 2023-12-29。
- 三个冻结点只读取 `base_1x` 的 `nav/orders/trades`；其他两档成本只读取既有 `summary.json`。
- first-pass manifest、bundle、总报告、独立 audit 和 partition summary 均以 SHA-256 绑定。
- replay 只用于机器证明确定性，不作为明细分析输入；2024—2025 holdout 和 2026 路径/数值都禁止读取。
- 不读取行情、证券清单、分数、预测或模型；跟踪报告不得出现证券或行业标签及逐笔交易。

## 预先固定的诊断问题

1. 资金闲置发生在信号漏斗还是订单执行：首批/第二批订单量、状态、原因、成交率、持仓日和新开仓日。
2. 事件到达后是否被定仓或执行约束压低：全期与有仓日的仓位、现金、持仓数、入场金额占 NAV 比例、
   容量限制和拒单/挂起原因。
3. 已成交交易为何为负期望：毛损益、费用、净损益恒等式；按最终退出原因、持有 1—5/6—10/11—15/
   16+ 交易日及年度拆分数量、胜率和净损益。
4. 失败是否跨两个冻结邻点与三档成本一致：只做既有结果的横向诊断，不构成新增效果尝试。

所有统计的分母、持有期桶和年度均已写入协议。事实按 `VERIFIED / LIKELY / UNRESOLVED` 分层；没有
反事实实验支撑时不得作因果断言。

## 一次性执行与交付

- diagnostic runner 一次、确定性内部 replay 一次、独立 auditor 一次；效果尝试增量固定为 0。
- 断网、无密钥、无 provider、无模型/预测/回测、无参数搜索、无实验总账写入。
- 机器结果、audit 和便携报告均写入 Git 忽略的项目内目录；Git 只提交协议、代码、测试、聚合验收和
  哈希，不提交明细业务数据或运行日志。
- 报告面向项目决策者，必须先给结论，再给图表证据、建议、待回答问题和限制；HTML 必须自包含。

## 不授权事项

本协议不改变 R3G-2 的 REJECT，不开放留出期，不授权 TS-v6 效果、模拟仓、Web 或生产。后续若继续，
须从诊断结论中只选择一个具有实质机制变化、可证伪且非同 scope 调参的新假设，另立结果前协议。
