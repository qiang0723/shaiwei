# D1-3A 对抗复核语义合同纠错

D1-3A 原机器报告和验收曾给出 `GO_INDEPENDENT_HUMAN_GATE`，它只正确证明了 8/8 请求完成、JSON/
schema、费用、传输和不可变证据门。后续在组装零业绩独立盲审包时逐项核对正文，发现至少 3 份响应
违反冻结提示中的语义合同。因此原 GO 不再具有准入权威，现以本纠错覆盖为：

- `review_execution_gate=STOP_SEMANTIC_CONTRACT_VIOLATION`；
- `human_gate_ready=false`；
- 两条候选均为 `NOT_ADMITTED_REVIEW_GATE_FAILED`；

- `strategy_effective=NOT_EVALUATED`、`production_authorization=none`；
- D1-3 就本批次终止，不补响应、不递补第三名、不改公式或方向。

机器可读纠错：`docs/D1_LLM_FACTOR_REVIEW_SEMANTIC_CORRECTION_20260725.json`，SHA-256
`de8b331cd8c923bb3b7b3f3a9e8c0aeb342db410cda647be72981f69a34917b2`。

## 2. 违约事实

冻结 system prompt 明确禁止创建替代因子、改变公式、调整窗口或建议尝试变体；响应 schema 另要求
`formula_change_or_new_candidate_proposed=false`。结构验证只检查了该布尔字段，没有核对自由文本是否与
之相符，导致以下三份被错误计为有效：

1. `708781185309964adecb`：结构字段为 false，但正文建议替换冻结聚合方式或换用另一类区间估计；
2. `b7ba1329435b0ca55dc2`：结构字段为 false，但正文建议尝试不同时间尺度、跳跃或风险中性类变体；
3. `fb9abc2c08eb24201de9`：结构字段为 false，但正文建议替换聚合方式和估计量。

三份响应的 response/raw artifact SHA-256 已逐项写入机器纠错并与追加式 review ledger 对上。原响应、
原账本、原运行报告和忽略区证据均未改写。语义审计结果为 5 PASS / 3 FAIL，而协议要求 8/8 有效且
禁止替换无效响应，所以独立人工闸的前置条件不成立。

## 3. 为什么主窗口可以做这次纠错

主窗口不能裁决候选的经济含义，因为它曾误见候选 18 的发现期数值；但本次只核对“响应正文是否违反
已冻结的输出合同”，不比较候选、不判断收益方向是否有效，也不读取任何发现期或后续业绩。纠错过程
未读取或导出发现期排名/数值、W1—W6、压力期、G1、前瞻或生产结果，因而不把受污染的主窗口变成
研究裁判。

## 4. 原证据如何解释

以下原结论继续有效：8 个 DeepSeek HTTP 请求均一次完成、费用 `$0.01472214`、无计费不确定性、
33 份忽略区证据和两份追加式账本哈希稳定、断网无密钥复跑 0 外部调用、生产 scheduler 未改变。

以下原结论失效：`human_gate_ready=true` 和 `GO_INDEPENDENT_HUMAN_GATE`。原 JSON 报告不回写，保留为
“结构/schema/传输门当时的机器输出”，必须与本纠错一起解释，不得单独用于推进研究。

## 5. 后续边界

本批剩余 D1 额度不授权修补或重发这 3 份响应。未来若重新研究，须有新的用户指令和新的结果前协议，
并至少修正两点：

1. 将“当前公式的可证伪条件”与“如何修改公式”拆开，后者在审查阶段完全禁写；
2. 在结构布尔字段之外，增加自由文本语义一致性审计，并在宣告机器 GO 前完成。

这属于未来新批次的方法改进，不回溯挽救 D1-3，也不允许利用本次看到的任何结果选择变体。
